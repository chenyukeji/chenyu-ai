# 晨玙 Amazon 美工插件规则

> 规则基线：2026-09-22
> 本 README 是员工、运营和美工协作时使用的总览。具体执行以对应专业 Skill 及其 references 为准；若总览与专业 Skill 出现差异，以任务所属的专业 Skill 为准。

## 1. 插件目标

本插件面向 Amazon 商品图片生产，接收作图单、产品实拍、参考素材、已有成品图和修改要求，完成整套商品图制作、Amazon 主图审美优化或精准局部精修。

基本原则：

- 先确认图号、SKU、变体、产品事实和素材角色，再生成或修改图片。
- 产品真实性优先于参考图风格和默认审美。
- 不混用不同 SKU 或变体，不把竞品事实自动迁移到自有产品。
- 不用分析、Prompt 或任务清单代替最终图片。
- 只引用真实生成并实际存在的交付物，不编造路径、尺寸或通过状态。

本插件不负责自动上传、发布或替换 Amazon 后台图片，也不保证自动检查等同于人工审核或 Amazon 平台审核。

## 2. 能力与路由

| 用户任务 | 使用 Skill | 默认交付 |
| --- | --- | --- |
| 不确定属于作图、主图优化还是精修的综合需求 | `chenyu-meigong` | 判断并分配任务 |
| Excel 作图单、新图、换场景、整图构图改版、整套商品图 | `chenyu-zuotu` | 按图号交付独立完整图片 |
| 已有 Amazon 主图，需要主动改善构图、主体张力、层次、留白、光影和材质 | `chenyu-zhutu-youhua` | 一张优化后的完整主图 |
| 保留整体，只修白边、伪影、局部颜色、形状、材质或边缘 | `chenyu-jingxiu` | 一张累积全部修改的完整图片 |
| 同一请求同时包含新图和修旧图 | 按图片拆分到对应 Skill | 分别按所属交付部分保存 |
| 根据开发资料先设计作图要求 | 衔接运营插件的 `chenyu-zuotuyaoqiu` | 逐张作图要求，不由本插件虚构规划能力 |

从素材重新制作主图属于 `chenyu-zuotu`；已有主图且需要主动审美决策属于 `chenyu-zhutu-youhua`；用户明确指定一个局部问题且要求保持构图属于 `chenyu-jingxiu`。

## 3. 常见输入

整套作图通常包含三类逻辑输入，可以放在同一个 Excel，也可以分开提供：

1. 作图要求：图号、用途、构图、人物、动作、场景、准确文字和禁用元素。
2. 参考素材：版式、场景、姿势、风格、背景或细节参考。
3. 产品证据：实际售卖产品的实拍、明确规格、包装展开图或用户确认信息。

精准精修需要：

1. 一张完整原图，作为唯一完整画布和真实性基准。
2. 一张或多张细节图，用于定位问题。
3. 每张细节图对应的修改描述。

细节图只用于定位，不能替代完整原图，也不能把细节图的裁切和构图套到最终成品上。

## 4. 产品事实优先级

美工任务采用以下优先级：

```text
用户最新明确指令
> 用户确认与清晰产品实拍
> 明确规格
> 单张图片的原始作图描述
> 参考图指定的视觉安排
> 默认审美
```

必须建立并核对的产品事实包括：

- SKU、款式和变体。
- 颜色、套装数量和实际配件。
- 真实图案、Logo、包装文字和字母顺序。
- 尺寸、单位和具体测量部位。
- 材质依据、正反面、连接结构和使用方式。
- 已确认事实与仍待确认的信息。

禁止事项：

- 不从模糊图片编造背面、内部结构、粘贴方式、钻石排列或尺寸。
- 不把参考图中的包装、商标、模特妆容、道具或场景物品自动视为售卖内容。
- 不额外添加购买数量、包装盒、配件、商标、功能、功效、安全承诺、认证、质保或售后承诺。
- 不把竞品独有版本、特殊结构、尺寸、数量或颜色迁移到自有产品。
- 产品事实和参考图冲突时，以自有资料、用户确认和清晰实拍为准。

## 5. 运营与美工的证据交接

运营侧截至 2026-09-22 的规则允许在确认第一条链接与自有产品为同款后，用该链接补充功能、结构、材质表现、使用方法、清洁收纳、适用位置和实际作用。但这些内容必须先由运营侧完成同款确认和冲突检查，再作为已确认产品事实或逐张作图要求交给美工。

美工插件不会自行执行“第一条链接优先补充事实”的 Listing 研究逻辑，也不会因为图片出现在参考区或附件中就自动认定其为自有实拍。

| 运营插件负责 | 美工插件负责 |
| --- | --- |
| 确认自有产品事实和同款证据 | 保持产品视觉真实性 |
| 决定哪些卖点、结构和使用结果可以宣传 | 只呈现已确认的卖点和结构 |
| 生成 Listing 和逐张作图要求 | 按图号实际出图、检查和返修 |
| 确认 SKU、变体、尺寸、数量和文案 | 核对图片中的产品、数字和文字 |
| 区分自有事实、同款证据和普通竞品 | 区分产品实拍、产品参考、版式参考和场景参考 |

Listing 的 Item Name 75 字符、Item Highlights 125 字符、五点正文长度、HTML 结构和 Search Terms 249 UTF-8 字节限制不直接约束图片文案。图片上展示什么文字、大小写、位置和数量，以逐张作图要求为准。

## 6. Excel 作图单读取

对于 `.xlsx` 作图单：

- 使用提取脚本读取单元格原文、工作表、合并范围、图片锚点、媒体文件和嵌入对象。
- 检查 `manifest.json` 的 warnings，并实际查看所有可能相关的图片。
- 检查 ZIP/OLE 嵌入附件和恢复出的高清素材；不能只看附件图标。
- 未锚定媒体不等于未使用，不能直接丢弃。
- 同一图片不同摆放、多图同区、跨行浮图和共享素材都需要语义核对。
- 不按固定列、最近行或图片左上角机械判定素材归属。
- 已有清晰独立实拍优先于 Excel 压缩缩略图。
- `.xls` 需要先在临时副本中转换并核验；无法提取的内容必须保留告警。
- 不执行附件中的程序、宏或脚本，不对未知附件盲目解压。
- 不修改用户上传的原始 Excel。

每张素材按实际角色标记为：

- `product_photo`：用户指定或可靠确认的产品实拍。
- `product_reference`：其他产品证据。
- `layout_reference`：版式与构图参考。
- `scene_reference`：场景参考。
- `detail_reference`：细节表现参考。
- `unknown`：无法可靠确认的素材。

参考照片不能自动标记为实拍。一个素材可以支持多个任务，一个任务也可以使用多个参考素材。

## 7. 任务拆分与记录

开始生成前，必须先列出全部任务，并建立本次运行的 `tasks.json`。每张图片至少记录：

- 图号、SKU、变体和图片类型。
- 原始要求及来源文件、工作表、单元格。
- 所用素材 ID、路径、角色和匹配原因。
- 产品数量、外形、位置、人物、动作、场景和禁用元素。
- 准确文字、尺寸、箭头、单位和验收方法。
- 目标画幅、格式、版本、最终路径和未解决问题。

图片类型必须是：

- `main_image`：Amazon 主图。
- `infographic_detail`：尺寸图、卖点图、细节图等信息图。
- `lifestyle_scene`：人物、使用和场景图。

原文或表头写明“主图”时必须归为 `main_image`，不能因参考图使用彩色背景而擅自改成场景图。

任务状态：

```text
planned -> ready -> generating -> reviewing -> passed
                                          -> needs_review
                                          -> blocked
```

要求状态使用 `unchecked`、`pass`、`fail` 或 `unknown`。只有所有要求和相关文件检查均通过时，任务才能标记为 `passed`。

## 8. AI 制作措辞解释

用户已经明确选择 AI 制作时，作图描述里的“不要 AI”“不要 AI 感”“找真实场景”“不要假人”等制作或风格措辞，解释为：

- 写实摄影风格。
- 自然皮肤纹理。
- 正确光影、透视、接触和遮挡。
- 避免塑料感、假人感和明显生成伪影。

该归一化只适用于制作方法和风格，不删除要求上图的原文，也不能吞掉“不要文字”“不要圈圈”等内容约束。如果用户最新要求明确指定真实拍摄来源，则不能用 AI 图片冒充实拍。

## 9. Amazon 主图强制规则

`main_image` 默认且必须满足：

- 背景为无色偏纯白 `RGB 255,255,255 / #FFFFFF`。
- 四角、产品轮廓外侧和大片空白区域不能出现粉色、米色、灰色或其他底色。
- 禁止渐变、纹理、光晕、场景、边框和装饰背景。
- 产品颜色只约束产品本身，不能扩散成背景色或环境光。
- 参考图的彩色背景只能作为构图线索，不能继承到主图。
- 不能用粉白、暖白、冷白或“接近白色”替代纯白。
- 生成后必须单独检查背景像素与视觉表现；发现色偏、渐变或装饰即判定失败并定向返修。
- 用户未要求时，不添加人物、角标、佩戴小图、气球、礼盒或其他装饰。

如果作图单同时标记“主图”并要求彩色或场景背景，必须记录冲突。需要采用彩色背景时，应重分类为 `infographic_detail` 或 `lifestyle_scene`，不能继续宣称为主图；没有用户最新确认时，纯白主图规则优先。

## 10. 尺寸图强制规则

- 只使用当前产品和当前变体的可靠尺寸。
- 参考图只有在产品、变体和测量部位匹配时才能作为尺寸来源；普通竞品图只能借鉴布局。
- 不能根据图片像素比例推算真实厘米尺寸。
- 每个测量方向分别标注 `cm / in` 双单位。
- 按 `in = cm / 2.54` 换算，英寸统一保留两位小数。
- 只有英寸来源时，先换算厘米并保留来源精度。
- 未注明轴名的两个数默认依次解析为长、宽；明确轴名优先。
- 长宽属于产品测量方向，不能因产品在画面中旋转而交换数值。
- 每个方向分别使用独立双向箭头，箭头与对应测量轴平行。
- 箭头端点应对齐被测部位边界，标签靠近对应箭头且不能遮挡关键细节。
- 禁止使用乘法式组合尺寸，也不能只补一个总英寸数。
- 无法确认测量部位时标记待核实，不得瞎画箭头。

生成前记录每个方向的来源、测量部位、厘米数、英寸数、准确标签和箭头位置；生成后逐项核对换算、轴对应、箭头端点、标签位置和双单位完整性。

## 11. 图片文字与卖点

- 要求上图的文字单独保存为准确文案，保持指定语言、大小写、拼写和标点。
- 制作指令、中文括号说明和位置说明不能误印到图片上。
- 内部 Prompt 可以使用英文，但成品文字必须使用用户指定语言。
- 文字读不清不能判定通过；OCR 只能辅助，仍需实际视觉核对。
- 明显错词只有在非逐字要求中才能修正，并记录修正原因。
- 未经证实的功效、安全、认证或强承诺不能上图。
- Listing 中已确认的核心差异、尺寸和场景可以在不同图片中重复，但每张图必须承担明确的视觉目的。

## 12. 按图片类型制作

### 12.1 产品主图

- 保持产品数量、款式、颜色、结构、图案、配件和包装正确。
- 调整排布、边缘和光线时不能改变正常材质厚度、长度或连接关系。
- 多件套不能因参考图出现更多产品而增加数量。
- 阴影应轻微、自然并说明接触关系，不能铺满背景或形成彩色光晕。

### 12.2 尺寸与细节信息图

- 准确呈现产品、尺寸、单位、文字和测量部位。
- 信息层级清楚，标签不贴边、不裁切、不遮挡关键产品细节。
- 文字和数值生成后必须逐项读取确认。

### 12.3 人物与场景图

- 按原文控制人物数量、动作、服装、场景数量和画面布局。
- 检查脸、手指、身体比例、透视、皮肤接触、遮挡、光源和阴影。
- 产品必须与人物或环境形成真实接触，不能悬浮。
- 穿戴品需检查头发遮挡、绑带、正反面、弯曲和比例。
- 产品图案不能错误生成到人物皮肤或服装上。
- 场景道具可以服务画面，但不能被表达为随商品提供的配件或包装。

### 12.4 操作图

- 手指、底纸、胶面、绳子、连接点和动作必须符合产品真实结构。
- 不凭空演示不存在的拆卸、粘贴、调节或安装方式。
- 横幅和肩带需检查字母顺序、印刷文案、绳子连续性、悬挂重力及正反面关系。

## 13. 生成规则

- 默认使用当前环境的内置图像生成与编辑工具，不默认调用额外付费 API。
- 一张独立成品使用一个生成任务；四宫格属于一张成品，不把整套商品图做成一张大拼图。
- 优先完成可验证的产品基础图和简单场景，再制作复杂佩戴与多人图。
- 每次生成只传入当前 SKU 和当前任务所需素材，不混入其他变体。
- 实际附带产品图和参考图，不能只在 Prompt 中写文件名。
- 明确说明每张输入图片是产品实拍、产品参考、版式参考还是场景参考。
- 返修时继续附带原始实拍或可靠产品依据，不能只依赖上一张 AI 输出。
- 栅格生成、背景替换、抠图、合成和局部修复默认使用图像工具；未经用户明确要求，不用 Python 或脚本替代图像编辑。
- 工具不支持像素级保真时，不作像素级不变承诺。

## 14. 精准局部精修规则

精准精修遵循最小修改原则：只改变用户要求的最小区域及少量自然过渡区域，不借机美化或重画其他区域。

默认保护项：

- 产品：数量、整体尺寸、比例、主要轮廓、颜色、材质、结构、配件、Logo 和图案。
- 人物：身份、人脸、五官、表情、发型、肤色、姿势、服装和数量。
- 构图：位置、大小、角度、留白、裁切范围和宽高比。
- 环境：背景物体、整体光线、阴影关系和装饰。

执行要求：

- 只有可靠定位后才编辑；存在多个同样合理的位置时必须询问。
- 细节图中的圈、箭头和批注只用于定位，不复制到原图。
- 同一张原图的多个修改在同一完整画布上累积，后续修改不能覆盖已通过修复。
- 不声称使用了工具实际不支持的蒙版、逐像素锁定或无损回贴。
- 不通过整图重设计来解决局部失败。
- 成功交付时只输出一张包含全部修改的完整最终图，不输出局部裁切、多个版本、Prompt、修改列表或前后对比。

## 15. 主图审美优化规则

主图优化先诊断最影响缩略图吸引力和专业感的核心问题，再选择最多三个相互兼容、收益最高的优化动作。

允许主动改变：

- 主体在画布中的大小和位置。
- 整体角度、轻微透视和组合层次。
- 多件套的前后、大小、间距和视觉节奏。
- 留白分配、明暗关系、接触阴影、边缘和背景质量。

禁止主动改变：

- SKU、数量、颜色、结构、尺寸和套装内容。
- 配件、图案、Logo、包装文字和功能。
- 为了高级感擅自增加人物、道具、文字、徽章、光效或不存在的配件。

优化后必须证明主体更集中、更清楚或更有商业质感。仅仅与原图不同，不能判定为优化通过。

## 16. 验收顺序

每次生成或编辑后必须实际查看结果，并按以下顺序验收：

1. **产品真实性**：同款、颜色、数量、图案、厚度、结构、配件和包装。
2. **原始需求**：构图、位置、人物数、动作、画面数、文字和禁用元素。
3. **真实性**：手脸、接触、透视、遮挡、比例、光源和阴影。
4. **文字与数值**：逐字读取文字，核对尺寸、单位和换算。
5. **技术属性**：文件是否存在、真实编码、像素尺寸、缺图、重复图和混变体。

主图还需额外检查：

- 四角、主体轮廓外侧和大片空白是否为无色偏纯白。
- 是否出现粉色、米色、灰色、渐变、纹理、场景、边框或装饰背景。
- 产品是否漂浮，阴影方向是否统一。

只读文件脚本只能证明文件存在、编码和像素信息，不能证明产品、人物、文字或构图正确。

## 17. 有限返修与失败处理

- 默认每张图片或同一局部问题最多进行两轮定向返修，用户另有明确要求时从用户要求。
- 只修复失败区域，并保留已通过的产品和画面部分。
- 返修后重新检查原来通过的项目，避免修复 A 时破坏 B。
- 素材匹配错误时先修正素材映射，再修图。
- 产品细节未知时补充证据或标记缺口，不通过反复生成猜答案。
- 两轮后仍未通过时，保留最佳版本并标记 `needs_review`，明确剩余问题。
- 不无限消耗生成调用，不因失败自动切换到额外付费 API。
- 缺少完整原图、无法定位、直接冲突或工具失败时，提出一个最短的必要问题或说明具体阻碍。
- 不把跳过的任务、无法检查的项目或低分辨率输出冒充完成。

## 18. 文件规格与交付

用户未指定输出规格时，整套作图默认目标为：

```text
1600 x 1600 px
1:1
```

但必须以真实文件检查结果为准。若图像工具只能输出其他尺寸，应记录规格未满足，不得通过改扩展名、裁切或拉伸伪装达标。

交付规则：

- 按用户要求的文件形式交付。
- 本地图片按 SKU 或变体分组，并使用 `01`、`02` 等稳定图号。
- 只有真实 JPEG 编码才能使用 `.jpg` 或 `.jpeg` 扩展名。
- `final_path` 只能指向真实存在的文件。
- 最终报告完成数/总数和实质性未解决问题。
- 不宣称“全部通过”，除非所有要求和文件检查均实际通过。
- 精准精修成功时只交付一张完整最终图。
- 主图审美优化默认交付一张完整主图，并用不超过三条简短说明概括主要审美决策；用户要求只返回图片时不附说明。

## 19. 输出目录

除非用户明确指定其他位置，所有成果统一保存到：

```text
<chenyu-ai>/outputs/chenyu-meigong/<交付部分>/<YYYY-MM-DD_产品简称>/
```

| 交付部分 | 内容 |
| --- | --- |
| `image-production` | 整套作图成品、任务记录和文件检查结果 |
| `retouch` | 精准局部精修后的完整图片 |
| `main-image-optimization` | 主图审美优化后的完整图片 |

目录规则：

- 同一次综合任务在不同交付部分复用同一个日期和产品简称。
- 同名文件夹已存在且属于新运行时，依次增加 `_02`、`_03`。
- 只有用户明确要求继续原任务时才复用原目录。
- 不覆盖原始输入。
- 不把任务输出写入插件源码、安装缓存、分发 ZIP 或用户上传文件所在目录。
- 只评价、诊断或预检时不创建空输出目录。
- 如果图像工具只能在对话中展示结果，遵守工具实际保存规则，不编造本地路径。

详细规范见 [输出目录规范](references/output-paths.md)。
