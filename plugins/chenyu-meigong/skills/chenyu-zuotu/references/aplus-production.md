# A+ 模块素材执行

仅在本次制作范围包含 A+ 时读取。本规则与普通图册共享产品事实、素材归属、实际传图及生成后直接交付流程；不改变普通图册的既有要求，也不自动上传 Amazon。

A+ 中有人物的主题图、佩戴图与生活场景同样执行 [欧美市场视觉与人物规则](model-rules.md#欧美市场视觉与人物)：未指定市场时面向欧美消费者，将目标市场、年龄范围、穿搭、动作及具体场景写进每个适用槽位的生成输入。多场景保留人物与机位差异；纯产品图或品牌标志图无需加人。

## 默认套图与共用变体

没有用户明确指定的其他方案时，同一产品的颜色、花色、尺寸、数量变体共用一套实际成品：

- 无品牌：A+01 产品主题横幅 600×180 px；A+02 核心价值大图 970×600 px；A+03 细节购买信息大图 970×600 px，共三张。
- 有品牌：A+01 品牌图 600×180 px；A+02 产品主题横幅 600×180 px；A+03/A+04 两张大图各 970×600 px，共四张。品牌图额外增加，不替代产品主题图。

以本品已确认品牌名称或 Logo 为依据，只有名称也可用准确文字制作品牌图；不从竞品猜品牌或编造品牌故事。无品牌不追问、不同时生成两版。整套自主确定统一配色、字体、光影和构图，竞品 A+ 与参考链接非必需；只需实际传入采用的产品素材及可选参考，参考为空不阻塞。

B 列多个变体、多个 product_ids 表示适用范围，不自动增加图片。一张共用图用一个任务关联全部适用 product_ids，成品只计一次；多款组合注明可选颜色/尺寸，避免混色套装或错误共同参数。确实无法准确共用时仅拆必要图片并记录理由。此默认不覆盖用户本次明确尺寸、数量、分变体制作要求；已有明确作图单按其范围执行，用户要求按新默认重规划时才替换旧方案。

## 读取范围与拆分

识别 `A+要求`、`FR A+要求`、`DE A+要求` 等工作表及原文的模块/素材标识；页名是线索，仍须读取准确语言、模块及槽位内容。若有 `aplus-brief-package.json`，复用其 `modules[].assets[]` 和事实资料，与 Excel 原文核对；不能要求用户必须额外提供内部 JSON。普通“作图要求”页和 A+ 页分开计数、共用“产品内容”页及适用素材。

A+ 也可位于普通作图单内部的“A+”分区，后续需求行即使没有编号或重复分区标签也要读取；分区标题和整套色调备注本身不计图。无编号时按实际独立素材顺序自动补 `A+01、A+02…`，保留原文及来源，不要求用户补号。

新版默认每行对应一张所有适用变体共用的成品。兼容用户明确提供的多槽位作图单：仅将行内明确需要独立导出的素材 a/b/c、独立变体、语言和桌面/移动端文件展开为任务，不能仅因列出多变体就展开。一项任务对应一个实际图片文件；三张独立槽位不能合成一张三联图，也不能将整个 A+ 页面拼成一张长图。只有作图单明确要求单槽位拼版时才在该槽位内合成。仅后台文本字段不创建图片任务。

目标站点/语言优先沿用用户指定及作图单；不因运营 Listing 默认四站自动增加四套。明确只制作普通图册或某个站点时，跳过本次范围外的工作表；附带参考中的 A+ 图片不自动成为待制作任务。

## 任务约定

沿用 `tasks.json` 的原文、单元格、素材和输出字段。A+ 每个实际素材至少保存：

- `content_type: aplus`、`image_type: aplus_asset`。
- `module_id`、`module_type`、`asset_id`、`slot`、`market`、`language`、`device`（`desktop`、`mobile` 或 `shared`）及适用变体。
- `output.width`、`output.height`、实际文件格式；规格来源及确认状态保存在 `spec_source`、`spec_status`。
- `exact_text` 只放需绘制在图片内的定稿；`backend_text`、`alt_text` 及中文释义单独保存，不加入上图文字。
- 源行指定的裁切、重排与安全区域写入 `requirements`，素材与事实沿用主 Skill 的角色区分。

A+ 首屏即使叫“主图”也仍是 `aplus_asset`，不能触发普通主图的白底、薄白框或无字规则。图号中保留模块/槽位对应，如 `A+01-a`、`A+01-b`；共享同一文件的槽位可记录 `used_by`，不为同一素材重复生成或虚增成品数。

## 尺寸、文案与构图

每个槽位以本次已提供或核实的宽高制作，不使用统一 1254×1254、1:1、固定七张或末张四宫格。图册与 A+ 共享品牌色、材质和产品事实；A+ 各模块按页面顺序承接信息，在各自画幅内安排构图。

尺寸未确定时先查所给作图单、后台槽位截图及已有规格证据；有明确模块且需要补核时可查当前官方资料。仅凭宽横图外观不能认定模块，也不能虚构 Premium 权限。未指定特殊槽位时直接使用上述公司默认画布，上传适配未核实不阻塞生成；仅当用户明确要求适配具体槽位而其关键规格缺失时暂停受影响素材。默认画布记录 spec_source=company_default，不能宣称上传规格已核实。

手机端要求可能是同一素材的裁切/安全区域，也可能是独立素材。仅在要求指定独立手机端素材时另出文件；共享素材在一个任务内满足已给的裁切要求，不因提到手机端就自动加一套。独立版本按目标画幅重新安排主体与文字，不拉伸方图、机械加白边或把产品压扁去凑比例。

上图文字保持准确的目标站点语言。不要把后台标题/正文、alt text 或中文释义印进图片；明确“无文字”的槽位不补英文标题。普通图册默认 Product Size、逐格标题、cm / in 双单位和尺寸表达规则不套用 A+；A+ 按已确认文案与当地单位要求执行，需要换算时保留事实与精度。共享图像不得带错站点文案或变体参数。

生成输入实际附带对应产品与参考图片，注明本次模块、槽位、端别、目标宽高和上图文字；参考图承担的产品/构图角色必须明确。先按所有已要求槽位建立完整清单，再逐项完成，不能只制作“作图要求”页就报告混合任务完成。

## 文件交付

普通图册沿用原编号；A+ 默认按站点/产品共用套图组织，文件名保留 A+ 图序，如 `FR/shared/A+01.png`，多个变体关联同一文件，不为各变体复制成品；仅明确独立变体素材才单独分组。用户或交付环境规定统一连续编号时遵从，在内部任务记录中保留文件与模块/槽位的对应关系；不覆盖普通图册的同号文件。

生成后使用现有 `check_outputs.py`，按每项 `output.width/height/format` 检查真实文件和像素尺寸。工具只提供近似画幅时，记录实际尺寸和未达标项，不把预期尺寸写成已验证结果；不为修尺寸擅自使用 Python 编辑图片。不能把文件规格未满足的结果称为可直接上传素材。

分别报告普通图册和 A+ 的实际文件数；模块数、槽位引用数和成品文件数不能混为一谈。沿用生成后仅检查文件与数量、不自动视觉复核/返修的既有流程，不因增加 A+ 自动追加检查轮次。缺失或暂缓的素材按模块/槽位列明，不宣称整单完成；文件检查不等于平台审核。
