# 制作与返修

## 准备生成任务

一次输入只包含该SKU及当前任务必要的素材。有实拍时优先用清晰原始实拍；参考制作或原创概念按主 Skill 的 production_mode 使用已匹配的产品参考和明确规格，并保留实物待确认项。构图例图控制其被指定的构图、场景或姿势。prompt使用以下信息，无需强行填满每个字段：

- 当前任务和画幅规格。
- 每张实际传入图的角色。
- 产品不可变化项：款式、颜色、数量、结构、图案、连接关系。
- 画面安排：左右/上下区域、人物数、产品比例、动作与可见部位。
- exact text及位置；明确无需文案时不加标题图标。
- 原文禁止项。
- 自然光影、材质和接触关系等必要写实要求。

内部prompt通常用清晰英文，成品文字必须使用用户指定语言。不得因使用英文prompt把中文/法文/德文成品文字改为英文。

## 按类型执行

产品主图：先看已记录的`main_style`。`clean_white`采用无色偏纯白背景（`RGB 255,255,255` / `#FFFFFF`），prompt写入主 Skill 的纯白硬约束；`white_with_use_inset`保持白底和醒目的单一产品主视觉，仅在有事实依据时加入完整可读的小幅使用演示；`scene_hero`让产品在真实用途的完整场景中占主导，例如桌旗展示铺设、垂落与自然褶皱，而不是只把图案平铺在桌面。缩略图检查视觉重心、主体占比、用途辨识度、场景裁切与材质；不要机械复制等大的同款产品，也不要让餐具、手或容器看起来属于售卖套装。保留真实颜色、数量、材质厚度、结构和长度；不得为了更好看凭空改变产品或照搬参考图中冲突的道具。

贴纸/钻贴：区分可剥离贴片、底纸上的眼睛/眉毛图案、钻石本身；不同款或数量不能混用。匹配额头、眼角等指定位置、皮肤曲面、尺度、方向与遮挡。局部细节在源图不可辨时标记unknown，不自信声称完全一致。

发箍/眼罩/穿戴品：检查实际接触、头发遮挡、绑带、正反面、弯曲与比例；不把耳边绑带生成在脸上，不把产品印刷变成身体纹身。

横幅/肩带：保留实际字母顺序和印刷文案，不用模糊字符替代；检查绳子连续、悬挂重力及字母与背面的关系。

剥离/操作图：逐个检查手指、底纸、胶面和接触点，动作与产品真实结构一致，不凭空演示不存在的结构。

尺寸细节：执行SKILL.md的“尺寸标注与缺失信息补全”，数值、单位、独立长宽箭头起止点和测量部位一致。尺寸图可结合有事实依据的局部细节或真实场景；检查其是否提供独立信息；局部相似不单独作为返修理由。每个方向均用cm / in双单位，检查换算、轴对应和标签位置，禁止乘法式组合尺寸。缺失规格可采用匹配当前产品的参考图明确尺寸并记录来源，不得继承不匹配的竞品尺寸。文字/标注生成后需实际读取确认。若模型不能准确完成，有限局部修复，最终仍错误须显式列出，不把“要求准确”当验证。

多场景图：按原文画面数和场景差异执行。四宫格可一次生成或分场景后用图像工具拼版，依据复杂度选择；不要强制每格一个调用浪费额度。图片中只出现售卖配件或明确属于场景的道具，礼盒不得被表达为包含包装。

## 验收顺序

1. 产品：同款、颜色、数量、图案、厚度、配件、结构，与当前模式的产品依据对照；原创图案检查整套一致性，未知实物项保留待确认。
2. 需求：每条原始描述中的布局、人物数、动作、画面数、文字位置均检查。对`clean_white`或`white_with_use_inset`主图额外检查未被演示占据的四角、主体轮廓外侧和空白区为肉眼纯白；未经要求的背景色、渐变、纹理或装饰判定失败，近白容差按主 Skill 记录。对`scene_hero`检查产品是否仍是主角，使用关系、垂落/褶皱、场景完整性和材质是否可信；三种形式都需在缩略图检查主体是否醒目、用途是否清楚，不能只因满足文字要求就判定好看。
3. 真实性：手脸、皮肤接触、透视、遮挡、比例、光源和阴影。
4. 文字与数值：实际逐字读图；OCR如可用只能辅助，原文和视觉核验共同决定。
5. 整套信息：核对每张图的信息重点。完全重复成品或用同一特写、场景和标签充数须返修；仍有独立信息价值的局部相似只记非关键瑕疵。尺寸图的辅助内容应尽量补充其他图未表达的信息。
6. 技术：真实文件编码和像素，整套缺图/重复图/混变体。

只读文件检查不证明前五项通过。普通缩放预览看不清产品细节时用原尺寸查看；不能靠整图缩略图判定精细钻石排列。

## 有限局部返修

记录“观察到的错误→需要改变的区域→应保留区域→验收条件”。例如“右侧下方模特额头钻贴变成银色：仅恢复为原始实拍的粉色款，保留其妆容、姿势、背景与左侧两张产品”。实际使用编辑工具引用当前目标和原始产品图；工具未提供mask时不能假称mask已锁定区域。

若问题是错误素材匹配，先改映射再修图。若是未知产品细节，补证据或标记缺口，不反复生图。若只有一张关键检查失败，不重做其他已通过图。两轮后仍有关键错误或出现同类退化，保留最佳结果并标明 `needs_revision`；仅有非关键瑕疵则可标明 `deliverable_with_notes` 交付。

## 输出能力边界

内置工具优先，API仅在明确选择时使用；批量不意味着自动采用API。不把JSON任务清单或提示词打包当作生图完成。

要求1600×1600要核验实际文件，若工具只能给其他分辨率且当前不允许其他编辑方式，记录规格不满足，不能改扩展名、拉伸或谎报完成。遵守当前工具对输出路径、图片展示、自动保存及图像处理的约束。能以实际文件交付时才承诺命名01.jpg等；内置显示结果按工具规则返回。
