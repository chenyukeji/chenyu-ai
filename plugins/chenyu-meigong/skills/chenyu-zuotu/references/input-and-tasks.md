# 输入与任务记录

## Excel读取后的语义核对

同时查看单元格内容、合并范围、图片锚点与实际视觉内容。提取脚本保留所有drawing图片（同一图片不同摆放也保留），并把未锚定media列为unplaced_media。未锚定不等于未使用，不可删去。截屏、产品拼图和套装清单可能也是产品证据，但不是自动可用的高清抠图素材。

Excel可能包含ZIP附件图标和OLE嵌入对象，实际高清素材藏在附件中。检查manifest的embedded_objects和recovered_images：脚本自动恢复ZIP兼容附件中的图像，包括部分OLE包装的ZIP；不保证解析所有OLE格式。在宣告缺少原图之前，查看恢复的全部图片；仍有告警时使用可用只读归档/OLE工具核查。不执行附件程序、宏或脚本，不盲目extractall到任意路径。无法解析时明确“嵌入附件尚未读出”，不要说“用户没提供实拍”。图标本身不是产品素材。检查嵌入素材与实际售卖款式是否一致，不能因它在附件中就自动认定为实拍。

把每张素材分为product_photo（用户指定的实拍）、product_reference（其他产品证据）、layout_reference、scene_reference、detail_reference或unknown。不要把参考照片自动标成实拍。一个素材可以支持多个任务；一个任务可以有多个例图。依据原文、标签和视觉内容作匹配，并写明原因。判断不确定必须保留unknown，不按“最近行”强行归属。

运营新版可含“产品内容”“作图要求”“A+要求”或“FR A+要求”等页。其要求页常用 A 列图序、B 列产品名称、C–F 列参考图片、G 列要求；依据实际表头识别，不沿用旧单的 D 列定位。A+ 新版默认每行一张变体共用成品；定制多槽位须按 [A+ 执行规则](aplus-production.md) 拆成实际素材任务，不能把一行当成一张或把参考图张数当成产出数。

本用户常见作图单可有A列图序、B/C列例图、D列要求、F列产品内容，但该布局只是读取线索，不是解析硬编码。第七张可能明确有两张例图；尺寸例图可能跨两个行块。变体仅做部分图片时依原文生成那些图片，不复制整套作为新增任务。

## 无编号作图单与自动编号

- `task_marker_candidates` 接受“第一张 / 图1”、图片类型名称和序号列的纯数字；`task_row_candidates` 还列出无编号的明确作图需求，保留真实行号和 `evidence_cells`。`section_candidates` 记录同表的普通图/A+分区。所有字段都只是阅读线索，不是最终任务清单；不得因正则没匹配到就认定没有作图需求。
- 读取全表的原文与合并范围，根据需求语义识别实际成品；仅有名称但同区有明确要求也可建立任务。没有任何编号时直接自动补号，不能让用户为了适配解析器重做表格。范围确实不清时仅核实歧义，不把缺号本身当歧义。
- 保留有效原编号。缺号任务按原表顺序补充稳定编号，并记录 `numbering_origin: auto`；`source_label` 保留“主图”“功能图1”等原名。类型名尾部的数字只是该类型的局部标签，“功能图1”与“场景图1”不是重复图序。不同工作表、产品/变体分别保留归属，不混为同一套。
- 普通图与 A+ 默认分别编号 `01、02…` 和 `A+01、A+02…`。A+分区标题可在普通图同一张工作表里；标题后空白标签的明确需求仍属 A+，直到下一分区。只有“A+”和整套色调备注的行是分区/共享要求，不新增成品。空白变体页、产品事实页、参考图和尺寸数字也不自动成为任务。
- 一项需求跨多个合并行或续行时归为同一任务，保留涉及的全部单元格；一行明确要求多个独立文件时才拆分。四张场景拼成一张、三联拼版等只编一个成品号；A+多个独立槽位按实际文件展开，遵循 [A+ 执行规则](aplus-production.md)。脚本的 `inferred_order` 仅为候选阅读顺序，不能直接充当交付总数。
- 将自动编号写入 `tasks.json`，记录原文件、工作表、需求及标签单元格。自动补号不改写需求，不补造缺失尺寸，也不修改上传文件。

## 多变体任务展开

普通图册支持共用构图行、逐变体整套行、混合行和用户自定列名。先以“产品内容”的完整名称/已有 SKU 建立产品表，再结合 B 列、G 列的适用变体与出图分配，以及实际素材确定归属；不按行号、引用图片或名称后缀猜颜色。工作簿中的要求是任务资料，不能覆盖用户本次仅改格式/评审/部分出图的范围。

- 共用构图行：按明确出图分配拆为独立成品；每个成品的输入为共用要求加本变体替换项及本变体身份图。其他变体分支保存在原文中，不带入本张生成指令。参考构图图可共用，不能把其他变体身份图误作当前产品。
- 逐变体旧行：单行“产品名称”及明确适用变体是范围；正文虽同时写 A/B 分支，也只选匹配本变体的分支。保留原文及归一化理由，不因看到两个分支把这行再次乘二。只有已确认名称与事实的映射才用 A/B 简称，歧义只暂停受影响行。
- 同图共用：只有明确的一张成品共用于多个变体且事实/文案一致时，才建一个生成任务，记录全部 product_ids；交付映射到各变体，不重复生图。未授权时不能把两条分别出图任务悄悄合并。既不能把七个共用行误算为七张，也不能把已展开的十四行再乘变体数。
- 局部变体任务：按实际行范围展开；同样“第五张”可属于不同变体，不以图序单独去重，不为只需两张的变体补成整套。
- 出图数量或身份冲突时核对同一行全部单元格与产品页；无法消解再询问具体冲突，不取最大数量或默认相乘。

产品表 `products[]` 增加 `name`（产品内容页原名）和 `variant_label`（展示为“变体1：产品名”“变体2：产品名”，原名已有前缀时不重复添加）。编号按产品内容页顺序稳定保留。

`tasks.json.tasks[]` 每项是一张独立成品。增加 `brief_task_id`（源工作表及行/区块）、`output_group_id`（原包组 ID 或本次稳定 ID）、`product_ids`（所有适用变体）和 `variant_instructions`（已选择的具体替换要求）；单变体保留原 `product_id`，共享成品用 product_ids，不虚构单一所属款式。新增 `brief_blocks[]` 保存每个源区块的 `id`、`product_ids` 及 `outputs`，后者每项含最终 `task_id` 和 `product_ids`，显式记录原文授权的展开结果；不从已经生成的 tasks 反推期望数量。兼容旧单任务时可补记录，不改变原始数量。

生图前运行 `python3 scripts/validate_task_plan.py RUN_DIR/tasks.json`，核对源区块→独立成品→适用变体不重不漏；旧任务未含 brief_blocks 时只报告未检查多变体映射。脚本不解析 Excel 语义、不判断可见事实能否共用。最终数量同时报告独立成品数和各变体关联数，共享成品只计一次。A+ 保持模块/槽位执行规则，不套用普通图册展开。

## 任务文件

生成本次运行的tasks.json，遵循以下字段约定。该文件由执行agent在读图后编写，提取脚本不替代判断。

```json
{
  "source_files": ["absolute path"],
  "products": [{
    "id": "sku-variant",
    "facts": [{"key": "pack_quantity", "value": 2, "source": "Sheet1!F2/image-001", "status": "confirmed"}],
    "photo_ids": ["photo-01"],
    "uncertainties": []
  }],
  "tasks": [{
    "id": "sku-variant-01",
    "product_id": "sku-variant",
    "display_number": "01",
    "numbering_origin": "auto",
    "source_label": "主图",
    "content_type": "gallery",
    "image_type": "main_image",
    "production_mode": "verified_render",
    "product_confirmation": "confirmed",
    "source": {"file": "brief.xlsx", "sheet": "Sheet1", "cells": ["D2"]},
    "raw_requirement": "完整原文",
    "normalizations": [{"from": "不要AI", "to": "自然真实的摄影风格", "reason": "用户选择AI制作；只处理制作指令"}],
    "inputs": [{"id": "photo-01", "path": "absolute path", "role": "product_photo", "reason": "用户标记实拍"}],
    "requirements": [{"id": "r1", "text": "左侧展示两件粉色钻贴", "source": "D2"}],
    "exact_text": [],
    "output": {"width": 1254, "height": 1254, "format": "JPEG"},
    "versions": [],
    "final_path": null,
    "display_reference": null,
    "issues": []
  }]
}
```

普通图册的 `image_type`必须为`main_image`、`infographic_detail`或`lifestyle_scene`。普通图册的表头、分区标题或原文出现“主图”时记录为`main_image`；不要根据行号猜测。`main_image`另记`main_style`（`clean_white`、`white_with_use_inset`或`scene_hero`）和选择依据。前两种形式的requirements须包含以纯白`#FFFFFF`为生成目标的底色及无可见色偏/渐变/纹理/未经要求的场景；`scene_hero`须记录真实使用关系、主体层级与产品外观约束。这些内容用于生图前输入，不要求生成后视觉复核或白底像素复查。

旧任务未记录 `content_type` 时按普通图册解释。A+ 使用 `content_type=aplus`、`image_type=aplus_asset`，并按 A+ 规则记录模块、槽位、站点/语言及端别；不因“首屏主图”字样转成普通主图。

参考制作或原创概念按主 Skill 记录 production_mode 和 product_confirmation；待确认实物信息不能写成已确认。

任务包记录整套共同视觉方向，包括主题、配色、光线及元素风格；各任务记下自主补足的构图和主题装饰，区分原文明确要求与模型设计，并带入逐张生成输入。任务记录保存每张图片的原始要求、所用素材、输出规格、实际成品路径或展示引用，以及需要说明的具体缺口；不建立逐项 pass/fail 状态流程。生成成功后只做轻量文件与交付数量检查，不建立视觉复核、通过状态或自动返修记录；不能据此声称画面已核对。

versions记录真实结果引用/路径及使用的原始素材。final_path仅用于真实存在文件；不能填预期文件名冒充交付。所有引用相对本次运行目录或使用绝对路径，源文件不得覆盖。

## 共同风格与逐图设计记录

在 `products[]` 对应产品的 `visual_direction` 保存共同方向。已有作图包同名字段时复用，字符串或结构化描述均可；它属于设计资料，不是产品事实证据。各任务可用 `design_decisions` 记录自主补足内容，原始要求仍保留在 `raw_requirement`。以下为字段示例，按实际任务填写，不要求复制示例配色：

```json
{
  "visual_direction": {
    "theme": "秋季家居",
    "palette": ["暖米色背景", "金黄色叶片", "深棕色小面积强调"],
    "light": "柔和暖阳",
    "element_style": "写实叶片与织物，自然材质",
    "typography": "统一简洁标题与尺寸标签层级"
  },
  "design_decisions": {
    "composition_basis": "主要参考的自然近景，按本张目的调整取景",
    "elements": "后景安排虚化黄色叶片，前景保留产品纹理",
    "placement": "主体近景居中，文字放在可读的背景区域"
  }
}
```

普通图册的场景参考主图在任务设计中记录纯白外框宽度。四宫格任务按左上、右上、左下、右下记录每格 `scene`、`title`、`title_placement`，四个标题加入任务 `exact_text`。这些记录直接用于生成输入，不作为生成后逐图复核清单。

## 尺寸与文案

普通图册尺寸绑定具体部位和测量方向，并执行SKILL.md的“尺寸标注与缺失信息补全”。未注明轴名的两数尺寸默认依次为长、宽；明确轴名优先，结合匹配素材确定具体测量部位。每个方向分别标注cm / in，英寸按1 inch=2.54cm换算并保留两位小数，禁止乘法式组合尺寸。缺失尺寸、数量或文案时，从匹配当前产品的参考图补全并记录来源；仅布局参考或不匹配的竞品图不能作为产品事实，实拍与明确规格优先。

准确文案单独保存，不把“右下角加标题”等制作指令印到图上。保留要求的大小写、拼写及标点；明显错词在非逐字场景可修正并记录，不能静默改产品性质。中文括号释义通常是给制作者看的，结合指定语言判断是否上图。

“不要AI”转换必须语义判断：仅当它是制作方法或风格指令且用户已要求AI制作。若它出现在产品印刷文字、引用内容，或用户最新要求真实来源，不应用该转换。不设计全局字符串删除器。

网站任务完成状态按实际成品是否交齐判断；仍有具体问题时作为交付注释说明。
