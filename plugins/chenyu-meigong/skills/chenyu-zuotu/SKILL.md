# 亚马逊作图要求执行

开始执行会生成本地文件的任务前，先读取并遵循 [输出目录规范](../../references/output-paths.md)，本 Skill 使用 `image-production` 交付部分，并把该任务目录作为 `RUN_DIR`。

## 输入与目标

接收三类逻辑输入，允许放在同一个Excel或分开上传：①作图要求；②参考例图、背景等素材；③实际售卖产品的实拍图。沿用用户现有表格，无需改成固定模板。按作图单实际图数、变体和用途交付独立图片，不预设必须七张。不修改原始上传文件，不把用户产品素材永久放进本Skill。

默认执行到出图、检查和交付；用户只要求设计、提示词或预检时，停在其指定范围。仅凭本Skill不能承诺后台无人值守、百分百一致或亚马逊必然审核通过。调用当前环境实际可用的工具。

## 1. 读取并对应输入

Excel先按当前可用的Spreadsheets技能读取；对于`.xlsx`，运行本目录下的提取脚本：

```bash
python3 scripts/extract_brief.py INPUT.xlsx --out RUN_DIR/extracted
```

在Skill目录解析脚本路径，RUN_DIR为本次任务目录。脚本只提取原文、图片字节、位置和编号候选，不自动认定产品身份或素材归属。检查`manifest.json`中的warnings并查看实际图片。按[输入与任务记录](references/input-and-tasks.md)完成语义匹配。

先列出全部任务，再实际生成。保留原始要求、来源文件/工作表/单元格、所用图片ID。检查合并单元格、多图同区、跨行浮图、共享素材、空表与变体例外，不能只按图片左上角行号或固定列映射。嵌入图片数量不等于成品数量。

`.xls`不由该脚本读取：用可用电子表格工具在临时副本转换并核验图片和原文；不能提取图片时仅标记对应缺失，绝不当成完整读取。外链、WPS单元格图等未解析格式保留告警，禁止假称无图。已有清晰独立实拍优先于Excel压缩缩略图。

## 2. 锁定事实与解释要求

按角色分别确定优先级：最新明确指令决定任务范围；实拍与用户确认决定产品外形/颜色/结构；明确规格决定尺寸/数量；每张原始描述决定构图/人物/文字；参考例图补充未规定的视觉安排；默认审美最后采用。实拍与规格冲突时不猜测，用其他现有证据解决，仍不明则只暂停受影响任务。

建立product facts：款式、颜色、套装数量、配件、真实图案、尺寸和单位、测量位置、材质依据、正反面、使用方式及不确定项。产品底纸印刷、模特妆容、参考图包装不是自动包含的产品。不能从模糊图编造背面、钻石排列、粘贴结构或规格。

用户已选择AI制作时，将作图描述里的“不要AI”“不要AI感”“找真实场景”“不要假人”等制作/风格措辞解释为写实摄影、自然皮肤纹理、正确光影、贴合透视；保留原文及归一化记录，不据此反复询问。此规则只作用于制作指令，不删除图片上用户要求逐字展示的文字，也不吞掉“不要文字”“不要圈圈”等内容约束。若用户最新指令明确要求真实拍摄来源，则遵从最新指令，不能称AI图为实拍。

把每张要求拆为独立可检查条目：产品数量/外形、位置、画面数量、人物与动作、场景、准确文字、尺寸箭头、禁用元素、规格。为每张任务显式记录`image_type`：`main_image`、`infographic_detail`或`lifestyle_scene`。工作表标题、分区标题或原文标记“主图”时必须归为`main_image`，不能因参考图或产品配色把它当成普通场景图。不同任务的共享事实可引用，但不能把同款的不同变体混用。默认输出规格仅在输入未指定时采用1600×1600、1:1；语言优先使用指定语言和原文，不自动变成德文/法文。

## Amazon 主图背景（强制执行）

- `image_type=main_image`默认且必须使用无色偏的纯白背景（`RGB 255,255,255` / `#FFFFFF`），画布四角、产品周围和分区空白都不能出现粉色、米色、灰色或其他底色。
- 产品颜色只约束产品本身，禁止把“粉色款”“蓝色产品”“配色相似”等产品事实扩展成背景色、环境光、渐变、光晕或装饰元素。参考图中的彩色背景对主图只可作为构图线索，不能继承。
- 主图prompt必须逐字包含等价硬约束：`seamless pure white background (#FFFFFF); no tint, gradient, texture, glow, scenery, border, or decorative background; product color applies only to the product, never to the background or lighting`。不能用`blush white`、`soft pink-white`、`warm white`等近似措辞代替纯白。
- 若作图单同时把一张图标为“主图”又明确要求彩色/场景背景，保留冲突记录并按最新用户指令处理。要使用彩色背景时，将其明确重分类为`infographic_detail`或`lifestyle_scene`，不得仍标记或宣称为主图。用户没有最新确认时，主图的纯白背景优先。
- 主图生成后单独验收背景：查看四角、产品轮廓外侧和大片空白区域；发现色偏、渐变、阴影铺满背景、场景、边框或装饰即为`fail`，必须定向返修，不能以“接近白色”通过。

素材不足先用全部已提供内容判断是否真的影响任务；可继续的任务继续，最后集中指出具体缺口。不要要求用户重新上传已可读取的素材，也不要为普通构图选择反复确认。

## 尺寸标注与缺失信息补全（强制执行）

- 用户未提供尺寸、数量或文案时，先查看该任务匹配的参考图，沿用其布局及适用于当前产品的内容；参考图已清楚给出且与当前款式、变体和测量部位匹配的尺寸可直接采用，记录来源，不重复追问。明确指令和明确规格优先于参考图。仅相似的竞品图可借鉴布局，不直接套用尺寸、套装数量或未经证实的卖点；没有可靠依据时不编造数值或内容，可继续完成不受影响的图片。
- 区分产品物理尺寸与画布像素尺寸；不能按图片像素比例推算产品厘米尺寸。未指定画幅时保留本Skill原有默认输出规格。
- 每个测量方向均单独标注 `cm / in` 双单位，按 `in = cm ÷ 2.54` 换算，英寸统一保留两位小数。只有英寸来源时先换算厘米，并保留来源精度。
- 未注明轴名、以乘号或星号连接的两数尺寸表达，默认依次解析为长、宽；用户明确标注的轴名优先。长宽是产品测量方向，不能因画面旋转而交换数值；结合匹配参考图确定测量部位，不能把局部尺寸画成整件尺寸。
- 分别绘制独立的长、宽双向箭头，每个方向各自标注对应的 `cm / in` 双单位数值。使用当前产品的实际尺寸，不预设具体数值。成品禁止显示乘法式组合尺寸，也不能只补一个总英寸数。
- 箭头与对应测量轴平行，端点对齐被测部位的边界，标签紧邻对应箭头且清晰可读；不要遮挡产品关键细节、交叉错配或贴边裁切。无法确定测量部位时标记该尺寸待核实，不瞎画箭头。
- 生图前把每个方向的来源、测量部位、厘米数、英寸数、准确标签和箭头位置写入任务要求；出图后逐项检查换算、长宽对应、箭头端点、标签位置、双单位完整性及是否残留乘法式尺寸。错误按原有有限返修流程处理，未通过不得宣称合格。

## 3. 逐张制作

实际生图前读取当前imagegen技能及[制作与返修](references/production-and-review.md)。默认使用内置image_gen，一张独立成品一个生成任务；四宫格是一张成品中的四个画面，不把整套商品图做成一张大拼图。优先完成可验证的产品基础图和简单场景，再完成复杂佩戴与多人图，不需每张等待用户确认。

生成输入必须实际附带对应产品图和参考图，不能只在prompt中写文件名。查看本地图片后，按当前工具支持的referenced_image_paths或最近图片机制传入，不同时使用两者，不混入别的SKU。每次注明各输入的角色；返修仍保留原始实拍作为产品依据，不仅依赖上一次AI输出。

选择产品修图、场景/佩戴、尺寸细节、拼版/文字其中的适用操作。生成`main_image`前先注入“Amazon 主图背景”硬约束，不能让产品颜色或参考图背景进入`Scene/backdrop`。默认所有栅格生成与编辑（包括背景、抠图、合成和局部修复）用图像工具；不能因为希望精确就擅自改用Python编辑图片。只有用户明确要求程序排版/处理且上级工具指令允许时，才用确定性排版工具。没有可用精确合成能力时，不承诺像素级保真。

不额外添加购买数量、包装盒、配件、商标、功效和安全承诺。文案逐字要求与未经证实的强功效/安全表述有冲突时，记录待核实，不造证明、不暗改后宣称完全一致。其他不受影响的任务继续。

保留原始主图构图要求。若用户要求“可直接上传/符合平台规则”，核实适用站点和类目的官方当前要求，记录具体冲突，不能把设计符合与平台合规混为一谈。未核实不作合规保证；普通制作不增加无关合规流程。

## 4. 检查、有限返修、续做

每次实际查看生成结果，对照该任务全部条目和原始实拍记录pass/fail/unknown及可见依据。检查产品局部，也检查整图构图。读不清不是通过。识别到图案变更、数量错误、产品悬浮、手指异常、文案错误等时，按明确错误局部编辑。

默认每张最多两轮返修（用户另有要求从其要求），保留最佳版本；返修后重查原来通过的产品细节，避免修A坏B。两轮仍有问题时标记needs_review并交付最佳版本与具体问题，不能冒充合格成品，也不无限消耗调用。工具故障遵守实际错误和限制，不自动切到付费API；只有用户明确选择API/CLI时采用imagegen技能的相应流程。

每张完成后更新本次任务记录，含版本、检查、真实输出引用及状态。继续/修改时仅处理未完成或受影响图片，保留已通过成品；需求变动使相关检查失效，重新检查。不要暗示对话结束后还会继续运行。

## 5. 交付

按用户指定文件形式交付；能提供本地图片文件时按SKU/变体分组编号01、02等，JPEG仅在真实编码为JPEG时使用该扩展名。用只读脚本检查文件规格：

```bash
python3 scripts/check_outputs.py RUN_DIR/tasks.json --out RUN_DIR/file-check.json
```

此脚本仅验证本地文件存在、真实编码和像素尺寸，不修改图片、不验证语义、不替代视觉检查。图像工具只返回显示结果时按工具规则直接展示并记录检查限制；不能编造下载路径或宣称精确1600×1600已核实。

生成图片遵循运行环境自动保存/展示规则；不为单纯展示或保存重复下载上传生成图片。若用户要求命名文件、ZIP或另有报告，使用当前Library技能保存这些交付物；实际保存后再提供真实文件链接。任务记录一般为内部过程，用户请求时再提供。

最终报告完成数/总数、实质性未解决问题并展示成品，不以prompt清单替代图片。不宣称“全部通过”除非每项均有实际检查；不承诺自动审查等于人工核验或平台审核。
