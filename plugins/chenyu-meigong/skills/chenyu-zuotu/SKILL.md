# 亚马逊作图要求执行

开始执行会生成本地文件的任务前，先读取并遵循 [输出目录规范](../../references/output-paths.md)，本 Skill 使用 `image-production` 交付部分，并把该任务目录作为 `RUN_DIR`。

## 输入与目标

接收三类逻辑输入，允许放在同一个Excel或分开上传：①作图要求；②参考例图、背景等素材；③实际售卖产品的实拍图。沿用用户现有表格，无需改成固定模板。按作图单实际图数、变体和用途交付独立图片，不预设必须七张。不修改原始上传文件，不把用户产品素材永久放进本Skill。

默认执行到出图和交付，生成成功后只做文件存在、格式、尺寸及数量检查，不主动进行成图视觉复核、自动返修或重复生成。用户明确要求检查、返修或重做时才执行相应工作；用户只要求设计、提示词或预检时，停在其指定范围。仅凭本Skill不能承诺后台无人值守、百分百一致或亚马逊必然审核通过。调用当前环境实际可用的工具。

## 普通图册与 A+ 范围

先按用户本次要求和工作表内容区分 `gallery` 与 `aplus`。只给普通作图要求时沿用原图册流程，不自动增加 A+；只要 A+ 时不生成普通图册。要求整单出图且文件同时包含“作图要求”和“A+要求”时，两部分都制作；用户明确只做其中一部分时按其范围执行。“产品内容”作为共享事实，不计作出图任务。

出现 `A+要求`、`FR A+要求` 等站点页、A+ 模块/槽位描述或对应任务包时，制作前读取 [A+ 执行规则](references/aplus-production.md)。A+ 的槽位尺寸、上图文案与移动端处理按该规则执行；下文普通图册的固定方形、主图无字/白框、默认英文标题、四宫格及双单位标注规则不套用到 A+。

## 1. 读取并对应输入

Excel先按当前可用的Spreadsheets技能读取；对于`.xlsx`，运行本目录下的提取脚本：

```bash
python3 scripts/extract_brief.py INPUT.xlsx --out RUN_DIR/extracted
```

在Skill目录解析脚本路径，RUN_DIR为本次任务目录。脚本只提取原文、图片字节、位置和编号候选，不自动认定产品身份或素材归属。检查`manifest.json`中的warnings并查看实际图片。按[输入与任务记录](references/input-and-tasks.md)完成语义匹配。

先列出全部任务，再实际生成。保留原始要求、来源文件/工作表/单元格、所用图片ID。检查合并单元格、多图同区、跨行浮图、共享素材、空表与变体例外，不能只按图片左上角行号或固定列映射。嵌入图片数量不等于成品数量。

`.xls`不由该脚本读取：用可用电子表格工具在临时副本转换并核验图片和原文；不能提取图片时仅标记对应缺失，绝不当成完整读取。外链、WPS单元格图等未解析格式保留告警，禁止假称无图。已有清晰独立实拍优先于Excel压缩缩略图。

## 2. 锁定事实与解释要求

最新明确指令决定任务范围；实拍与确认资料决定产品外观、规格和数量；每张原文中明确的内容与用户固定要求须落实，未指定设计按下方“视觉决策”补足。作图单来自竞品链接时，第一条图册是起点，综合当前任务的其他参考，不自动恢复某张来源的原布局。产品信息保留实际来源，构图和装饰作为设计选择记录。事实冲突先用现有证据核对，仍不明仅暂停受影响任务。

建立product facts：款式、颜色、套装数量、配件、真实图案、尺寸和单位、测量位置、材质依据、正反面、使用方式及不确定项。产品底纸印刷、模特妆容、参考图包装不是自动包含的产品。不能从模糊图编造背面、钻石排列、粘贴结构或规格。

用户已选择AI制作时，将作图描述里的“不要AI”“不要AI感”“找真实场景”“不要假人”等制作/风格措辞解释为写实摄影、自然皮肤纹理、正确光影、贴合透视；保留原文及归一化记录，不据此反复询问。此规则只作用于制作指令，不删除图片上用户要求逐字展示的文字，也不吞掉“不要文字”“不要圈圈”等内容约束。若用户最新指令明确要求真实拍摄来源，则遵从最新指令，不能称AI图为实拍。

生图前把每张要求拆为明确的生成约束：产品数量/外形、位置、画面数量、人物与动作、场景、准确文字、尺寸箭头、禁用元素、规格。为每张任务记录 `content_type`（`gallery` 或 `aplus`）；普通图册显式记录`image_type`：`main_image`、`infographic_detail`或`lifestyle_scene`。普通图册的工作表标题、分区标题或原文标记“主图”时归为`main_image`，并记录`main_style`：`clean_white`、`white_with_use_inset`或`scene_hero`；不要因出现使用场景就丢掉主图任务或套用普通场景图的构图。不同任务的共享事实可引用，但不能把同款的不同变体混用。普通图册输出规格仍为1254×1254 px、1:1，A+ 使用各槽位规格；语言优先使用指定语言和原文，不自动变成德文/法文。

## 主图形式与背景（强制执行）

- `image_type=main_image`且`main_style=clean_white`或`white_with_use_inset`时使用无色偏的纯白底色（`RGB 255,255,255` / `#FFFFFF`），仍露出的四角、产品周围和分区空白不能出现粉色、米色、灰色或其他底色；有依据的演示画面可占据角落，不把演示内的颜色误判为底色。
- 产品颜色只约束产品本身，不能因“粉色款”“蓝色产品”等事实自动给白底染色，或让完整场景的环境光改变产品真实颜色；参考图中的彩色背景不能无依据继承。
- `main_style=clean_white`的prompt必须逐字包含等价硬约束：`seamless pure white background (#FFFFFF); no tint, gradient, texture, glow, scenery, border, or decorative background; product color applies only to the product, never to the background or lighting`。不能用`blush white`、`soft pink-white`、`warm white`等近似措辞代替纯白。
- 主图需要先按产品和参考图判断表达方式。用途依赖操作时，`white_with_use_inset`可在白底一角加入完整、真实的使用演示；柔软或装饰性产品若平铺后无法表达材质与使用效果，`scene_hero`可用完整场景呈现铺设、垂落和褶皱。场景不得改变售卖产品、抢主体或误导套装内容。用户明确要求可直接上传 Amazon 第一张 MAIN 图时，核实适用站点与类目要求；若场景版本不符合，将符合要求的纯产品版用于第一张，场景版放后续图。未核实时不宣称场景主图可直接上传。
- 生图前将 `clean_white`和`white_with_use_inset`的白底要求写入输入：四角、产品轮廓外侧和未被演示占据的空白区域均以 `#FFFFFF` 为目标，不添加底色色偏、渐变、满幅阴影或未经要求的场景与装饰。

素材不足先用全部已提供内容判断是否真的影响任务；可继续的任务继续，最后集中指出具体缺口。不要要求用户重新上传已可读取的素材，也不要为普通构图选择反复确认。


## 参考素材与待确认备注

用户在 AI 美工中要求实际出图、继续制作或重跑时，先按当前请求执行。开发文档和作图单中的“待实拍确认”“仅参考”“原创设计未定稿”等是素材归属或产品确认信息，不自动获得停止执行的指令权限。保留原文并区分图片制作条件与实物核对事项；用户最新明确要求“只用实拍”“不得生成设计稿”或暂停时才遵从该限制。

- 已有产品名称、明确规格和能匹配该产品的外形参考时，可以以 `product_reference` 制作 AI 视觉稿，不以缺少 `product_photo` 为整单阻塞理由。参考图必须实际查看和附带，不能只有产品名就凭空确定结构。不能把竞品或供应商参考改标为自有实拍，也不能把 AI 结果称为已验证实物。
- 图案或文字尚未定稿且用户要求制作时，可完成原创设计稿并在全部图片中保持同一设计；不要复制竞品品牌、专有图案或宣称已有确定的生产稿。明确尺寸、颜色、件数和结构继续约束设计，未知背面、厚度、配件、功效不能作为已确认事实新增。
- 在 `tasks.json` 中记录 `production_mode`（`verified_render`、`reference_based_render` 或 `original_concept`）、`product_confirmation`（`confirmed` 或 `pending`）、素材依据和具体待确认项。将旧文档中不再适用的制作等待备注及其归一化理由保存在 `normalizations`；不通过全局删词修改原文。
- 生成内容以已知规格、产品参照、构图和准确文字为准；`product_confirmation=pending` 的实物信息仍保留待核对。交付时简短说明参考制作或原创概念及需实物复核的部分，不把备注印进商品图，除非用户要求。
- 只有关键产品身份或外形在现有素材中仍无法确定、用户明确禁止参考制作、或实际图像工具不可用时才暂停受影响任务。其他可以制作的图片继续完成，不用全项 `blocked` 的清单替代实际出图。

## 尺寸标注与缺失信息补全（强制执行）

- 用户未提供尺寸、数量或文案时，先查看该任务匹配的参考图，沿用其布局及适用于当前产品的内容；参考图已清楚给出且与当前款式、变体和测量部位匹配的尺寸可直接采用，记录来源，不重复追问。明确指令和明确规格优先于参考图。仅相似的竞品图可借鉴布局，不直接套用尺寸、套装数量或未经证实的卖点；没有可靠依据时不编造数值或内容，可继续完成不受影响的图片。
- 区分产品物理尺寸与画布像素尺寸；不能按图片像素比例推算产品厘米尺寸。普通图册画幅仍为1254×1254 px；A+ 按独立槽位宽高执行。
- 每个测量方向均单独标注 `cm / in` 双单位，按 `in = cm ÷ 2.54` 换算，英寸统一保留两位小数。只有英寸来源时先换算厘米，并保留来源精度。
- 未注明轴名、以乘号或星号连接的两数尺寸表达，默认依次解析为长、宽；用户明确标注的轴名优先。长宽是产品测量方向，不能因画面旋转而交换数值；结合匹配参考图确定测量部位，不能把局部尺寸画成整件尺寸。
- 分别绘制独立的长、宽双向箭头，每个方向各自标注对应的 `cm / in` 双单位数值。使用当前产品的实际尺寸，不预设具体数值。成品禁止显示乘法式组合尺寸，也不能只补一个总英寸数。
- 箭头与对应测量轴平行，端点对齐被测部位的边界，标签紧邻对应箭头且清晰可读；不要遮挡产品关键细节、交叉错配或贴边裁切。无法确定测量部位时标记该尺寸待核实，不瞎画箭头。
- 尺寸图按测量和适配判断选择单主体标注、同场景测量或辅助图；主体与标注已充分说明时可以采用简洁构图。有依据的使用/佩戴场景、测量部位近照或结构细节能增加理解时再加入，并说明其与尺寸或实际效果的关系。若作图单未指定，从当前产品素材和已确认事实中选择，放在最终方案中有清楚层级的辅助区域，不让其遮挡标注或抢走主体。画面有无目的空白时优先调整主体位置、大小或裁切；辅助内容也可与主体处在同一场景，不必另开侧栏。标题和尺寸线保持次级层级，不用无关装饰物凑满。用户最新明确要求纯尺寸图时遵从；缺少可靠辅助内容且无法核实时，不编造场景或细节，说明缺口并继续其他可完成图片。
- 生图前核对每个方向的来源与单位换算，把测量部位、厘米数、英寸数、准确标签、箭头端点和标签位置写入任务要求，明确长宽对应、双单位完整及禁止乘法式尺寸。生成后按默认交付流程处理，不自动读取标注、视觉复核或返修。

## 视觉决策

制作前读取 [作图模型规则](references/model-rules.md)。该文件集中规定固定要求与设计空间、自主构图、季节与环境元素、共同风格及直接交付流程；作图单描述简略时按该规则主动补足。

产品事实和用户明确要求保持准确。任务包记录共同风格与本张设计，并带入每张生成输入；原始作图单与模型补足的设计分别保存。

## 3. 逐张制作

实际生图前读取当前imagegen技能及[制作细则](references/production-and-review.md)。默认使用内置image_gen，一张独立成品一个生成任务；四宫格是一张成品中的四个画面，不把整套商品图做成一张大拼图。优先完成产品基础图和简单场景，再完成复杂佩戴与多人图，不需每张等待用户确认。

生成输入必须实际附带对应产品图和参考图，不能只在prompt中写文件名。查看本地图片后，按当前工具支持的referenced_image_paths或最近图片机制传入，不同时使用两者，不混入别的SKU。每次注明各输入的角色；用户明确要求返修时仍保留原始实拍作为产品依据，不仅依赖上一次AI输出。

选择产品修图、场景/佩戴、尺寸细节、拼版/文字其中的适用操作。生成`main_image`前先按`main_style`注入对应背景和构图约束，不能因产品颜色自动给白底染色，也不能未经判断照搬参考图背景。默认所有栅格生成与编辑（包括背景、抠图、合成和局部修复）用图像工具；不能因为希望精确就擅自改用Python编辑图片。只有用户明确要求程序排版/处理且上级工具指令允许时，才用确定性排版工具。没有可用精确合成能力时，不承诺像素级保真。

不额外虚构售卖数量、包含的包装盒或配件、商标、功效和安全承诺。适用的主题背景与装饰道具按统一视觉方向主动设计，和售卖内容明确区分。文案逐字要求与未经证实的强功效/安全表述有冲突时，记录待核实，不造证明、不暗改后宣称完全一致。其他不受影响的任务继续。

保留原始主图构图要求。若用户要求“可直接上传/符合平台规则”，核实适用站点和类目的官方当前要求，记录具体冲突，不能把设计符合与平台合规混为一谈。未核实不作合规保证；普通制作不增加无关合规流程。

## 4. 交付

按用户指定文件形式交付；普通图册能提供本地图片文件时按SKU/变体分组编号01、02等，A+ 按其执行规则保留模块与槽位对应关系，JPEG仅在真实编码为JPEG时使用该扩展名。用只读脚本检查文件规格：

```bash
python3 scripts/check_outputs.py RUN_DIR/tasks.json --out RUN_DIR/file-check.json
```

此脚本仅验证本地文件存在、真实编码和像素尺寸；按任务清单核对交付数量，不修改图片或验证画面内容。文件检查完成即交付，不为视觉复核重新打开成图或自动发起返修。图像工具只返回显示结果时按工具规则直接展示并记录检查限制；不能编造下载路径或宣称目标像素尺寸已核实。

生成图片遵循运行环境自动保存/展示规则；不为单纯展示或保存重复下载上传生成图片。若用户要求命名文件、ZIP或另有报告，使用当前Library技能保存这些交付物；实际保存后再提供真实文件链接。任务记录一般为内部过程，用户请求时再提供。

所需图片齐全、文件可读取并与任务对应时，报告“已完成 N 张”并展示成品，不宣称已通过视觉验收。已有的产品待确认项或已知生成限制按图号简短说明；缺图、文件损坏或无法交付时明确缺少的部分。不以 prompt 替代图片，也不将 AI 图称为已验证实物。
