# Amazon Product Image Detail Repair

开始执行会生成本地文件的任务前，先读取并遵循 [输出目录规范](../../references/output-paths.md)，本 Skill 使用 `retouch` 交付部分。若宿主图像工具只能直接展示结果，则遵守工具规则，不为满足目录约定编造文件路径。

## 任务契约

接收三个部分：
1. **Original Image**：一张完整原图，作为唯一完整画布及真实性基准。
2. **Detail Images**：一张或多张从该原图裁切、放大或截图的细节图，用于定位。
3. **Modification Description**：每张细节图对应的修改描述。

将每组“细节图＋描述”视为一个局部任务。内部完成理解、定位、编辑指令组织、修复和检查；成功交付时只呈现 **一张包含全部修改的完整原图**。不交付局部裁切、多个版本、前后对比、分析、Prompt、修改列表或QA报告。

细节图不是新设计参考，不把其比例、裁切或构图应用到完整原图。保留完整原图，不用细节图替代编辑基础。

此输出契约针对实际修图。创建、安装或解释本Skill时按用户当次请求响应。遵守宿主更高优先级的必要沟通和工具展示要求；不能通过Skill屏蔽这些要求。

## 输入核对与内部定位

- 查看完整原图及全部细节图。对尚未看过的本地图片，先使用可用的图片查看工具。
- 内部记录原图宽高、宽高比、产品与人物数量、主体结构、颜色、材质、比例、位置、背景、光影和构图。只记录可验证的信息。
- 按用户编号、文字或明确排列关系匹配细节图与描述。不根据文件名猜测不明确的对应关系。
- 利用结构、纹理、轮廓、颜色、相邻物体和位置关系，将每张细节图匹配回原图。重复产品或左右对称部位必须区分。
- 细节图中的圈、箭头、批注只用于定位，不复制到原图。
- 为每个任务建立内部记录：目标位置、请求变化、最小编辑范围、边缘过渡范围、保护项、与其他任务的重叠关系和完成状态。不输出记录。
- 只有可靠定位后才编辑。缺少完整原图、描述对应关系不明、存在多个同样合理的位置或描述直接冲突时，用一句最短问题询问必要信息。不要猜着改，也不要把跳过任务的图片宣称为全部完成。
- 若部位已可靠确定但边界不够精确，采用保守范围；不能用“宁可少改”掩盖未定位或未完成。

## 最小修改原则

只改变实现描述所必需的最小区域及少量自然过渡区域。按语义理解修改意图，不借机美化其他区域。

例如“胡子稍微短一点”：只适度缩短长度，保留宽度、颜色、毛发质感、面部、眉毛、表情和背景；无具体数值时采用可见但保守的幅度，不杜撰精确尺寸。

例如“去掉中间白线”：删除指定白线，依据相邻产品真实表面与结构补全；不重画整个产品，不用无关纹理遮盖。

### 默认保护项

除非用户明确要求改变该项，否则保持：
- **产品**：数量、整体尺寸与比例、主要轮廓、颜色、材质、结构、配件、Logo和图案。
- **人物**：身份、人脸、五官、表情、发型、肤色、姿势、服装和数量。
- **构图**：产品与人物的位置、大小、角度、留白、原图裁切范围和宽高比。
- **环境**：背景物体、整体光线、阴影关系和装饰。

将明确请求视为对应保护项的局部例外，不扩大到其他部位。不得擅自增加文字、Logo、徽章、图标、箭头、水印、装饰、配件或产品数量。不得删除正确零件。

## 编辑执行

1. 使用宿主可用的图像编辑工具，优先使用 image_gen；遵守该工具当前输入、图像引用和展示说明。不以文字方案替代成品，不默认调用额外付费API。
2. 使用实际图像引用提供完整原图及相关细节图，明确标识“完整画布”和“定位参考”的角色。若使用 image_gen，本地引用使用 referenced_image_paths；仅当至少一张目标图没有本地路径时使用能覆盖全部目标的最小 num_last_images_to_include。不得同时传两种引用方式。若工具引用上限无法包含全部所需图，分批在同一完整工作图上累积处理，或请求补齐可引用图片。
3. 内部编辑指令逐项写清目标位置、变化和保护项，要求保持完整画布，不把细节参考生成成最终裁切图。
4. 仅在工具确实支持局部选区、蒙版、局部高分辨率修复及回贴时，使用“原图局部区域→放大精修→无缝融合回完整原图”。保留真实坐标、边界和完整画布，避免接缝、模糊、光色跳变。
5. 工具不支持局部管线时，使用完整原图作为编辑输入，给出明确的最小编辑约束。不虚构已使用蒙版、逐像素锁定或无损回贴，不承诺生成式编辑能使非目标像素绝对不变。未经用户明确要求，不使用Python或其他脚本替代图像编辑。
6. 对同一原图的多任务保留统一状态：以原图为永久对照，以最新通过检查的完整图为后续编辑基础。后续修改不得丢失先前修复。重叠区域按依赖顺序处理，兼容变化可在一次编辑中合并完成。
7. 若工具每次调用会自动展示生成结果，优先在单次编辑调用中纳入全部兼容任务，以减少中间图；不得谎称能隐藏工具强制展示的结果。用户交付物仍仅指定一张完整最终图。
8. 不通过整图重新设计来处理局部失败。用户明确要求逐次修改时保持该顺序；否则自行选择最能保护原图且避免遗漏的执行方式，不要求用户批准常规操作。

## 修改类型

| 类型 | 执行动作 | 必须保留 |
| --- | --- | --- |
| 删除错误元素 | 去除指定白线、污点、伪影、多余物体或零件，按周围真实结构补全 | 正确零件、表面连续性、接触与遮挡关系 |
| 局部形状调整 | 仅将指定部分缩短、加长、变薄、变厚、收窄或修圆 | 颜色、材质、纹理、风格、与主体连接关系 |
| 局部颜色修正 | 在指定区域调整颜色，融入原有光照 | 结构、纹理、高光、阴影，避免纯色色块覆盖 |
| 真实感修复 | 修正纹理、边缘过渡、微小阴影、光照和表面细节 | 产品设计与可见真实细节，避免凭空创造结构 |
| 边缘修复 | 清理白边、灰边、毛边、锯齿、抠图残留和背景污染 | 真实轮廓和必要纤维、羽毛等自然边缘 |

小型纹理、胡子、眉毛、头箍连接、手套指尖、饰品接口等优先采用工具支持的局部高分辨率处理。修复应保持商业产品摄影质感，不擅自扩展为全套亚马逊图片合规改版。

## 冲突与失败

- 对非直接矛盾的要求，按“用户明确描述→产品真实性→原图结构→最小修改”处理。
- 同一区域被同时要求相反变化时，不自行选一个，也不重设计产品以规避冲突；询问一个必要澄清问题。
- 保持原图分辨率或更高分辨率、宽高比和完整构图。先核实工具能力与可验证的输出尺寸。不得把低分辨率输出声称为原分辨率，也不得用改扩展名、裁切或拉伸伪装达标。
- 若工具无法满足必要分辨率或保真要求，先寻找已授权且支持的编辑路径；无可行路径时简短说明具体阻碍，不伪造成功。
- 缺少输入、无法定位、直接冲突或工具失败属于必要异常，可给一句必要询问或失败说明；“只输出图片”不要求静默失败或谎报完成。无异常时不输出这些说明。

## 内部检查与局部返修

工具允许检查结果时，对照完整原图和每组细节要求，检查：
1. 全部请求是否完成，位置与幅度是否正确。
2. 非目标区域是否有误改，先前修复是否被覆盖。
3. 产品数量、结构、比例、颜色、配件和图案是否保持。
4. 人物身份、脸部、姿态、数量是否保持。
5. 背景、构图、光线、完整画布是否保持。
6. 是否出现新伪影、白边、结构断裂、接缝或不自然纹理。
7. 尺寸是否符合原图分辨率或更高要求，宽高比是否保持。

只修复失败的局部并重新检查，保留已通过部分；默认同一问题最多局部返修两次，仍无法达标时如实说明阻碍，不无限重画。工具不提供检查能力时，不声称已经完成无法执行的检查。

## 最终输出

成功时，通过宿主指定的图片展示方式，**仅输出一张修改完成后的完整图片**；image_gen 在代码模式下使用其要求的 generatedImage 返回方式。不再附加文字或重复图片。

不返回分析过程、编辑Prompt、QA清单、修改说明、修改列表、局部结果、备选版本、前后对比或安装文档。

始终满足：**一张原图＋多张细节图＋多条对应描述→同一画布上的全部修复→一张完整最终图片。**
