# 晨玙 Amazon Listing 规则

更新日期：2026-10-13

本文件是 `chenyu-yunying` 插件生成欧洲站非媒体类目 Listing 的统一规则。平台硬性规则与晨玙内部写作标准分开标明；目标站点或类目存在更严格且已核实的要求时，从严执行。

## 1. Amazon 平台规则

- 非媒体类目 `Item Name` 最多 75 个字符，包含空格。
- `Item Highlights` 最多 125 个字符，包含空格。
- 两个字段都参与搜索，Amazon 不对其中一个设置搜索优先级。
- 最重要的变体属性保留在 Item Name，受 75 字符限制无法容纳的其他属性移入 Item Highlights。
- 标题不得使用 Amazon 禁止的特殊字符；同一实义词不得无意义反复出现，介词、冠词和连词等语法词除外。

官方依据：

- [Amazon 2026 年 Item Name 与 Item Highlights 说明](https://sellercentral.amazon.de/seller-forums/discussions/t/c6f803a9-67a5-4c02-809a-bf3a9cb6b25f?postId=c6f803a9-67a5-4c02-809a-bf3a9cb6b25f)
- [Amazon 产品标题规范公告](https://sellercentral.amazon.de/seller-forums/discussions/t/0cbed52b-f184-452d-909e-6f8501a28791)

## 2. 产品事实与同款证据

标题只参考全部有效链接的竞品标题，五点只参考全部有效链接的竞品五点，不跨字段取材；开发表只负责识别本品和纠正明确的实质差异，不用于自由扩写标题或五点。仅当开发表明确写出的材质、结构、功能、数量、适配等属性与参考差别很大、会影响商品或购买判断时，才以开发表为准修正对应内容；其他内容继续整合参考。缺项、简略描述和措辞不同不属于差异。修正需保留参考原文、开发表单元格和值及具体改动位置。

不得从开发表零散属性、作图要求或生成效果图推演新的制作工艺、功能、操作或购买收益；每个参考词组/短句必须支持所写的具体含义，而非只因涉及同一个部件就挂作来源。

本品属性缺失时默认采用第一条链接的对应属性；五点内容则充分整合所有有效参考。以下顺序仅处理已明确出现的实质差异，不因本品描述缺项或说法不同就推翻参考。事实冲突核对优先级（不代表文案取材或篇幅优先级）：

```text
用户当前明确说明 > 最后一张产品详情表的变体名称、产品主图及对应规格 > 其他自有资料 > 第一条已确认同款或用户授权采用的链接 > 其他同款链接 > 同材料竞品的适用功能 > 普通同类竞品
```

用户、采购记录或产品证据确认第一条链接与自有产品是同款时，可以采用该链接中与当前规格不冲突的功能、结构、材质表现、安装、使用、清洁、收纳、覆盖效果和适用场景。本 Listing 工作流已获用户授权默认参考第一条链接：补足未给出的属性时，即使未独立确认整件同款，也先提取其当前匹配款式中可用的具体尺寸、材料、结构、配件和使用方式，填入产品属性及“产品内容”页，再以这些细节撰写 Listing；人工发现不符时可随后微调。用户授权不覆盖自有资料中的既有属性，不允许迁入另一款式、品牌、认证或售后承诺。内部事实记录保存采用依据和具体 ASIN/字段；产品内容页直接写属性，不写参考链接或证据状态。

五点和详情必须充分整合用户提供的全部有效参考链接，能采用的相关实质内容覆盖越全面越好；不是只围绕第一条写，其他链接同样可以贡献核心卖点、结构细节、用法和场景。一条五点可融合多个链接，按共同主题合并同义内容，把互补信息组织成五个不同的购买重点；每个有意义的短句均可追溯到实际采用的 ASIN、点位和原文。第一条链接优先用于本品描述缺失时的产品属性依据，不限制文案取材范围；只有本品描述确实明确写出且存在实质差异时，才局部替换对应内容，未写或措辞不同不算冲突。

不得迁移竞品品牌、店铺身份、ASIN 文案、不同尺寸、不同数量、不同配件、竞品独有版本、认证、质保和售后承诺。开发资料与同款链接冲突时，以开发资料为准。未确认同款时，只要自有产品与竞品材料一致，竞品五点中的材料表现及适用于本品的功能就可以采用，并按自己的产品和句式改写；不要求额外确认整件商品同款。遇到与本品结构或用途明确冲突的内容再排除，其他竞品信息用于关键词和写法参考。来源和材料对应关系留在内部事实记录，不把竞品身份写给买家。

滤芯、耗材、集尘袋、软管、转接件等依赖适配关系的产品，兼容系列、型号和 OEM/替换件号属于核心产品事实。来源可以是用户当前明确说明、自有包装或说明书、供应商确认，或已经确认同款的具体竞品点位。普通未确认竞品标题只能提供待核候选，不能单独支撑兼容宣称；但用户明确指定当前产品适用的型号或件号后，应按用户确认写入事实表和买家文案。

每个买家字段必须单独记录实际使用的事实编号：Item Name、Item Highlights、五点 1–5 和 HTML 详情分别写入 `field_fact_ids`。字段中出现的材质、过滤介质、性能、周期、认证、安装方式、兼容型号和使用结果必须能在该字段的事实编号中追溯；只在全局 `claim_fact_ids` 中笼统列出事实不够。参考链接中的“活性炭、抑菌、OEM 标准、建议更换周期”等具体宣称，未取得自有事实、已确认同款点位或同材料适用功能依据时不得写入。

## 3. Item Name

- 单行，最多 75 个字符；内部目标尽量达到 70–75 个字符，但没有硬性最低长度。先完成竞品标题合并与自有事实筛选，再考虑长度；没有来源支持的词不能为了接近上限而加入。
- 只用真实、高相关关键词和关键差异写标题，不用尺寸、材质、低价值词或空泛形容词补长度。
- 不用 `/` 分隔关键词或场景，按目标语言自然成句。
- 使用恰好三个不同的核心关键词短语，优先选择买家搜索本品时使用的产品名称、同义称呼及“图案/主题＋产品名称”等明确指向本品的短语；三个短语不按词类各占一个名额。先保证产品相关性，再根据目标站点真实搜索数据优先选搜索需求较高的词，保留来源站点、指标和时间；竞品标题中的出现频次不能当作搜索量，无搜索量数据时不标称“高搜索量”。单独的用途、场景或宽泛节日词不作为默认核心词；只有目标站点搜索证据支持且搜索意图匹配本品的场景组合短语才可采用。尺寸、材质、颜色、数量和普通形容词本身不占核心词名额。
- 用户给出多个竞品链接或标题时，必须读完所有有效标题，分别识别产品名称、同义称呼、图案/主题组合及补充属性，结合搜索证据选择三个与本品匹配的核心短语；用途/场景和尺寸另作补充信息评估。全部有效标题的 ASIN/链接、采用词义及排除理由记入内部 `title_candidate_audit`；`title_reference` 只映射标题实际采用的来源，未采用或仅用于后台搜索词的链接不挂入标题参考；只沿用“桌旗”一个词或只看第一条链接不合格。按目标站点语言和自己的句式重写，不照搬整句。标题和 Item Highlights 综合全部链接的有效词组与细节，优先采用相关的共有词义，再补关键差异与互补信息。标题每个有实际含义的词组须对应有效竞品标题原文，Highlights 可对应竞品标题或五点；本品事实只用于明确实质差异的局部修正；不添加无依据的氛围、效果或用途描述。竞品品牌、独有图案、材质或规格不得迁移。
- 数量为 1 时不写数量；数量大于 1 时，本地化数量短语紧贴在第一个核心产品词前。
- 能解释价格、适配或购买差异的重要结构与功能优先放在标题前部，例如层数、加厚、双面、带灯、可折叠。普通尺寸、材质和颜色不自动挪到其他卖点字段；无购买价值时可仅保留在参数资料，内部款号不写入买家文案。竞品标题中出现的材质可在本品标题采用，不额外要求证明它是主要购买理由；不能为凑字数加入。
- 竞品标题中出现的尺寸可在本品标题采用；最多一组，放在标题最后。尺寸值按本品明确的实质差异修正，不再追加购买重要性门槛；竞品标题未提及则不自行从五点或参数表补入。
- 适配型产品的主要兼容系列、型号或替换件号属于标题核心识别信息，不是“内部款号”。至少一个主要标识必须进入 Item Name，不能只写通用品名和尺寸。若确需同时写尺寸，仍放标题最后。
- 场景不是标题必填项，也不为凑足三个核心短语而加入。只有真实搜索证据支持且与本品匹配、有空间时才补充；其他适用场景放入 Item Highlights。
- `Design A/B/C`、`Diseño A`、`Variante A` 等内部编号不得进入任何买家可见字段。只有用户明确确认它本身就是买家识别的公开变体名时，才可记录到 `buyer_visible_variant_terms` 后保留。
- 父体只写共用事实；子体只写当前 SKU 的真实属性。

推荐结构：

```text
[确认品牌] + [数量>1] + 第一核心产品词/关键差异 + 其他核心词 + 高价值属性或场景
```

## 4. Item Highlights

材质、尺寸及一般结构不是必填卖点。按字段对应取材：标题参考全部有效竞品的标题，五点参考全部有效竞品的原始五点，不跨字段搬运。竞品标题出现的材质或尺寸可用于本品标题，不再额外要求证明它是主要购买理由；竞品五点出现的内容在本品五点中整合、去重。对应参考字段未提及的普通参数，不因开发表有值就自行补入。开发表只在明确实质差异处修正对应内容。Highlights 可补充参考中已有、标题未覆盖的有效信息，但不强制搬入材质或尺寸凑篇幅。产品参数页可保留已有事实，不据此强迫前台字段重复。

- 每个站点、每个子体必填，单行，最多 125 个字符。
- 有足够重要信息时内部目标为 120–125 个字符；信息价值优先于接近 125 字符。不足时逐项检查标题未覆盖的真实规格、图案/结构、使用位置和场景；没有有效新信息时可以留短，不能堆砌近义词或重复句。
- 必须自然包含 Item Name 三个核心关键词短语中的至少一个（可用目标站点认可的同义词形），使两个前台字段明确衔接；其余内容再补标题放不下的真实信息，不机械重复整句。
- 用一句自然、可读的当地语言表达，不写成逗号堆砌的关键词清单。
- 优先放竞品实际强调、标题未覆盖且有购买价值的功能、适配或用途信息。材质、尺寸和变体属性先按上述取舍，不按属性清单依次填满。标题已写整包数量时，不在 Highlights 再写相同件数与产品名称；其他数量（如图案种数）须明确所数对象。
- 适配型产品必须在 Item Name＋Item Highlights 中覆盖完整的已确认兼容清单。Item Highlights 优先列品牌系列和 OEM/替换件号，再补标题未提及的尺寸；“请核对旧滤芯尺寸/说明书”只能作为必要提醒，不能替代具体兼容信息。
- 适配型产品的五点 1 必须以兼容系列/型号/替换件号为核心，HTML 详情必须再次完整列出全部已确认兼容标识；中文翻译保持相同标识。尺寸只作补充核对，不能成为第一卖点。
- 可以自然重复标题中的关键差异和核心关键词，但必须补充新的规格、结构或场景信息。

## 5. 五点卖点

- 必须正好五条。
- 每条格式：`相关 Emoji＋【本地语言利益点标题】＋2–4 句正文`。
- 只计算正文时，每条必须超过 200 个可见字符；200 个及以下不合格。
- 不设置机械最高字符数，但不得用同义改写、空话或重复句凑长度。
- 每条围绕一个具体产品特点展开，用数量、部位、尺寸、材料表现、操作或真实用途补足信息。特点本身已清楚时，不强制追加“因此更方便”一类利益解释。
- 第一条直接说明最重要的产品差异和购买理由，不以背景介绍或免责声明起笔。
- 五点尽量整合所有有效链接有价值的实质内容，每个链接均记录采用信息及位置；重复信息合并，不适用或无新增内容的链接记录原因，不为凑链接数挂空引用。本品属性缺失以首链接为默认依据，仅对本品明确的实质差异作局部修正。
- 写作前按 [五点取材与去重](skills/chenyu-listing/references/bullet-evidence.md) 完成参考卖点提纲；每条的核心购买信息不同，不能用外观、佩戴、包装等不同标题重讲同一结构。
- 一条自有五点可以融合多个竞品的适用描述，同一来源的不同信息也可分配至不同主题；合并同义内容，避免重复占位，不强制保留来源的五条划分。
- 每条自有五点都要指向至少一个已实际读取的竞品原始五点，以 `ASIN 第N点（采用的主题）` 标在对应参考列；融合多个点位逐一列明。只有标题、图片或自有开发文档时不能声称五点已参考竞品。取不到原五点先补取，仍缺失则暂停相关五点交付。
- Item Name 和 Item Highlights 的有含义词组分别注明来源：采用的词组、竞品 ASIN、对应原文短语；Item Name 仅引用竞品标题，Highlights 可引用标题或第 N 点；因实质差异修正的规格注明已确认事实和差异。参考列展示逐词组映射，不以一串 ASIN 或“参考标题/图册”替代。

标题和 Highlights 按有意义词组、五点和详情按最小有意义短句记录实际来源。新包使用 `source_mapping_version=2` 与 `clause_sources`，详见 [分析脚本接口](skills/chenyu-listing/references/analysis-contract.md)。参考列逐项显示“生成词组/短句 ← ASIN 标题/第N点/详情（实际原文）”或本品事实编号；融合多处时保留各处对应关系。语法连接词和纯栏目标题无需独立来源，产品修饰词、具体属性及使用结果不能当作语法豁免。来源真实不等于属性适用于本品，两项分别核对。`clause_sources` 与词组来源记录文案实际从哪里提炼；`field_fact_ids` 记录本品事实核对，二者不互相替代。已有参考来源且自有资料仅用于核对一致性时，不在每个短句下重复追加“自有事实”；自有信息确实贡献独有内容或不同参数时，才给对应短语记录 fact_id。

### 5.1 买家文案硬规则

- 所有句子都直接回答买家关心的问题：产品包含什么、有什么结构或细节、怎样使用、适合放在哪里，以及使用后能得到什么具体结果。
- 不写面向卖家、审核人员或运营流程的解释，例如“便于买家区分实际包装与场景道具”“让买家清楚了解包装内容”“保持整套产品的统一识别度”“与标题/图片一致”。这类句子没有提供新的产品信息，视为空话。
- 不使用“买家、顾客、消费者”作为文案叙述对象来解释信息呈现方式；直接描述产品事实和使用结果。
- 不把证据状态、来源或差异核对写给买家。“已确认的套装内容”“根据资料/包装记录”“参考产品”“竞品图中”“自有套装不包含”等词句必须留在事实或参考记录，目标语言和中文翻译都不得出现。卖点标题直接写产品特点或使用收益，例如“手缝修补基础工具”，不得写“已确认的套装内容”。
- 产品包装重量和外包装尺寸用于开发、物流或仓储核算。除非包装本身是买家选择商品所需的明确规格，否则不得写进五点或详情，也不得向买家解释这些数据“不是针或单件工具的尺寸”。
- 同一条五点内不得出现逐字重复或仅替换少量词的同义句；五条之间也不得用相同句子重复凑长度。每个句子必须增加新的事实、动作、条件、位置或可观察结果。
- 保留既有超过 200 字符的长度要求，但来源与非重复优先；长度不足应回查参考中尚未使用的实质内容及本品差异，不得为了通过检查臆造动作、搭配或收纳。仍缺证据时说明缺口，不把凑足字符称为完成。
- 可以在不同前台字段重复核心事实，但必须按字段深度展开；不允许在同一个字段内机械复述。
- 不把数量的算术结果或功能的否定重述当作新增信息。例如“4个可分成4份”“一次准备四份小礼物”“无需另外挑选”“不受固定姿势限制”“换位置后仍可重新塑形”“单独使用仍保留完整造型”均不是独立卖点，不能用来补长度。真实的套装构成、可调部位和用途可以直接写一次。
- 逐句做删除检查：删除该句后，买家是否少知道了某项具体属性、操作条件或用途？若没有，就删除；不能仅因为多了一个场景名或换了一个动作词而保留。

### 5.2 Listing 与作图要求隔离

- Listing 可以说明产品适合放在哪里、如何调整或如何使用，但场景必须服务于购买判断或实际使用，不能转写为美工构图方案。
- “画面更丰富、增加层次、前后错落、不同高度排布、形成视觉焦点、增强动态感、避免呆板、近景/远景、构图、镜头、留白、主体占比”等均属于作图要求，不得进入 Item Highlights、五点或详情。
- 对可弯折、可调节产品，直接写可调部位和有证据的姿态；只有特殊锁定、调节范围或操作条件确有证据时才展开。不要把“可以调整”再解释成“不受固定姿势限制、换位置仍能调整”，也不能写画面动态感或构图效果。
- 竞品图片只能用于确认可见结构、尺寸关系和真实使用位置；竞品的拍摄角度、道具搭配、前后景、摆放层次和构图方式不得迁移为 Listing 卖点。
- 中文翻译也执行同一边界，不得因为它不属于上传字段而保留作图口吻。

可参考的主题组织方式（先按实际参考内容取舍，不强制将数量、尺寸和材质分别占一条）：

1. 准确包装/变体组成、核心差异，以及该组合的具体使用方式。
2. 关键结构或功能、实际操作动作，以及功能带来的可观察结果。
3. 材质或可见设计细节，以及这些细节在触摸、安装、佩戴或实际使用中的具体表现。
4. 重要尺寸、适配边界和明确的摆放/安装位置。
5. 礼赠、使用场景、清洁收纳或另一项未覆盖的购买理由；必须提供新的具体信息，不得总结前四点。

已确认同款或用户授权采用的参考链接是可用卖点与使用细节的主要内容来源，自有资料补充和校正本品差异。不能只写“营造氛围、精美设计、用途广泛”等空话，必须说明产品具体有什么、如何使用以及带来什么结果。

## 6. HTML 详情描述

通读全部有效竞品五点及普通/A+描述，整合各链接的共同重点与互补细节为 3–5 项详情功能；本品描述明确且有实质差异时才局部替换。每个最小有意义短句记录实际引用的 ASIN、标题/第 N 点/详情及原文短句，允许一段融合多个来源；本品事实通过 field_fact_ids.description 绑定，不把整篇详情只指向一个链接。

只使用 `<p>`、`<br>`、`<b>`，按以下顺序生成：

1. 产品概述：2–3 句，说明产品是什么、核心结构、主要用途和场景。
2. 3–5 项编号功能：每项 2–4 句，详细说明特点、材料/结构、使用方式、解决的问题、买家结果和必要边界。
3. 产品参数：写清测量部位、数值和单位。
4. 使用或保养方法：有可靠事实时填写，位于参数之后、包装之前。
5. 包装内容：逐项列真实数量；场景道具不算配件。
6. 必要注意事项：仅在确有事实时填写，位于包装内容之后。

包装内容默认只写实际包含的物品和数量，不自动追加“图片中的其他装饰/道具不包含”等笼统免责声明。只有某个具体配件极易被误认为随货提供，且自有资料、用户说明或已确认同款证据明确要求提示时，才在“注意事项”中点名该具体配件；不得把免责声明写进包装内容来凑字数。

## 7. 前台字段重复

取消“标题、Item Highlights、五点和详情不能重复”的硬性要求。

允许关键差异同时出现在标题、Item Highlights 和五点 1；重要尺寸同时出现在 Item Highlights、五点和详情；核心关键词在多个前台字段自然出现；主要场景在 Item Highlights、五点 4 和详情中重复。不同字段只需承担不同深度：标题负责识别，Item Highlights 负责补足，五点负责解释，详情以适用的参考五点和描述充分展开，本品描述只在明确的实质差异处局部修正。

逐字复制大段文案只作为质量复核提示，不因关键词、尺寸或核心事实重复而判定失败。

## 8. Search Terms

Search Terms 最后生成，只填写 Item Name、Item Highlights、五点、详情和其他前台属性尚未覆盖的增量词。

### 8.1 候选词来源

1. 从第一条适用链接提取 ASIN，并作为主要参考 ASIN。
2. 使用运营任务已配置的卖家精灵账号反查该 ASIN 的自然关键词，记录实际站点、ASIN、读取时间和原词；可运行 `skills/chenyu-listing/scripts/collect_sellersprite_keywords.py`。账号已配置时不得略过这一步。
3. 同时从全部有效参考链接的标题提取产品词、同义词、当地常用词形和高相关长尾词；不得只依赖卖家精灵，也不得只看第一条链接标题。
4. 按当地产品名称、同义称呼、结构/用途叫法和常见词形整理候选。前台去重后若不足 240 UTF-8 字节，继续查目标站点其他同类商品的标题及相关 ASIN 的真实反查词，不限于开发文档已有链接；记录候选和排除理由。只吸收与自有产品类型、结构和用途匹配的真实同义词及词形；不同结构的窗板、单独售卖的软管、其他设备等不得借词引流。来源记录使用 `same_category_title_terms`，保存商品 ASIN、标题和站点。
5. 三类候选分别保留来源 ASIN、来源字段和来源站点；候选短语应经过目标 Amazon 站点前 20 个自然结果复核，未完成复核的词只保留在内部候选记录，不得写入交付版 Search Terms 或参考列，也不能声称搜索量或相关性等级已核实。
6. 英文参考标题词和卖家精灵反查词必须先由 AI 翻译、改写成目标站点自然商品称呼及相关同义表达，再查当地自然结果、去重和选词。不能因英文来源或缺少欧洲搜索量直接排除；美国站数据不冒充欧洲搜索量。具体执行 [跨语言搜索词与短字段复核](skills/chenyu-listing/references/search-localization.md)。
7. 删除品牌、ASIN、竞品身份、无关节日词、错误规格和与产品不符的功能词。

### 8.2 Amazon 搜索相关性复核

把候选短语逐个放到对应 Amazon 站点搜索，检查前 20 个自然商品，广告位不计：

- 同款或直接同类占比不低于 70%：高相关，优先采用。
- 占比 40%–69%：中等相关，继续细化为更准确的产品短语再验证，不因剩余字节而直接采用。
- 占比低于 40%：过泛或有歧义，通常删除。
- 结果主要是其他品类、配件或不同用途商品：删除。

不以 Amazon 显示的结果总数量判断相关性，以首页靠前自然结果的产品构成为准。研究记录保存候选短语、来源 ASIN、卖家精灵来源站点、Amazon 验证站点、检查数量、同类数量、相关性等级和采用决定。

### 8.3 最终填写

- 审核时保留完整关键词短语；写入后台时再按词元去重，只保留前台未出现的增量词。
- 全部小写、单行、单空格、无标点。
- 不重复词，不机械并列同一词的单复数和词序变体，不写停用词。
- 不写品牌、ASIN、主观宣传词、临时性表达和无关流量词。
- 控制在 249 个 UTF-8 字节以内；高相关增量词充足时目标 240–249 字节，尽可能接近上限。按 UTF-8 编码计数，交付参考列标注实际字节数。
- 所有已经通过审核、且前台尚未覆盖的有效增量词都应写入；不得因为只取少量候选而让 Search Terms 无故过短。
- 不足 240 字节时，先补查全部参考标题中前台未采用的相关产品称呼、更多目标站点同类标题，以及卖家精灵中尚未采用的高相关反查词。记录实际补查内容、排除理由和仍无法扩充的具体原因后才可留短；240 是扩充目标，不是允许用泛词凑数的最低门槛。
- 完整候选短语须明确指向本品的产品类型、结构或实际用途。单独的节日、礼物、家居、装饰、派对、季节词或普通形容词不能仅凭高流量或自然位比例入选；产品组合短语中的适用词元可以在前台去重后保留，不设跨产品的机械黑名单。
- 新生成或重做的包使用 `search_term_policy_version=3`，采用词同时满足 `high` 与 `product_specific`，保存产品匹配理由。超过上限时按相关性、产品匹配程度及新增检索叫法择优；未容纳的合格候选记录 `decision=exclude`、`exclusion_reason=byte_limit`，不得截断单词。具体字段见分析脚本接口。

## 9. 变体与交付

- 每个子体分别生成 Item Name、Item Highlights、五点、HTML 详情和 Search Terms。
- 能明显影响购买和价格的重要变体差异进入标题前部；普通变体属性放入 Item Highlights。
- 只有确认父子关系及合法变体主题时才生成父体标题。
- Excel 每个站点按“子体标题、Item Highlights、五点 1–5、HTML 详情、Search Terms”的顺序排列。
- 每个目标站点文案旁增加完整“中文翻译”列，再保留逐词组/短句对应的参考来源；中文翻译供中国卖家核对，不属于上传字段，不计入目标站点字符或字节限制。
- 中文翻译必须与目标站点原文逐字段对应，保留数量、尺寸、使用条件和卖点顺序。HTML 详情的中文翻译保留相同的 `<p>`、`<b>`、`<br>` 标签序列、段落和编号顺序，只翻译可见文字，写入 `listing-package.json` 时保留原始标签；导出 Excel 中文列时渲染为分段换行、粗体标题的富文本，不显示标签字符；不得新增原文没有的承诺。Search Terms 中文列只解释词义。
- 中文翻译只翻目标语言的买家文案，不翻事实状态、资料来源、竞品差异、包装核算或审核结论。目标语言和中文翻译必须一起写入 `listing-package.json` 并通过校验后，才可写入最终 Excel。
- 产品内容统一使用“产品名称、产品图片、产品尺寸、产品材料、产品规格、补充信息”六列，与作图交付保持同一风格。
- 产品事实、同款证据和买家可见文案分开保存。
- `Design A/B/C` 等内部列名可留在运营表头或内部参考列，但不得进入 Item Name、Item Highlights、五点、HTML 详情或 Search Terms。

## 10. 交付前检查

- Item Name 最多 75 字符，尽量达到 70–75 字符但没有硬性最低长度；Item Highlights 不超过 125 字符并尽量达到 120–125，且自然包含至少一个标题核心关键词短语或其有效同义词形。
- 标题使用恰好三个真实核心词，数量和重要差异位置正确；材质与尺寸按竞品标题取材，不额外设置主要卖点门槛；单组尺寸只在末尾。
- 五点正好五条，每条正文超过 200 个可见字符并包含 2–4 句。
- 五点与详情全部使用买家可读的产品语言，不含运营解释、信息呈现说明、作图构图语言或笼统道具免责声明；同一字段内无重复句和同义复述。
- 目标语言与中文翻译均不含“已确认/待确认、根据资料、包装记录、参考产品、竞品图、自有套装”等内部核对语言；证据和差异只出现在参考列。
- 详情包含 2–3 句概述、3–5 项详细编号功能、参数和包装，其他块按事实填写。
- 允许前台字段自然重复，不执行机械去重。
- Search Terms 从卖家精灵、全部有效参考标题和必要时补查的同类商品标题建立候选池；只含匹配本品、前台未覆盖的增量词，不超过 249 UTF-8 字节。来源或自然位复核未取得时暂停该站 Search Terms 交付，在对话中说明失败原因；不得把臆测词、资料缺失或“待验证”写入 Excel。
- 所有数字、材质、功能、包装和变体均可追溯到自有证据、已确认同款点位或同材料适用功能来源。
- 母版中的示例文案不是事实来源，也不是已审核文案。导入母版只复用结构和样式；即使同产品再次生成，也必须按本次用户反馈逐句复核目标语言与中文翻译。格式、字符数和脚本通过不代表语义质量通过。
