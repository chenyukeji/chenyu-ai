# 晨玙作图要求

读取 [开发文档读取规范](../../references/kaifawendang.md)，复用已确认产品事实，并遵守 [Listing 与作图要求边界](../../references/deliverable-boundaries.md)。已有 Listing 时只核对产品事实和重要信息优先级，不复制其标题、五点、详情或关键词；没有 Listing 也可独立规划，不强制先写文案。

开始执行会生成文件的任务前，先读取并遵循 [输出目录规范](../../references/output-paths.md)，本 Skill 使用 `image-brief` 交付部分。

同一任务已有 `competitor-research.json` 时读取其中 visual_evidence、原始商品链接和图片 URL，借鉴信息层级、构图类别和卖点呈现方式，不重复联网抓取。用户提供竞品链接但尚无研究包且确实要求参考竞品视觉时，先读取并执行 [竞品研究 Skill](../chenyu-jingpin/SKILL.md)。

## 参考链接图册覆盖

先把开发文档与用户提供的有效商品链接按站点和 ASIN 去重，逐条核对研究包的 `visual_coverage`、`image_summary` 和图册候选。每个链接的当前变体主图、图册以及可读取的 A+ 图都应进入评估范围；开发表嵌入图只是补充，不能替代逐链接看图。一个链接可能提供多张用途不同的参考图，也允许多条链接共同服务同一张成品图；不以链接数、预设参考图张数或 Excel 现有列数限制选择。

若某链接只有部分图片或读取失败，先交由 `chenyu-jingpin` 按其失败处理规则补查并更新同一研究包；仍不可用时记录具体链接及缺口，不假称已看完整图册。最后的作图单只嵌入与任务相关且有独立借鉴价值的图片，不为了覆盖链接而塞入无关图；但每条链接都须经过评估，有适用图片却未选时在内部选择记录中说明原因。

普通竞品图片只作版式参考。若图片中的产品与当前变体在图案、颜色、结构和规格上逐项一致，或用户、采购资料已经确认第一条链接为同款，应记录匹配依据并把它作为同款产品证据。自有资料没有展开的尺寸、结构、材质表现、功能和使用方式，可以采用同款竞品中与当前规格不冲突的信息，不必一律等待自有实测；同时记录 ASIN、图片或字段点位。不得迁移品牌、不同数量/尺寸/配件、竞品独有版本、认证、质保或售后承诺。自有资料与同款证据冲突时以自有资料为准；多个同款来源冲突时只标出具体待核项。

## 与 Listing 隔离

- 作图要求从统一产品事实、自有素材和 `visual_evidence` 独立生成，不以 Listing 成品文案作为画面输入。
- Listing 只能提示哪些事实重要；每张图表现什么、采用什么构图、是否需要场景和使用哪些参考图，必须根据视觉证明任务重新判断。
- 不按五点 1–5 的顺序机械安排图片，不用 Search Terms 决定道具、场景或上图文字，不把 200 字符五点缩写后塞进图片。
- 不复制 Item Name、Item Highlights、五点或 HTML 详情的完整句子。必须上图时重新写 1–3 个英文词或必要数值，只表达当前图片能够直接证明的内容。
- 作图要求可以使用构图、层次、镜头和场景语言，因为这些是给美工的执行指令；这些表达只留在作图单，不反向成为 Listing 卖点。
- 形成结构化 `image-brief-package.json` 后运行 `scripts/validate_image_brief_boundaries.py`。同时生成 Listing 时传入 `--listing-package`，阻断完整句复制、五点/SEO 顺序驱动和过长上图文字；只有检查通过后再写入 Excel。

## 图片规划

先确定每张图要完成的销售任务，再按任务查找最匹配的竞品参考图。不能因为当前素材里有什么就反向决定图序、图片类型或卖点；素材只用于确认产品身份、外观和可执行性。用户没有另行指定图数或顺序时，默认规划七张：

1. 第一张主图：纯白背景、完整展示售卖产品、无文字。
2. 第二张产品近照图：产品细节为清晰主体，默认加入与真实用途一致的使用场景或环境局部，并通过虚化、裁切或明暗层级让场景退居辅助位置；默认无文字。
3. 第三张尺寸图：展示真实测量方向与准确数值；可加入与品类或主题一致的克制边框、角饰、场景边缘或不遮挡尺寸线的细节局部，但中心测量区保持干净；除数值和单位外不加说明性文字。
4. 第四张使用流程图或细节图：产品确有可验证的使用步骤时优先做流程图，否则改为细节图；默认用轻量使用环境、场景边缘或小幅情境窗帮助理解动作和细节，不能削弱步骤/细节主体。步骤优先只用 01/02/03，必须出现动作词时用极短英文，不臆造闭合或安装方式。
5. 第五张产品特点或优势图：只表现已确认且具有区分度的特点，并默认加入少量真实使用场景或环境局部，让买家理解特点在实际使用中的价值；场景不得抢过产品和特点主体。没有可靠或有意义的特点时直接改为完整场景图，不为凑图编造卖点。
6. 第六张场景图：用一个清晰、自然的典型使用场景突出产品。
7. 第七张四宫格场景图：四个有区别的真实使用场景，产品身份和变体图案保持一致；默认无文字。

除第一张白底主图外，第 2–7 张都可以按画面目的融入场景元素。第 2–5 张以“产品/信息为主、场景为辅”，第 6–7 张以场景表达为主但仍要保证产品清楚可辨。辅助场景可表现为淡化背景、环境局部、边框/角饰、桌面或地面关系、人物动作局部或小幅情境窗，不要求每张都做成完整场景大图。场景必须符合产品真实用途和季节主题，不遮挡主体、尺寸箭头或关键细节，不改变产品结构、颜色、图案和比例，也不能让道具看起来像包装内含物。用户明确要求纯净信息图或无场景时，以用户要求为准。

用户明确指定的图数、顺序或图片类型优先于上述默认方案。个别品类确实不适用某个槽位时，保留其销售目的并替换为最接近的可执行图型。

多变体先分别判断“能否共用任务/构图母版”和“能否共用同一张最终成品”。图片任务、信息层级、参考图与验收逻辑一致时，默认按图号合并要求，不按“变体数 × 图片数”机械展开。仅尺寸不同且某图不显示尺寸数值、测量线或可辨认的长短差异，同时结构、颜色、材料、配件和包装相同，才可将该图作为变体共用的同一张成品；尺寸图及任何会呈现变体差异的图仍各出一张。颜色、图案、包装或产品外观不同，即使共用构图，也必须分别出成品。每个任务明确标出最终成品张数与适用变体，并汇总实际总张数；例如两款仅长度不同、七个任务中六图不体现长度而尺寸图各一张时，应规划 6 张共用图＋2 张尺寸图，共 8 张，而不是 14 张。仅在任务目的或执行条件也无法共用时才拆分任务区块。

图片能不使用文字就不使用文字。必须使用文字时，除非用户另有明确要求，图片内文案统一使用精简英文，即使 Listing 使用德语、法语等目标站点语言也不改变；单个标签或短语优先控制在 1–3 个词，尺寸图只保留准确数值和单位。上图文字独立撰写，不截取 Listing 长句，不堆标题关键词，也不使用 Search Terms。

每张任务记录：

- 图号、产品/变体ID、图片类型和画面目的。
- 有事实依据的产品特点及事实来源；不得只引用 Listing 字段或复制 Listing 句子作为依据。
- 构图、场景类型与强度（轻量辅助或完整场景）、人物/道具、产品姿态和不可变化特征；非主图需明确场景如何服务当前画面目的。
- 准确上图文字、语言及位置；无需文字时明确无文字，需文字时默认使用精简英文。
- 可访问的参考商品链接或图片直链、素材角色及可借鉴范围。
- 尺寸、测量部位、单位、画幅及输出规格；默认 1:1、1254×1254 px。
- 禁止元素、逐项验收条件和具体缺失信息。

先锁定默认七张或用户指定的任务清单，再从所有已评估链接的图册中按“主图构图、近照主体、尺寸表达、流程/细节、特点/优势、单场景、四宫格场景”等目的逐张筛选参考。每个任务的参考图数量按实际需要决定：一张已经完整覆盖构图和信息表达时只用一张；多个链接各有可借鉴的主体比例、信息层级、局部细节或场景氛围时就组合使用，不设两张或四张的上限。新增参考图必须提供不同且明确的借鉴价值，不能为了显得丰富而放重复或无关图片，也不能只因“已有足够图片”漏掉更贴切的候选。

选图时先形成逐图映射：成品图号、参考图序号、来源链接/ASIN、原图编号或本地路径、借鉴点，以及仅作版式参考还是已确认同款产品参考。一个 ASIN 可在不同任务中贡献不同图；同一图重复使用须有不同借鉴点。嵌入前检查所选图片确实属于该 ASIN 当前变体，不是推荐商品、无关节日款或同链接的其他变体。

参考例图和竞品 visual_evidence 可借鉴布局与信息表达，不继承其产品规格、商标、配件或卖点，也不要求美工复制竞品图片。区分实际售卖内容与场景道具。缺少自有实拍时，先检查是否存在已核实的同款竞品图；有可靠同款视觉证据即可继续规划。作图要求文字必须逐一写明每张已使用参考图的具体作用，例如“参考图片1用于主体比例”“参考图片2用于尺寸信息层级”；未使用的参考图序号不得出现在文字里。只有缺失信息会导致产品外观或结构被臆造时，才在受影响任务内写明具体缺口，不建立通用“待补素材”区。

尺寸绑定真实测量部位，cm/in 按 2.54 换算。尺寸来源按“自有实测或开发资料 > 已确认同款竞品 > 普通同类竞品”使用：自有资料缺失而同款竞品已明确标出尺寸时，可直接用于尺寸图并注明同款来源，无需写成停工式“制作前必补”；后续若取得自有实测且有差异，再以实测更新。只有未确认同款、测量部位不明或多个同款来源冲突时，才把具体尺寸列为待核项。衔接当前美工流程时英寸保留两位小数，各测量方向单独注明箭头与标签；圆形产品标直径，不强行编出长宽。未给画幅时默认 1:1、1254×1254 px，并标明这是制作规格，不冒充平台通用要求。声称可直接上传前须核实适用站点类目要求。

## 交付给美工

默认交付完整逐图作图表，不能只给泛泛视觉方向。用户提供参考工作簿时优先沿用其有意设计的任务顺序；没有指定模板时，读取并执行 [Excel 交付结构](references/excel-delivery.md)，并以 [晨玙 Amazon 运营交付大母版](../chenyu-yunying/assets/晨玙Amazon运营交付大母版.xlsx) 中的“产品内容”和“作图要求”作为唯一的字段、配色、图片嵌入方式和文字颗粒度示例。只生成作图要求时，任务文件默认仅保留这两张表，四站 Listing 不生成；固定流程要求保留全部页时，四站 Listing 可以为空。每个共用构图母版使用一个清楚的任务区块；多变体在同一区块内写明哪些共用同一成品、哪些各出一张、各自替换内容及验收差异，确实不能共用任务时再拆分。工作簿不新增“审核说明”页；产品实拍只在“产品内容”中嵌入一次，不在“作图要求”重复；竞品参考图直接嵌入“参考图片1…N”列，不使用图片超链接。

母版示例中的七张任务分别使用 1、3、2、3、3、3、4 张参考图，共 19 张参考图；加上“产品内容”中的 1 张自有产品图，整个工作簿共嵌入 20 张图片且没有图片超链接。这组数量只说明如何按任务动态分配，不是所有产品必须照搬的固定配额。

保持美工所需内容清楚：作图要求、嵌入参考图和产品事实。每张参考图在作图要求中注明其借鉴范围，必要时同时说明“同款产品参考”或“版式参考”，避免把竞品外观、件数、尺寸或文案误当成自有产品事实。未找到有价值的参考图时用文字明确构图目标，不放低价值占位图。

交付前先核对所有有效参考链接的图册覆盖及失败记录，再逐图核对事实依据、变体对应、文字、尺寸、嵌入参考图片的清晰度和图号/来源/文字用途映射；统计实际嵌入图数、涉及的来源 ASIN，以及有适用候选却未选的原因。不能用最终图数代替链接覆盖检查；发现研究包漏链接或漏图册时先补研究，再导出作图单。同时检查场景是否服务当前图片任务、是否抢主体、遮挡尺寸信息或造成包装内容误解。另做串线检查：不得复制 Listing 长句，不得照搬五点顺序，不得以 SEO 关键词覆盖率决定图序或上图文字。下游 chenyu-zuotu 可按这些要求执行，但本 Skill 不强制安装美工插件，也不自动出图。
