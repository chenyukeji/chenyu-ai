# A+ 交付结构

## 工作簿

沿用 [运营交付大母版](../../../references/delivery-master.md) 的产品内容页和作图表样式。A+ 是新增独立页，不修改原“作图要求”的七列及规则：

- 只要 A+：`产品内容＋A+要求`。
- 图册作图要求与 A+ 都要：`产品内容＋作图要求＋A+要求`；两种任务编号分别使用图册原编号与 `A+01` 等，不混算图数。
- Listing 同时要求时，默认仍独立交付 Listing 文件，产品内容保持一致；用户明确要求所有成果合并时遵从。
- 多语言 A+ 需要分别交给美工时使用 `FR A+要求`、`DE A+要求` 等页名，仅生成已要求的站点。

复制母版“作图要求”页的 A–G 七列、列宽、表头配色、字体、边框和嵌图方式，新页名为“A+要求”；表头保持 `图片顺序、产品名称、参考图片1、参考图片2、参考图片3、参考图片4、作图要求`。不新增顶部说明行、来源说明页或审核页。清除母版示例文本及示例图片，按独立成品数量增减正文行（默认正文四行、开启品牌时额外一行）；长要求须给足行高，参考图保持比例。

默认每行代表一张独立成品。默认正文按 A+01–A+04 四行；开启品牌时额外增加首行品牌图。网站有模块计划时保留稳定模块 ID 和成品文件名，展示序号变化不改文件名。B 列逐行列出全部适用变体的原始名称，G 列写明“本产品所列变体共用此图，独立成品1张”；不写“每个颜色1张”，不按 B 列名称数量展开。

C–F 仅嵌入实际采用的可选设计参考；没有参考时保持空白，不虚构图片、填占位或要求补链接。本品身份图在产品内容页保留，品牌素材按实际来源附带并在要求中明确。用户指定多槽位或确实需要独立变体图时，逐项明确文件和适用范围，记录例外依据，不隐式扩图。

G 列按需要写清：

1. 图片角色与规格：品牌图/产品主题/核心价值/细节购买信息、准确宽高、目标站点语言和适用变体；公司默认尺寸与已核实后台槽位分开记录。
2. 画面要求：主题、主体角度、位置与主辅占比、背景、操作关系、各槽位内容；有参考时引用嵌图编号说明贡献，无参考时写具体原创构图。
3. 上图文字：逐条准确文案及具体落点；不需要时写“无文字”。
4. 后台文字与 alt text：分别标识字段，给出定稿及中文释义，不把它们误当作图内文字。
5. 手机端处理与产出：指定需要调整的裁切/重排方式、独立成品数量与共用变体；手机预览不增加成品数。

任务级缺口集中在对话及内部包说明。尚未确认的参数不能混入正式美工执行行，依赖该产品事实的画面应替换为有依据的内容或说明具体缺口。上传槽位未核实与产品事实缺失分开记录；默认设计尺寸已定时可直接交给美工制作，但不宣称可直接上传。只交付通用规范时不制作无产品内容的空工作簿。

## 网站自动回填

网站请求模块回填列时，在原 A–G 七列之后追加 `模块类型、标题、副标题、正文、图片文件名`，G 列仍为逐张“作图要求”。每行严格对应计划中的一个图片位置，准确保留模块类型及稳定文件名；左右单图模块只交付标题与正文（正文最多 1000 字符、10 行），副标题留空；横幅模块保持纯图。纯图行允许标题、副标题和正文为空；“作图要求”必须有具体构图、事实依据、所选结构的准确尺寸和文案位置。可另附 `modules` JSON（每项 `template/title/subtitle/body/image_name/brief`），与工作簿一一对应。品牌背景由网站排字时注明无字背景及安全区域，不把品牌名作为待烘焙文案。

## 内部包

`aplus-brief-package.json` 使用独立 `schema_version=1` 和 `deliverable_type=aplus_brief`，不要送入针对图册 默认 7 张或用户指定张数与末张四格规则的 `validate_image_brief_boundaries.py`。

- 顶层保存目标市场/语言、等级及假设、统一事实记录路径、可选竞品研究包路径（没有时为空）、整体风格、品牌依据、`has_brand`、`expected_output_count`、`shared_variants`、默认规则覆盖依据、`status`、`gaps`、`modules`。
- 沿用 `modules[]/assets[]` 兼容现有读取：默认每个 module 只有一个 asset、成品数量为 1；默认正文四项、开启品牌后五项。不确定后台模块时 `module_type` 为未确认，不据画布猜官方类型。默认画布记录 `spec_source=company_default`，尺寸已定与上传适配未核实分开表示。
- `modules[]` 保存 `module_id`、购买问题、独立信息价值、`module_type`、规格来源/核对日期、适用变体、`assets[]`、后台文案及翻译、引用/排除理由。
- `assets[]` 每项保存素材 ID、所属槽位、宽高、站点/全部适用变体、共用标识、构图、参考图片 ID/路径及实际贡献、事实证据、上图文字及落点、alt text、移动端处理与成品数量。未确认规格显式记录，不填猜测值冒充已核实。
- 检查编号唯一、模块与素材一一对应、实际采用的引用存在（空参考合法）、独立成品数量与所选模板和品牌开关一致、没有未知参数进入定稿；判断性检查仍由助手完成，不以 JSON 有字段代表事实或审美通过。

导出后重新打开 Excel 核对表头、换行、行高、全部嵌图锚点及比例；运行运营现有 `validate_product_content_workbook.py` 检查产品内容。不要把上传校验或成品图片验收说成已执行，本 Skill 只完成要求文档。
