# A+ 交付结构

## 工作簿

沿用 [运营交付大母版](../../../references/delivery-master.md) 的产品内容页和作图表样式。A+ 是新增独立页，不修改原“作图要求”的七列及规则：

- 只要 A+：`产品内容＋A+要求`。
- 图册作图要求与 A+ 都要：`产品内容＋作图要求＋A+要求`；两种任务编号分别使用图册原编号与 `A+01` 等，不混算图数。
- Listing 同时要求时，默认仍独立交付 Listing 文件，产品内容保持一致；用户明确要求所有成果合并时遵从。
- 多语言 A+ 需要分别交给美工时使用 `FR A+要求`、`DE A+要求` 等页名，仅生成已要求的站点。

复制母版“作图要求”页的 A–G 七列、列宽、表头配色、字体、边框和嵌图方式，新页名为“A+要求”；表头保持 `图片顺序、产品名称、参考图片1、参考图片2、参考图片3、参考图片4、作图要求`。不新增顶部说明行、来源说明页或审核页。清除母版示例文本及示例图片，按模块数量增减正文行；长要求须给足行高，参考图保持比例。

每行代表一个模块，A 列写 A+ 编号，B 列写开发资料原始变体名称，C–F 嵌入本行实际采用的 A+ 参考图。一个模块有多个槽位时，在 G 列分别写“素材 a/b/c”；不要把三个独立图片槽位只交代为“一张三联图”。共享构图可合并变体要求，外观、语言、参数或图案不同的实际成品分别计数。

G 列按需要写清：

1. 模块与规格：Basic/Premium、模块名、桌面/移动端槽位、各素材宽高、适用站点和变体。
2. 画面要求：主题、主体角度、位置与主辅占比、背景、操作关系、各槽位内容；引用嵌图编号说明借鉴点及最终组合。
3. 上图文字：逐条准确文案及具体落点；不需要时写“无文字”。
4. 后台文字与 alt text：分别标识字段，给出定稿及中文释义，不把它们误当作图内文字。
5. 手机端处理与产出：指定需要调整的裁切/重排方式、各变体和语言需要的素材数量。

任务级缺口集中在对话及内部包说明。尚未确认的参数不能混入正式美工执行行，依赖它的模块应明确属于待定规划；不把有待确认的稿件称为可直接出图或上传。只交付通用规范时不制作无产品内容的空工作簿。

## 内部包

`aplus-brief-package.json` 使用独立 `schema_version=1` 和 `deliverable_type=aplus_brief`，不要送入针对图册 6–8 张与末张四格规则的 `validate_image_brief_boundaries.py`。

- 顶层保存目标市场/语言、等级及假设、统一事实记录路径、竞品研究包路径、整体风格、`status`、`gaps`、`modules`。
- `modules[]` 保存 `module_id`、购买问题、独立信息价值、`module_type`、规格来源/核对日期、适用变体、`assets[]`、后台文案及翻译、引用/排除理由。
- `assets[]` 每项保存素材 ID、所属槽位、宽高、站点/变体、构图、参考图片 ID/路径及实际贡献、事实证据、上图文字及落点、alt text、移动端处理与成品数量。未确认规格显式记录，不填猜测值冒充已核实。
- 检查编号唯一、模块与素材一一对应、引用存在、各素材实际数量合计、没有未知参数进入定稿；判断性检查仍由助手完成，不以 JSON 有字段代表事实或审美通过。

导出后重新打开 Excel 核对表头、换行、行高、全部嵌图锚点及比例；运行运营现有 `validate_product_content_workbook.py` 检查产品内容。不要把上传校验或成品图片验收说成已执行，本 Skill 只完成要求文档。
