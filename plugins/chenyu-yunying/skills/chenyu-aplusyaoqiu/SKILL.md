# 晨玙 A+ 要求

将 A+ 规划成有阅读顺序的产品说明页面。普通图册执行 [作图要求](../chenyu-zuotuyaoqiu/SKILL.md)；本 Skill 不套用图册的 6–8 张、首张主图、末张四宫格、1254×1254 或默认英文规则。两者同时要求时共享事实与研究包，分别规划，再交付同一图片要求工作簿中的独立工作表。

## 输入与证据

读取 [开发文档读取规范](../../references/kaifawendang.md)，按最后一张产品详情表的变体名称、同一行规格及产品身份图确定对象。规格、材质、功能、数量、配件及适用范围以本品资料为准；仅外观相似的竞品不能证明本品属性。用户已确认同款或授权补全事实时，按共享规范保留具体依据，不继承竞品品牌、认证或承诺。

复用现有 `competitor-research.json`；需要采集参考时交给 [竞品研究](../chenyu-jingpin/SKILL.md)。按站点-ASIN 去重并逐链接核对 A+ 图片、可读文字、顺序、模块边界、当前变体和覆盖状态。图册、品牌故事、关联推荐不算 A+ 样本。下载成功不等于已看图；逐图查看实际画面，记录信息、构图、文字落点及缺点。无法从静态页面确认的模块类型标为未知，不仅凭图片比例推断。看不到 A+ 时可继续按自有事实规划，明确参考缺口，不声称已学习这些图片。

用户只要求总结参考规律时，交付样本观察、可迁移建议及不宜照搬之处，不虚构自有产品，不为了生成 Excel 追问开发资料。具体样本、网页和图片保存在任务目录；仅稳定的决策方法进入技能。

## 规划

读取 [A+ 通用设计要求](references/design-guide.md)，先确定页面要解决的购买问题，再选模块及画面。将样本观察、专业建议和平台要求分开。按信息价值安排场景引入、特点证明、操作/适配与用途展开，允许合并、删减和调整顺序；不把参考张数或同店重复模板当作通用配额。

记录目标站点/语言、Basic 或 Premium、后台可用模块及限制。未知等级时以 Basic 静态模块作为规划假设，不假定拥有 Premium 权限。目标语言优先沿用用户指定或已有目标站点；只有参考链接时沿用该站点作为明确的默认假设。多站点仅按任务范围展开，不因运营 Listing 默认四站自动生成四套 A+。中文是运营解释和翻译，买家可见文字按目标站点本地化；明确区分烘焙在图内的文案、后台文字字段和 alt text。

每模块必须说明购买问题、事实依据、与前模块不同的信息、具体画面及所需素材。素材不足时先用已有资料形成可信构图；改为有依据的其他模块，或集中列明阻塞项，不能把“由美工查清规格”当成可执行要求。没有参数、证书、测试或产品组合依据时不添加性能曲线、认证徽章、对比表或虚构套装。

## 交付

生成文件前读取 [输出目录规范](../../references/output-paths.md) 和 [A+ 交付结构](references/delivery.md)。单独 A+ 使用 `aplus-brief`；图册与 A+ 同时交付使用 `image-brief`。内部 `aplus-brief-package.json` 与最终 Excel 一一对应。每个模块写明准确模块名/待确认状态、各图片槽位尺寸、构图、图片实际贡献、准确上图文字、后台文字、中文释义、alt text、变体、成品数和手机端处理；一个模块可能需要多张素材，不能用模块数代替出图数。

逐模块检查事实、图文对应、语言、引用归属、可读性、重复信息和实际导出尺寸。平台规格以当次官方资料或用户后台已确认槽位为准；没有确认时可交付规划稿，但不能标作可直接上传。技能交付要求和文件，不自行生成成品图片、不提交 A+、不修改店铺。
