# 晨玙欧洲站 Listing

先读取 [开发文档读取规范](../../references/kaifawendang.md)。若运营入口已有确认的产品记录，复用并核对本次修改，不重复索要资料。

## 完成条件

竞品链接、网页、图片、关键词表和分析报告都只是中间证据。只完成抓取不得结束任务。正常完成必须为每个目标站点和在售变体交付自有产品标题、五点、HTML 详情描述和 Search Terms，并通过事实与格式复核；只有缺少会导致虚构的关键自有事实时，才列出具体缺口等待确认。

本 Skill 生成自有产品 Listing，不把竞品图片当作自有素材。用户同时需要自己的商品图时，Listing 完成后将同一份自有事实交给 `chenyu-zuotuyaoqiu` 生成作图要求；需要实际出图时再交给已安装的美工能力。

## 生成

1. 确认目标站点（DE/FR/IT/ES/UK）、产品身份和变体。用户明确指定站点时只生成指定站点；只提出综合 Listing 需求而未限定站点时，默认生成 DE、FR、IT、ES 四站，UK 仅在明确要求时加入。不从参考链接国家推断站点。只有开发资料或用户明确确认自有品牌时才使用品牌；否则输出无品牌文案，不询问品牌、不使用品牌占位符。
2. 从自有事实提取特征、适用场景与有依据的购买理由，区分所有变体共用内容和款式差异。竞品措辞只提供表达思路，不能复制其品牌、连续文案、规格和功能。
3. 每个站点/变体先建立关键词分配表：选定 3 个真正的核心关键词和 1 个主要场景放入标题；再把未进入标题的相关次要词分配给五点，把同义词、单复数变体和长尾词分配给 Search Terms 或详情。`title_keywords` 必须全部标记为核心词并自然进入标题，不能用颜色、数量或普通描述词凑足三个名额。已确认售卖数量为 1 时标题不写数量；大于 1 时必须用目标语言把数量短语放在第一个核心关键词正前方，但数量仍不属于核心关键词。单色款可补充该颜色，多色款不得枚举颜色。重复关键词通常不增加信息量，不为覆盖机械复述；没有搜索数据时可提出候选，但不能声称有搜索量、排名或转化验证。
4. 按目标语言自然表达，先说明产品是什么，再突出买家关心的已确认差异。避免堆词、主观最佳、促销承诺和无依据功效。
5. 实际需要判断平台限制或交付可发布稿时，核实适用站点、类目当前官方要求；无法核实时明确该项未验证，不把固定字数当通用规则。

## 开发表与竞品工作流

1. 接收开发表并确认目标站点。综合 Listing 需求未指定站点时采用 DE、FR、IT、ES 默认组合；用户要求单站或其他组合时遵从用户指定，不从竞品链接国家推断。
2. 对 XLSX 运行 `python ../chenyu-yunying/scripts/extract_development_brief.py "开发表.xlsx" --out "任务目录/brief"`，检查 manifest.json 的全部工作表、超链接、图片锚点、附件和 warnings。运营入口已生成 manifest 时直接复用；脚本不执行公式或联网，其他格式使用当前环境的表格能力。
3. 建立自有产品事实及变体记录：名称、材质、尺寸和测量部位、颜色/图案、结构、包装内容，每项保留工作表/单元格或用户确认来源及 confirmed/unconfirmed/conflict 状态。图片归属须实际查看后判断；不让竞品资料填补事实缺口。
4. 读取同一任务的 `competitor-research.json`。若用户提供竞品链接但尚无研究包，先读取并执行 [竞品研究 Skill](../chenyu-jingpin/SKILL.md)，然后复用其结果；本 Skill 不自行抓取网页或图片。
5. 从研究包按目标站点和语言分析竞品原词、同义组、字段覆盖与独立商品组频次。抓取失败和字段缺失保留状态，不用搜索摘要补全。竞品图片只帮助理解信息重点，不写入自有事实。
6. 为每个站点/变体建立“自有事实 → 购买理由 → 关键词 → Listing 字段”映射。明确记录标题的 3 个核心词、主要场景、售卖数量及数量短语，以及标题未采用的次要词和长尾词应进入哪个字段。将全部有效竞品链接的标题和五点按包装/规格、材质结构、功能效果、搭配方式、场景人群、使用注意等主题合并去重，形成五条信息密度高且可回溯自有事实的购买理由；每条先绑定事实锚点，再规划作用或呈现效果、买家价值、使用方式或适用边界，避免只写抽象形容词。竞品高频但自有产品不具备的内容排除。不主动新增评论痛点分析；研究包已有或用户提供的评论最多用于调整信息重点，不能证明自有产品解决问题或优于竞品。
7. 读取 [写作与审核](references/writing-and-review.md) 及 [欧洲站本地化](references/europe-localization.md)，严格按统一字段顺序和格式直接用目标语言生成父体/子体标题、五点、HTML 详情描述和 Search Terms。多站点任务先形成稳定的英文语义提纲；UK 在目标站点内时据此生成英国站文案，其他站点按段落/信息块重写，不整段逐句翻译，并分别参考本地竞品词汇和榜单样本。无已核实父子体关系时不伪造父体标题。
8. 按 [分析脚本接口](references/analysis-contract.md) 形成 listing-package.json，运行 `validate_listing_package.py` 检查站点/变体覆盖和自有事实引用，再运行 `analyze_listing.py` 复核词频、长度、覆盖及重复片段。
9. 模型核对语言、语义、数字、单位、事实、变体和竞品身份泄漏；针对错误局部修正文案并重复校验，不因抓取或初稿完成而停止。
10. 仅在最终包 ready_for_delivery 且语义审核通过后交付自己的产品 Listing；规则限制未核实时单独披露，不冒充已验证或已发布。

## 交付

严格按以下顺序交付，缺少的非买家字段也要注明原因，不能静默省略：

1. 产品信息核对：采用的已确认事实、来源及待确认项。
2. 高频关键词汇总：关键词、独立竞品商品组数、类型、建议位置；没有可靠样本时明确“无频次结论”。
3. 父体标题：仅在父子体关系及变体主题已核实时提供。
4. 子体标题：每个在售颜色、尺寸或款式分别提供。
5. 五点卖点：严格五条，并遵守统一模板和内容顺序。
6. 详情描述：使用基础 HTML，包含总结导语、五点未充分展开的补充功能、产品参数、包装内容，以及有事实依据时的使用方法或注意事项。
7. 核心关键词：10—20 个适合前台自然使用的词；不足时按真实数量交付，不凑数。
8. 长尾关键词：10—15 个相关词组；不足时按真实数量交付，不制造无关词。
9. 后台 Search Terms：一行可复制内容。
10. 关键词分配与标题结构检查：3 个核心关键词、核心词证据、主要场景、标题数量规则、颜色模式、可选品牌，以及次要词/长尾词在五点、详情和 Search Terms 的分配。五点优先使用标题未覆盖的相关词，但不为“每点一个词”牺牲自然表达。

买家可见文案必须使用目标语言；产品核对、证据和待确认项使用中文。用户及适用类目要求优先于默认格式，任何覆盖都要在审核摘要说明依据。

变体不自动等于合法父子体关系；需要提供父子体建议时核实类目支持的变体主题。未证实的卖点不填入正式文案。必要规格缺失时明确具体缺口；缺少品牌不构成缺口。

默认在对话中交付完整内容；用户要求 Excel 时生成独立副本并按可用表格能力核验，不覆盖开发原文件。目标语言文案与必要的中文事实说明分开，但不默认新增“审核说明”工作表；重要未确认项放在受影响字段旁或最终摘要中。只做文案交付，不登录或发布商品。

交付前核对：每项客观宣称有来源、各变体无混用、单位换算正确、内部采购信息未泄露、没有竞品身份信息被误用。

先按站点交付可复制文案，再集中附中文审核摘要：待确认事实、竞品来源及读取状态、关键词依据。任务文件保存在输出目录，不进入插件包。此流程由助手执行，不宣称具备后台服务或跨会话记忆。
