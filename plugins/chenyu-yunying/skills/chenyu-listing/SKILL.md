# 晨玙欧洲站 Listing

先读取 [开发文档读取规范](../../references/kaifawendang.md)。需要生成文件时再读取 [输出目录规范](../../references/output-paths.md)，本 Skill 使用 `listing` 交付部分。

开始写作前读取插件根目录的 [Listing 规则](../../LISTING_RULES.md)。输入为开发 Excel、已确认产品事实、竞品文字与关键词证据及目标站点要求；并按需读取：

- [写作与审核](references/writing-and-review.md)：生成或修改任何 Listing 时读取。
- [产品表达方法](references/product-expression.md)：参考优秀商品组织具体卖点、操作说明或装饰效果时读取。
- [欧洲站本地化](references/europe-localization.md)：涉及 DE/FR/IT/ES/UK 任一站点时读取。
- [分析脚本接口](references/analysis-contract.md)：形成、校验或分析 `listing-package.json` 时读取。

## 内容来源与事实核对

以参考商品链接的适用内容形成 Listing 主体，自有事实作补充和差异校正。`title_phrase_sources`、`item_highlights_phrase_sources`、`clause_sources` 记录实际取材来源；`field_fact_ids` 负责核对本品适用性。不能把事实核对编号当作文案来源批量覆盖整句，也不能为提高参考占比挂不相干的 ASIN 或原文。

先整理参考商品的核心卖点、结构细节、用法和适用场景，再重组标题、五点和详情。每条只挂一个参考句、其余均用自有事实扩写，不算充分整合；应回到全部参考补足实际采用内容。无需设置机械来源比例，参考缺少可用信息时保留真实缺口，不虚构来源。

## 完成条件

竞品链接、关键词和分析结果只是中间证据。正常完成必须为每个目标站点和在售子体交付 Item Name、Item Highlights、五点、HTML 详情和 Search Terms，并通过事实、格式、长度、变体和语言复核。若竞品标题或五点未读到，先补取；仍无法取得时暂停依赖该字段的文案，不以其他字段冒充来源。

本 Skill 不抓取竞品网页。没有 `competitor-research.json` 时，先执行 [竞品研究 Skill](../chenyu-jingpin/SKILL.md)。不登录或发布 Amazon 商品。

## 工作流

1. 确认目标站点、产品身份、售卖数量和变体。用户未限定站点时默认 DE、FR、IT、ES；UK 仅按需加入。只有开发资料或用户确认的自有品牌才能使用品牌。
2. 解析开发 Excel，以最后一张产品详情表的变体名称和产品主图/实拍图确定产品，同一变体行提供规格；前面确认页或供应商款式名称不同不影响此选择。先建立当前变体的完整产品属性：名称、材质、尺寸及测量部位、颜色/图案、结构、包装内容、兼容系列/型号/替换件号。开发资料未填写属性且用户明确允许参考第一条链接时，读取该链接当前匹配款式的具体属性，把与自有图片、已有规格和售卖数量不冲突的值补入产品属性，再据此生成产品内容页和 Listing；不必等人工逐项确认，后续可人工微调。只采用实际读到且适用于当前变体的值，不迁移其他款式、品牌、认证或售后承诺。来源、用户授权与属性状态保留在内部事实记录；产品内容页直接写属性值，不写“参考 XX”或“待确认”。滤芯、耗材、配件、转接件等依赖适配关系的产品仍须先确认兼容标识，不能只凭竞品链接或尺寸推定。
3. 参考商品链接是 Listing 卖点、使用说明和详情展开的主要内容来源，第一条提供主要定位与叙述方向。先通读全部有效链接的标题、五点及详情，按共同重点和互补信息形成内容提纲，再用自己的语言自然重写；不能先围绕自有事实反复扩写，再给每条补挂一个参考点。自有资料负责补充本品独有信息、替换不同规格和核对适用性，不决定默认篇幅或五点顺序。一致的内容保留真实参考来源，尺寸、颜色、数量等差异只在相关位置校正；所有商品宣称仍须适用于本品。每条五点至少使用一个实际读到的竞品五点内容；标题和图册不能冒充原始五点。未取得所需内容先补研究，仍缺失时只暂停依赖它的交付。新包设置 `source_mapping_version=2`；标题、Highlights 逐有含义词组溯源，五点和详情逐最小有意义短句建立 `clause_sources`，来源精确到 ASIN、标题/第 N 点/详情及实际原文；自有差异用事实编号。一个短句融合多个来源时分别列明，不能只给整条五点一个笼统来源。映射同步写入原参考列，具体结构见分析脚本接口。
4. 通读用户给出的全部有效竞品标题和五点，识别产品名称、同义称呼和“图案/主题＋产品名称”等搜索短语并保留 ASIN/站点，按产品相关性和目标站点真实搜索需求选择恰好三个核心短语，不按产品、主题、场景各分配一个名额。对 Item Name 与 Item Highlights 中每个有购买含义的词组分别建立 `title_phrase_sources`、`item_highlights_phrase_sources`：写目标文案短语、竞品 ASIN、标题或第 N 点、原文短语；纯自有规格则写已确认事实编号。对应参考列逐词组显示“采用的词 ← ASIN 标题/第N点”或自有事实，不能只罗列 ASIN 或笼统写“参考标题与图册”。竞品词义须适用于自有产品；不得迁移品牌、冲突图案/材质/规格，或为接近 75 字符添加无来源形容词。Item Highlights 承接标题放不下的核心/长尾词、规格、结构和场景；标题已写明的整包数量不在 Highlights 重新起句复述，把空间留给新信息。五点与详情自然覆盖关键词，不机械去重。适配型产品把主要兼容系列或替换件号放进 Item Name，并在 Item Highlights 覆盖完整已确认清单。
5. Search Terms 最后生成。先使用运营任务注入的卖家精灵账号，并用带 Playwright 的 Python 运行本 Skill 目录下的 `scripts/collect_sellersprite_keywords.py --request US:B012345678 --out internal/sellersprite-keywords.json`（按竞品实际站点和 ASIN 改参数，可重复 `--request`），读取真实反查结果；服务器当前可用 `/home/ubuntu/chenyu/chenyu-crawler/.venv/bin/python`。不得因为运营任务缺少账号而跳过：先检查任务环境与管理员已配置的凭据注入状态。再逐一读取全部有效参考链接的标题；先按产品名称、当地同义称呼、结构/用途相关叫法和常见词形整理候选池，逐项标明来源与排除理由；若去重后只剩少量有效增量词，继续查目标站点其他匹配的同类商品标题和更多相关 ASIN 的真实反查结果，不限于已有链接，不在只得到一两个词时直接收尾。记录每个词的 ASIN、标题及站点，排除不同产品结构、错误规格和无关词。按 [写作与审核](references/writing-and-review.md) 复核自然搜索结果，最终使用全部已采用且前台未覆盖的有效增量词；有足够证据时尽量覆盖不同的真实检索叫法并利用可用字节，不为填满字节加入泛词。少于三个不同增量词时，先完成补查并在内部记录候选、排除理由与确实无法扩充的原因。美国站数据只作欧洲站语义候选，不声称当地搜索量。反查或自然搜索因页面或网络问题失败时，可重试查询并补查同站点竞品；登录失败按下述共享会话规则停止，不重复提交账号密码；仍未获得真实证据时暂停该站 Search Terms 交付，在对话中说明具体失败原因，不在 Excel 写臆测词或“待验证”。
6. 综合全部有效竞品五点及普通/A+描述，将共同重点、互补细节与本品差异组织成 3–5 项详情功能；第一条提供主要定位和风格，顺序按本品信息安排。详情的概述与功能说明以适用参考内容展开，参数和本品独有差异用自有事实补充；逐最小有意义短句记录实际来源，并另行绑定本品事实；独立改写成自然本地化文案，不以空话扩写。
7. 为每个站点/子体生成：最多 75 字符、尽量接近 75 但无硬性最低长度的 Item Name、不超过 125 字符 Item Highlights（目标 120–125）、严格五条且每条正文超过 200 字符的五点、规定结构的 HTML 详情，以及不超过 249 UTF-8 字节的 Search Terms。五点综合各链接的适用内容，相关共同重点优先，融入互补细节与本品差异；开发资料的包装重量、包装尺寸、差异核对、缺失配件和证据状态只留在事实或参考记录，不能占用卖点。
8. 写完五点和详情后逐句执行买家视角检查：每句必须新增产品事实、实际使用动作、适用条件、尺寸边界或购买相关结果；删除运营解释、信息呈现说明、证据状态、资料来源、竞品差异、抽象总结、同义复述、拍摄与排版用语和默认道具免责声明。
9. 为每个目标站点字段生成完整中文翻译，供中国卖家核对。翻译只翻目标语言中的买家文案，不翻事实表、核对过程或参考列；不得出现“已确认、待确认、根据资料、包装记录、同款竞品、竞品图、自有套装”等内部表达，也不得新增原文没有的事实、承诺或使用范围。HTML 详情的中文翻译保留与目标站点原文对应的 `<p>`、`<b>`、`<br>` 标签、段落和编号顺序，翻译标签内的文字，不把 HTML 详情压平成纯文本；目标站点原文修改后同步更新中文列。
10. 为 Item Name、Item Highlights、每条五点、详情和 Search Terms 写简短来源；在 `field_fact_ids` 中分别为 `title`、`item_highlights`、`bullet_1` 至 `bullet_5`、`description` 绑定本字段实际使用的已确认事实编号。功能可以绑定自有事实、已确认同款或同材料适用功能证据；无法建立适用关系的材质、周期、性能、认证或兼容宣称先核实，不能以“参考链接这样写”为由直接发布。将目标语言和中文翻译一并写入 `listing-package.json`，运行 `validate_listing_package.py` 和 `analyze_listing.py`，再进行语言、数字、单位、事实、变体及同款证据语义复核。只有 `ready_for_delivery=true` 且语义审核通过后才能交付。

卖家精灵统一使用脚本中的共享浏览器：同一账号的选品和运营任务连接同一个浏览器、共享默认上下文，每个任务只开关自己的窗口。最后一个使用者结束后自动关闭浏览器并清理临时页面，保留登录状态和成果；有其他任务或未知页面时不强行关闭。不得另建浏览器、无痕上下文或临时登录脚本；自定义采集也须使用 `sellersprite_session.launch_context` 和 `ensure_login`。会话目录由 `CHENYU_BROWSER_DATA_DIR` 指定，未配置时使用用户级固定目录，与任务工作目录无关。需要检查时运行 `scripts/sellersprite_session.py status`（不提交密码），初始化登录用 `login`。锁定、密码错误或安全验证会跨任务停止自动登录；确认主账号解锁、凭据修正或人工验证完成后，才运行 `recover` 单次恢复。网络或不明失败冷却 5 分钟；不得通过换目录、删状态或另写脚本规避保护。

## 写作关键约束

- Item Name 最多 75 字符，优先容纳有搜索依据的产品名称、同义称呼及图案/主题组合短语，不为凑长度加入尺寸、材质或空泛形容词；恰好三个核心关键词短语自然成句。数量大于 1 时本地化数量短语紧贴第一个核心产品词；关键结构与功能按购买重要度前置。材质仅在它本身是已证实的主要购买理由时进入标题；尺寸仅在直接影响适配、覆盖或变体选择时保留一组，并放在标题末尾。场景词不作为默认核心词，仅在目标站点搜索证据支持且意图匹配本品时采用，不用 `/` 堆场景。竞品标题频次不等于搜索量，无数据时不标称高搜索量。
- Item Highlights 必填且最多 125 字符，尽量写到 120–125；自然包含标题三个核心关键词短语中的至少一个（或目标站点认可的同义词形），再补标题放不下的真实规格、图案/结构和场景；标题已有的整包数量不在 Highlights 以“8只装/8 sacs/lot de 8”等写法重复，不用同义重复或空话凑满。
- 滤芯、集尘袋、软管、适配器等适配型产品设置 `compatibility_required=true`，用 `primary_compatibility_term` 保存标题中的主要系列/件号，用 `compatibility_terms` 保存必须在 Item Name＋Item Highlights 中覆盖的完整已确认标识。尺寸只能辅助核对，不能替代具体兼容系列、型号或 OEM/替换件号；目标语言与中文翻译必须保留相同标识。
- 兼容性可由用户当前明确说明、自有包装/说明书、供应商确认或已确认同款证据支持。普通未确认竞品的标题只能提供候选标识；若适配信息仍未确认，应暂停该项宣称，不能用“购买前核对尺寸”掩盖核心信息缺失。
- 适配型产品的第一条五点必须直接回答“具体兼容什么”，HTML 详情也必须完整列出全部已确认兼容系列、型号和替换件号；中文翻译保持相同标识。尺寸、更换提醒和使用注意只能在适配信息之后补充，不能占用第一卖点。
- 五点使用“相关 Emoji＋【本地语言利益点标题】＋2–4 句正文”；只计正文时每条必须超过 200 个可见字符。
- 五点以全部适用参考的核心内容和共同重点确定权重，第一条提供主要定位，允许跨来源合并、补充及重排；一条可引用多个来源，不强制对应首链接第几条。每条必须以读到的竞品原始五点为内容参照，在参考列逐项写清 ASIN、第几点和实际采用的主题；自有事实负责核实可用性。一条若只能引用标题、图册或开发文档，不能作为已完成的竞品五点整合交付。
- 五点和详情只写买家能直接使用的产品信息，不写“便于买家区分包装与道具”“让顾客清楚了解”“保持统一识别度”“与图片/标题一致”等卖家或运营解释。超过 200 字符只能靠真实细节、动作、条件和结果补足。
- “已确认的套装内容”“根据资料/包装记录”“参考产品”“竞品图中”“自有套装不包含”等属于内部核对痕迹，目标语言和中文翻译一律禁止。买家标题直接写具体利益点，例如“手缝修补基础工具”或“多尺寸穿线针”，不要把证据状态写成卖点。
- 包装重量和外包装尺寸仅用于物流或开发核算；除非该包装本身是买家选择商品所需的明确规格，否则不得写进五点或详情，更不得解释“这些不是单件工具尺寸”。
- 不强制给每个特点附加利益句。“4个分4份”“无需另外挑选”“不受固定姿势限制”“换位置后仍可塑形”等数量常识或功能复述不能补字数。删除后不损失具体产品信息的句子必须删掉；母版和旧稿的示例也必须重新执行此检查。
- 买家文案只写产品事实和真实使用方法。可以写产品适合放在桌面、书架或树旁以及如何调整，但不得写“画面更丰富、增加层次、前后错落、不同高度、视觉焦点、动态感、避免呆板、近景/远景、构图、镜头、留白”等美工表达；中文翻译同样不得出现。
- 从竞品图片只提取可证实的产品结构和真实使用位置，不把竞品构图、拍摄角度、道具组合或画面效果改写成产品卖点。
- 同一条五点、同一个详情功能块内不得重复相同或近义句；五条之间不得机械复用完整句子。不同前台字段仍可自然重复关键事实，但要增加相应深度。
- 详情按共同重点与互补价值集成全部有效竞品五点及普通/A+描述中适用于本品的具体信息，用自有句式展开，不复制竞品原句；使用 `<p>`、`<br>`、`<b>`，依次包含 2–3 句概述、3–5 项详细编号功能、参数、可选使用/保养、包装和可选注意事项。
- 包装内容默认只列实际包含物及数量，不自动添加“图片中的其他装饰/道具不包含”。确有具体配件误认风险且证据明确时，才在注意事项中点名说明。
- 关键差异、重要尺寸、核心关键词和主要场景可在前台字段自然重复。标题负责识别，Item Highlights 负责补足，五点负责解释，详情负责完整展开。
- Search Terms 必须全部小写、单行、单空格、无标点、无品牌和 ASIN；删除 Item Name、Item Highlights、五点、详情及其他已填属性已经覆盖的词。
- 如果 Search Terms 仅有一两个词或明显偏短，继续回查全部参考标题、目标站点更多同类标题及相关 ASIN 的真实反查词，核对不同产品叫法和结构词；完成候选与前台去重审计后才能决定留短，不能因为第一个链接或卖家精灵未返回更多词就停止扩词。未完成卖家精灵或自然搜索复核时，不把候选词交付为已完成 Search Terms；研究状态只写在内部记录及对话中，不写入 Excel 参考列。
- `Design A/B/C`、`Diseño A`、`Variante A` 等内部变体编号不得进入任何买家可见字段；只有用户确认的公开变体名称可写入 `buyer_visible_variant_terms` 后保留。内部编号只能出现在运营表头或参考列。

## 交付

默认在对话中按以下顺序提供可复制内容：

1. 产品信息核对与来源
2. 父体标题，仅在关系与变体主题已核实时提供
3. 子体 Item Name
4. Item Highlights
5. 五点 1–5
6. HTML 详情
7. Search Terms

用户要求 Excel 时生成独立副本，不覆盖开发原文件，并读取 [运营交付大母版](../../references/delivery-master.md)。默认仅建立“产品内容”和用户要求的各目标站点 Listing 工作表；同站点多变体并列。每个变体按“目标站点文案、中文翻译、参考”三列成组，Item Name、Item Highlights、五点1–5、HTML 详情和 Search Terms 均提供完整中文翻译。中文翻译必须先写入 `listing-package.json` 并与目标文案一起通过校验，再写入 Excel；HTML 详情中文列使用 `scripts/render_chinese_description.py` 将已校验的中文 HTML 渲染为带段落换行和粗体标题的 Excel 富文本，不在单元格显示标签；字符和字节限制只检查目标站点文案，不计算中文翻译。产品内容页统一使用“产品名称、产品图片、产品尺寸、产品材料、产品规格、补充信息”六列；先逐项核对可用产品属性是否已填入相应列，再撰写买家文案。每个变体必须实际嵌图，依次选择自有主图（含开发 Excel 嵌图）、对应规格供应商图、任一有效链接中已确认同款且匹配当前规格的主图，并记录匹配依据。图片来源留在内部记录，产品内容页不写待核对、资料缺失或来源免责声明，也不默认增加关键词、审核说明或内部分析工作表。Listing 各字段原有的“参考”列继续记录标题词组与竞品五点来源，供文案审核；产品内容页只呈现产品属性。导出后运行 `plugins/chenyu-yunying/skills/chenyu-yunying/scripts/validate_product_content_workbook.py` 检查实际嵌图与内部备注。

交付前核对每项客观宣称均可追溯、变体不混用、单位正确、内部采购信息未泄漏，且买家文案不包含竞品身份、内部审核语言、面向卖家的解释、拍摄与排版用语、重复句或默认道具免责声明。
