# 晨玙欧洲站 Listing

先读取 [开发文档读取规范](../../references/kaifawendang.md)。需要生成文件时再读取 [输出目录规范](../../references/output-paths.md)，本 Skill 使用 `listing` 交付部分。

开始写作前必须读取插件根目录的 [Listing 规则](../../LISTING_RULES.md) 和 [Listing 与作图要求边界](../../references/deliverable-boundaries.md)，并按需读取：

- [写作与审核](references/writing-and-review.md)：生成或修改任何 Listing 时读取。
- [欧洲站本地化](references/europe-localization.md)：涉及 DE/FR/IT/ES/UK 任一站点时读取。
- [分析脚本接口](references/analysis-contract.md)：形成、校验或分析 `listing-package.json` 时读取。

## 完成条件

竞品链接、关键词和分析结果只是中间证据。正常完成必须为每个目标站点和在售子体交付 Item Name、Item Highlights、五点、HTML 详情和 Search Terms，并通过事实、格式、长度、变体和语言复核。只有缺少会导致错误产品身份、规格、件数或变体混用的关键事实时才暂停。

本 Skill 不抓取竞品网页。没有 `competitor-research.json` 时，先执行 [竞品研究 Skill](../chenyu-jingpin/SKILL.md)。不登录或发布 Amazon 商品。

## 工作流

1. 确认目标站点、产品身份、售卖数量和变体。用户未限定站点时默认 DE、FR、IT、ES；UK 仅按需加入。只有开发资料或用户确认的自有品牌才能使用品牌。
2. 解析开发 Excel，建立名称、材质、尺寸及测量部位、颜色/图案、结构、包装内容、兼容系列/型号/替换件号和变体记录，每项保留来源及 `confirmed/unconfirmed/conflict` 状态。滤芯、耗材、配件、转接件等依赖适配关系的产品必须先确认兼容标识，不能只凭尺寸写作。
3. 若用户、采购资料或产品证据确认第一条竞品链接为同款，把该 ASIN 设为主要同款参考。必须取得该链接的标题和完整五点，按原顺序建立 `primary_reference_bullet_outline`，逐点记录概括主题的 `source_topic`、保留原点具体信息的 `source_details`，以及可支撑改写的已确认 `own_fact_ids`；只写“兼容性、品质、易安装”等宽泛主题而不记录型号、材料、动作、使用结果等具体内容不合格。每条自有五点都引用该 ASIN 对应点位。自有五点的主题、顺序、主要内容和“特点—使用—结果”展开方式应与第一条链接相近，再替换为自有产品的真实规格与表达；不得复制品牌、原句、冲突规格/数量/配件、认证、质保、售后和竞品独有版本。用户要求按首链接写作而首链接五点尚未取得时，继续检索或明确暂停，不能自行另拟五点结构。未确认同款时，竞品只提供关键词与表达思路。
4. 通读用户给出的全部有效竞品标题，逐条拆解产品词、图案/主题、用途/场景及尺寸并保留 ASIN/站点，比较重合与互补信息后按自有事实合并为恰好三个核心词，用目标语言和自己的句式写 Item Name。标题描述词必须有竞品标题中的语义对应且适用于自有产品，不能为接近 75 字符新增竞品标题没有的氛围、效果或用途；竞品品牌、不同图案/材质/规格不得迁移；Item Highlights 承接标题放不下的核心/长尾词、规格、结构和场景；五点与详情自然覆盖关键词，不对前台字段执行机械去重。适配型产品把一个主要兼容系列或替换件号放进 Item Name，并在 Item Highlights 覆盖完整的已确认兼容清单；同一系列的拼写变体可进入 Search Terms。
5. Search Terms 最后生成。先使用运营任务注入的卖家精灵账号，并用带 Playwright 的 Python 运行本 Skill 目录下的 `scripts/collect_sellersprite_keywords.py --request US:B012345678 --out internal/sellersprite-keywords.json`（按竞品实际站点和 ASIN 改参数，可重复 `--request`），读取真实反查结果；服务器当前可用 `/home/ubuntu/chenyu/chenyu-crawler/.venv/bin/python`。不得因为运营任务缺少账号而跳过：先检查任务环境与管理员已配置的凭据注入状态。再逐一读取全部有效参考链接的标题；前台去重后候选仍少时，继续查目标站点其他匹配的同类商品标题，不限于已有链接。记录每个词的 ASIN、标题及站点，排除不同产品结构、错误规格和无关词。按 [写作与审核](references/writing-and-review.md) 复核自然搜索结果，最终使用全部已采用且前台未覆盖的有效增量词；不为填满字节加入泛词。美国站数据只作欧洲站语义候选，不声称当地搜索量。反查或自然搜索因登录、页面或网络问题失败时，先重试并补查同站点竞品；仍未获得真实证据时暂停该站 Search Terms 交付，在对话中说明具体失败原因，不在 Excel 写臆测词或“待验证”。
6. 写 HTML 详情前，逐点对照第一条已确认同款链接的五点，以及其普通/A+描述；其他竞品五点提供补充表达与信息线索；没有已确认同款时，仍应通读全部有效竞品五点，只用自有已确认事实写详情。把适用于本品的具体结构、用法、场景、规格和结果整合为自己的 3–5 项功能描述；首条同款五点 1–5 各点都要在详情找到可核对的内容，同类内容可合并，不照抄原句或引入未经证实的功能。在 `primary_reference_bullet_outline` 每项记录详情对应短句 `description_excerpt`，并以 `field_fact_ids.description` 绑定所用的自有事实。
7. 为每个站点/子体生成：最多 75 字符、尽量接近 75 但无硬性最低长度的 Item Name、不超过 125 字符 Item Highlights（目标 120–125）、严格五条且每条正文超过 200 字符的五点、规定结构的 HTML 详情，以及不超过 249 UTF-8 字节的 Search Terms。第一条同款链接存在且内容有效时，五点沿用其买家卖点主题、具体内容和顺序；开发资料的包装重量、包装尺寸、差异核对、缺失配件和证据状态只留在事实或参考记录，不能占用卖点。
8. 写完五点和详情后逐句执行买家视角检查：每句必须新增产品事实、实际使用动作、适用条件、尺寸边界或购买相关结果；删除运营解释、信息呈现说明、证据状态、资料来源、竞品差异、抽象总结、同义复述、作图构图语言和默认道具免责声明。
9. 为每个目标站点字段生成完整中文翻译，供中国卖家核对。翻译只翻目标语言中的买家文案，不翻事实表、核对过程或参考列；不得出现“已确认、待确认、根据资料、包装记录、同款竞品、竞品图、自有套装”等内部表达，也不得新增原文没有的事实、承诺或使用范围。目标站点原文修改后同步更新中文列。
10. 为 Item Name、Item Highlights、每条五点、详情和 Search Terms 写简短来源；在 `field_fact_ids` 中分别为 `title`、`item_highlights`、`bullet_1` 至 `bullet_5`、`description` 绑定本字段实际使用的已确认事实编号。任何无法绑定到已确认事实的材质、功能、周期、性能、认证或兼容宣称必须删掉或先向用户核实，不能以“参考链接这样写”为由直接发布。将目标语言和中文翻译一并写入 `listing-package.json`，运行 `validate_listing_package.py` 和 `analyze_listing.py`，再进行语言、数字、单位、事实、变体及同款证据语义复核。只有 `ready_for_delivery=true` 且语义审核通过后才能交付。

## 写作关键约束

- Item Name 最多 75 字符，优先用真实的主题、图案或场景词接近 75 字符，不为凑长度加入尺寸、材质或空泛形容词；恰好三个核心关键词短语自然成句。数量大于 1 时本地化数量短语紧贴第一个核心产品词；关键结构与功能按购买重要度前置。材质仅在它本身是已证实的主要购买理由时进入标题；尺寸仅在直接影响适配、覆盖或变体选择时保留一组，并放在标题末尾。主要场景可选，不用 `/` 堆场景。
- Item Highlights 必填且最多 125 字符，尽量写到 120–125；自然包含标题三个核心关键词短语中的至少一个（或目标站点认可的同义词形），再补标题放不下的真实规格、图案/结构和场景，不用同义重复或空话凑满。
- 滤芯、集尘袋、软管、适配器等适配型产品设置 `compatibility_required=true`，用 `primary_compatibility_term` 保存标题中的主要系列/件号，用 `compatibility_terms` 保存必须在 Item Name＋Item Highlights 中覆盖的完整已确认标识。尺寸只能辅助核对，不能替代具体兼容系列、型号或 OEM/替换件号；目标语言与中文翻译必须保留相同标识。
- 兼容性可由用户当前明确说明、自有包装/说明书、供应商确认或已确认同款证据支持。普通未确认竞品的标题只能提供候选标识；若适配信息仍未确认，应暂停该项宣称，不能用“购买前核对尺寸”掩盖核心信息缺失。
- 适配型产品的第一条五点必须直接回答“具体兼容什么”，HTML 详情也必须完整列出全部已确认兼容系列、型号和替换件号；中文翻译保持相同标识。尺寸、更换提醒和使用注意只能在适配信息之后补充，不能占用第一卖点。
- 五点使用“相关 Emoji＋【本地语言利益点标题】＋2–4 句正文”；只计正文时每条必须超过 200 个可见字符。
- 使用第一条同款链接时，五条分别对应其五点 1–5：主题不重排，具体内容要素也不能只剩宽泛概括；不把一个主题拆成多点，也不拿尺寸、注意事项或内部核对替换原链接的独立卖点。相似写作不等于照抄；品牌和自有产品不具备的细节必须删除或换成同主题下已确认的事实。
- 五点和详情只写买家能直接使用的产品信息，不写“便于买家区分包装与道具”“让顾客清楚了解”“保持统一识别度”“与图片/标题一致”等卖家或运营解释。超过 200 字符只能靠真实细节、动作、条件和结果补足。
- “已确认的套装内容”“根据资料/包装记录”“参考产品”“竞品图中”“自有套装不包含”等属于内部核对痕迹，目标语言和中文翻译一律禁止。买家标题直接写具体利益点，例如“手缝修补基础工具”或“多尺寸穿线针”，不要把证据状态写成卖点。
- 包装重量和外包装尺寸仅用于物流或开发核算；除非该包装本身是买家选择商品所需的明确规格，否则不得写进五点或详情，更不得解释“这些不是单件工具尺寸”。
- 不强制给每个特点附加利益句。“4个分4份”“无需另外挑选”“不受固定姿势限制”“换位置后仍可塑形”等数量常识或功能复述不能补字数。删除后不损失具体产品信息的句子必须删掉；母版和旧稿的示例也必须重新执行此检查。
- Listing 与作图要求严格隔离。可以写产品适合放在桌面、书架或树旁以及如何调整，但不得写“画面更丰富、增加层次、前后错落、不同高度、视觉焦点、动态感、避免呆板、近景/远景、构图、镜头、留白”等美工表达；中文翻译同样不得出现。
- 从竞品图片只提取可证实的产品结构和真实使用位置，不把竞品构图、拍摄角度、道具组合或画面效果改写成产品卖点。
- 同一条五点、同一个详情功能块内不得重复相同或近义句；五条之间不得机械复用完整句子。不同前台字段仍可自然重复关键事实，但要增加相应深度。
- 详情结合首条同款竞品五点及普通/A+描述中适用于本品的具体信息，用自有句式展开，不复制竞品原句；使用 `<p>`、`<br>`、`<b>`，依次包含 2–3 句概述、3–5 项详细编号功能、参数、可选使用/保养、包装和可选注意事项。
- 包装内容默认只列实际包含物及数量，不自动添加“图片中的其他装饰/道具不包含”。确有具体配件误认风险且证据明确时，才在注意事项中点名说明。
- 关键差异、重要尺寸、核心关键词和主要场景可在前台字段自然重复。标题负责识别，Item Highlights 负责补足，五点负责解释，详情负责完整展开。
- Search Terms 必须全部小写、单行、单空格、无标点、无品牌和 ASIN；删除 Item Name、Item Highlights、五点、详情及其他已填属性已经覆盖的词。
- 如果 Search Terms 看起来过短，先回查全部参考标题与其他同类标题的可用同义词，再决定留短；不能因为第一个链接或卖家精灵未返回更多词就停止扩词。未完成卖家精灵或自然搜索复核时，不把候选词交付为已完成 Search Terms；研究状态只写在内部记录及对话中，不写入 Excel 参考列。
- `Design A/B/C`、`Diseño A`、`Variante A` 等内部变体编号不得进入任何买家可见字段；只有用户确认的公开变体名称可写入 `buyer_visible_variant_terms` 后保留。内部编号只能出现在运营表头或参考列。

## 交付

默认在对话中按以下顺序提供可复制内容：

1. 产品信息核对与来源
2. 父体标题，仅在关系与变体主题已核实时提供
3. 子体 Item Name
4. Item Highlights
5. 五点 1–5
6. HTML 详情
7. Search Terms

用户要求 Excel 时生成独立副本，不覆盖开发原文件，并读取 [运营交付大母版](../../references/delivery-master.md)。默认仅建立“产品内容”和用户要求的各目标站点 Listing 工作表；同站点多变体并列。每个变体按“目标站点文案、中文翻译、参考”三列成组，Item Name、Item Highlights、五点1–5、HTML 详情和 Search Terms 均提供完整中文翻译。中文翻译必须先写入 `listing-package.json` 并与目标文案一起通过校验，再写入 Excel；字符和字节限制只检查目标站点文案，不计算中文翻译。产品内容页统一使用“产品名称、产品图片、产品尺寸、产品材料、产品规格、补充信息”六列；每个变体必须实际嵌图，依次选择自有主图（含开发 Excel 嵌图）、对应规格供应商图、第一条有效商品链接当前变体主图。图片来源留在内部记录，产品内容页不写待核对、资料缺失或来源免责声明，也不默认增加关键词、审核说明或内部分析工作表。导出后运行 `plugins/chenyu-yunying/skills/chenyu-yunying/scripts/validate_product_content_workbook.py` 检查实际嵌图与内部备注。

交付前核对每项客观宣称均可追溯、变体不混用、单位正确、内部采购信息未泄漏，且买家文案不包含竞品身份、内部审核语言、面向卖家的解释、作图构图语言、重复句或默认道具免责声明。
