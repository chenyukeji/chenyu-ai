# 晨玙 Listing

先读取 [开发文档读取规范](../../references/kaifawendang.md)。若运营入口已有确认的产品记录，复用并核对本次修改，不重复索要资料。

## 生成

1. 确认目标站点、语言、产品身份和要处理的变体。品牌未知不能编造；需要时明确询问，或省去未确认品牌并标记草稿。
2. 从自有事实提取特征、适用场景与有依据的购买理由，区分所有变体共用内容和款式差异。竞品措辞只提供表达思路，不能复制其品牌、连续文案、规格和功能。
3. 将提供的关键词按相关性分配到标题、五点、描述和搜索词。没有搜索数据时可提出相关词候选，但不能声称有搜索量、排名或转化验证。
4. 按目标语言自然表达，先说明产品是什么，再突出买家关心的已确认差异。避免堆词、主观最佳、促销承诺和无依据功效。
5. 实际需要判断平台限制或交付可发布稿时，核实适用站点、类目当前官方要求；无法核实时明确该项未验证，不把固定字数当通用规则。

## 交付

输出一份可直接审阅的 Listing：目标站点/语言、标题、五点、产品描述、搜索词候选、变体差异。五点是默认工作格式，用户及适用类目要求优先。关键词说明、事实依据和待确认项单独列出，不混入买家可见文案。

变体不自动等于合法父子体关系；需要提供父子体建议时核实类目支持的变体主题。未证实的卖点不填入正式文案。没有品牌或必要规格时，明确草稿的具体缺口。

默认在对话中交付完整内容；用户要求 Excel 时生成独立副本并按可用表格能力核验，不覆盖开发原文件。中文审核说明和目标语言文案分开。只做文案交付，不登录或发布商品。

交付前核对：每项客观宣称有来源、各变体无混用、单位换算正确、内部采购信息未泄露、没有竞品身份信息被误用。
