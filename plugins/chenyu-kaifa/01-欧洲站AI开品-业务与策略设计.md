# 晨玙欧洲站 AI 开品插件：业务与策略设计

版本：设计稿 v1.4（精铺版）｜核实日期：2026-09-18｜建议插件名：`chenyu-kaifa`

本方案按用户最新确认的精铺模式设计：

| 项目 | 已确认要求 |
|---|---|
| 销售站点 | 德国、法国、意大利、西班牙 |
| 新品发现来源 | 美国站与德国站新品榜 |
| 目标含税售价 | **€5–20**，单品和组合装均按一个销售单位判断 |
| 货品成本上限 | **采购＋包装合计≤人民币20元/销售单位**；组合装按整套合计 |
| 中国卖家线索 | 只需找到**至少1个销售同类产品的中国卖家**即可通过该项候选准入 |
| 产品形态 | 现货单品、现货多件装、两个现货产品的组合装 |
| 定制 | 前期不做改模、改结构、专门材料开发；取现货样品验货 |
| 数据获取 | 卖家精灵网页版直接采集，Amazon 页面核实 |

类目广泛探索，采用分层筛选与小批量验证。采购与包装上限不包含头程、关税、FBA、广告等，这些仍需另算利润。包装材料、标签和组套包装人工计入包装成本，避免把组套支出漏出上限。

本文是设计资料，未登录用户账号或实际跑品。用户确认的站点、价格、成本和产品模式为业务约束；其余采样规模、权重、阈值和算例为待校准的设计值。

配套文档：[工程实现与验收](02-欧洲站AI开品-工程实现与验收.md)、[初始规则配置](03-欧洲站AI开品-初始规则配置.json)。

## 1. 产品定位：低成本现货精铺与组合选品

插件的目标是连续产出“有需求依据、能找到现货、成本在范围内、值得小批量试销”的具体 SKU。每个 SKU 都保留选入原因、报价、利润与退出条件。

核心问题：哪款现货值得上？是否有中国卖家在卖同类？目标欧洲站是否有需求？单卖还是组合更合适？在 €5–20 售价与 ¥20 采购包装上限内能否获得合理贡献？

决策对象为 **目标站点 × 需求 × 现货规格/套装 × 售价 × 履约方式**。候选可以直接是一个有购买需求的普通现货单品，不强制要求结构创新或新品类空白。

精铺工作流是“广泛发现、低成本初筛、重点取样、少量试销、保留复盘”。同类重复 SKU、供应商重复款和大量颜色变体先去重，避免用上架数量替代有效测试。

员工指令示例：“从美国和德国新品榜，以及中国卖家现有商品中，找德法意西可卖的现货；售价5到20欧，采购加包装不超过20元，同时给出现货组合机会。”

## 2. 中国卖家准入：一个即可

**确认有1个中国卖家销售同类产品，即通过“中国卖家存在性”筛选。** 不再要求3个卖家、2个持续商品组，也不因为只有一个卖家而在该项打低分。

记录：卖家标识、所属地依据、站点、对应ASIN、同类匹配证据、观察时间。只看到店铺名或中文评价不能推断卖家国籍。CN与HK分列，是否合并由配置决定。

中国卖家证据可来自本次研究站点，不额外要求四个目标销售站各有一个中国卖家。只在美国找到时，进入候选池并继续验证目标欧洲站需求；不追加第二个中国卖家门槛。

该规则决定候选准入。需求、价格、成本、供货与产品适用要求分别评估，不需要把“有中国卖家”扩展成已证实盈利或本账号已具备销售资格。

卖家精灵公开字段中的卖家所属地关联Buy Box卖家；网页版实际含义须实测，不直接推断品牌国籍。[字段文档](https://open.sellersprite.com/api/2)

类目不限，优先排序考虑现货可得、体积重量、规格简单、采购包装成本、售后负担和验证工作量。高验证投入产品可以进入研究记录，是否试销按企业实际能力决定，不自动引入定制开发。

## 3. 完整策略池与统一开品工作台

保留原有选品思路，新增近60天FBM机会，并将历史旺季回看落实为正式季节选品策略。一个工作台按任务调用多种策略，同一候选共用证据、询价、利润与验样流程。策略数量不等于用户必须操作的步骤数量。

| 分组 | 策略 | 怎样发现机会 | 输出 |
|---|---|---|---|
| 现货与市场 | A 同类中国卖家现货 | 从至少一个中国卖家的同类商品验证现货方向 | 可匹配规格与现货候选 |
| 现货与市场 | B 近期商品需求 | 从近期上架、需求出现或增长的商品找切入点 | 新进入候选与趋势证据 |
| 现货与市场 | C 关键词需求 | 从本地购买词、长尾规格与搜索结果发现未充分满足的需求 | 需求簇及对应产品 |
| 现货与市场 | I 卖家相邻产品线 | 从可比卖家的店铺、用途和现有供应链找相邻需求 | 适合继续扩展的现货候选 |
| 新品与时机 | E 美德新品榜 | 美国与德国新品榜发现产品，验证欧洲目标站需求 | 新品信号与本地验证任务 |
| 新品与时机 | H 历史旺季提前备货 | 回看去年旺季增长与销量，提前验证今年机会 | 季节候选、销售窗口和备货日期 |
| 新品与时机 | J 近60天FBM机会 | 从近期FBM商品找需求和交付改善空间 | 经同类供给核实的候选 |
| 组合与规格 | D 评论需求 | 从用户明确的缺件、尺寸和使用问题中发现可用现货解决的需求 | 现货规格、配件候选与验货要点 |
| 组合与规格 | F 两个现货产品组合 | 从分别有需求的组件生成互补方案 | 组合BOM、共同购买理由与单卖对照 |

A/B/C/D/E/F/H/I保留，J为新增。H包含用户提出的“9月回看去年11—12月销量飙升”方法。原字母作为稳定策略编号，前台展示中文名称。

### 3.1 操作简单，策略可以按需组合

用户可用自然语言发起“常规找品”“找今年冬季产品”“从这家店扩品”“找现货组合”等任务，也可勾选策略。系统展示本次启用的策略、取数月份、预算和共同验证动作。默认计划可调整，不要求每次全跑九种。

- 常规找品：A/B/E/J发现；C/D核实需求和规格；有种子商品时按预算扩展I/F。
- 旺季提前备货：H主导发现；C核实历史与今年关键词；A核实同类中国卖家及现货；按候选情况补D/F/J。
- 店铺扩品：I/A发现；C/D核实；F比较组合。
- 组合找品：F/D生成；A/B/C补足组件及组合需求依据。

每条策略均可单独选择。C可直接从关键词生成候选；D可从指定类目或标杆评论生成规格/配件候选；I可从已知店铺生成相邻候选，均保留独立发现能力。D/I缺少种子时复用已有候选或先运行预算内的A，不假设已有全类目评论或完整店铺数据。

A关注功能、使用场景、规格和件数的同类关系；B保留上架日期、父子体关系、当前需求和促销，不因缺少长期历史自动淘汰；C必须用本地页面/数据核实购买意图，机器翻译不产生搜索量；D只采用现货可解决的规格或搭配；I的店铺共现、推荐位只作发现线索，不能证明共同购买。所有策略最终遵守一个中国卖家、售价€5–20、采购包装≤¥20等共同约束。

策略命中同一商品时只增加来源和理由，不重复计算销量或采购SKU。F是方案生成策略，可以独立发起，也能处理其他策略的候选；所有策略都可以输出单品、多件装或互补组合。

### 3.2 策略J：近60天FBM机会

用户提出的思路适合精铺早期试跑：寻找已出现需求、当前供给可能仍以自发货为主的现货，评估采用FBA能否改善交付并保留利润。该假设需要目标市场证据支持，不能仅凭配送标签下结论。

2026-09-18核对的卖家精灵公开选品页展示了“Within 60 Days”上架时间选项，以及AMZ/FBA/FBM配送筛选。真实账号下的筛选生效、权限、字段和结果仍需联调。[卖家精灵公开选品页](https://www.sellersprite.com/v3/)

建议首个预设如下。销量和评论数为试跑参数，不是平台标准或已验证成功条件。

| 条件 | 初始设置 | 用途与边界 |
|---|---|---|
| 目标站 | DE、FR、IT、ES分别查询 | 竞争和需求按本站判断 |
| 来源上架时间 | 近60天，保存原始日期 | 不等于该需求只存在60天；首次采到时间另存 |
| 配送方式 | FBM | 只作为发现标签，不能证明同ASIN或同类没有FBA |
| 价格 | 先筛€5–20 | 核实运费、促销条件和件数；最后判断自己销售单位的售价 |
| 估算销量 | 近30日≥30件作为优先研究起点 | 10—29件可观察；父体估算只作粗筛，不能当选中子体或当前FBM卖家的销量 |
| 评论 | 可优先看≤100条 | 用于排序；需核对共享评论，不作全局淘汰门槛 |
| 中国卖家 | 最终保留至少1个同类中国卖家证据 | 可先用所属地筛选提速；没有命中时可从其他同类补证据 |
| 采购与包装 | 单品/整套≤¥20 | 报价后判断，不让AI从亚马逊售价猜进价 |

上架0—14天的候选单独观察；数据可能覆盖不足30天，不将短期销量线性放大。15—60天候选优先验证当前需求。记录所选“近30日”或自然月，不能把不同统计周期混用。

结果少时保留近60天队列，同时补看有需求的常规现货；年龄与FBM只限制这个预设，不成为全插件准入要求。已有FBA的商品仍可通过常规入口比较规格、价格、竞争和利润。

### 3.3 FBM策略的同类供给核实

1. **候选当前报价：** 页面当前展示的是谁销售、谁配送，是否有运费、何时送达？
2. **同ASIN其他报价：** 其他可见卖家是否存在FBA？当前FBM是否可能只是FBA暂时缺货后的状态？历史缺失时标未知。
3. **同需求竞争：** 其他品牌、其他ASIN的可替代商品，是否已有FBA、Amazon自营或快速自发货供应？

真正影响开品判断的是第3项及自身经济模型。仅一个ASIN没有FBA，只能描述该商品的可见报价情况。卖家精灵的卖家字段文档关联Buy Box卖家，商品销量也不能自动归到当前卖家或某种履约方式。[卖家精灵字段说明](https://open.sellersprite.com/api/2)

对进入深研的候选，用3个经本地验证的购买关键词，每词默认查看前20个相关商品组，再合并去重。保存自然/广告位置、功能规格、套装件数、实际可见报价、配送方式、到手价和送达区间；同需求竞品查询**不限制上架时间和配送方式**。这些为采样预算，可按任务范围调整。

输出两个独立结果：

- **可见FBA供给：** 已发现 / 样本未发现 / 未知，附商品组数、报价覆盖、关键词、邮编和采集时间。
- **交付改善空间：** 存在 / 有限 / 待验证，依据实际到手价、送达承诺和我们拟采用的履约方案。

页面未加载、报价面板读不到或配送身份不明，均为未知。完成约定采样且未见FBA时，只写“本次样本未发现”，不声称全市场没有。即使未见FBA，也必须评估Amazon自营和快速自发货的竞争；Prime标识本身不能证明FBA，Amazon提供卖家自配送的Prime方案。[Amazon德国站Seller Fulfilled Prime说明](https://sell.amazon.de/en/programme/prime-durch-verkaeufer)

### 3.4 判断这个FBM机会是否值得做

值得继续验证的组合条件是：同类有需求依据、至少一个中国卖家、可比供给交付较弱、现货能匹配、包装及物流可行、在€5–20内有足够贡献。FBA供给少只是其中一项。

| 观察结果 | 下一步 |
|---|---|
| 有需求，相关样本FBM为主、送达较慢，现货与FBA利润可行 | 优先询价、验样和小批量计划 |
| 有需求，同类已有少量FBA，但存在可验证的规格或交付不足 | 比较可替代程度、到手价与利润，再决定是否继续 |
| 无FBA，但Amazon自营或快速自发货已覆盖需求 | 调低“交付改善”优先级，按普通现货机会评估 |
| 当前FBM，但老商品/其他报价已有成熟FBA供给 | 撤销“FBA供给缺口”标签，保留真实竞争结果 |
| 看起来销量高，实际来自老父体、其他变体或此前履约方式 | 仅保留商品组线索，补查当前规格需求 |
| 无FBA且需求薄弱，或体积/费用使低售价无法盈利 | 观察或淘汰；记录具体原因 |

还要核算机会能否持续到入仓：拿样、采购、运输、入仓的总天数与季节窗口一起展示。采购决策前刷新竞品配送和到手价，出运前检查供给是否已明显变化。不能推断别的FBM卖家没有在途FBA库存，也不把当前缺口承诺为长期机会。

### 3.5 策略E：美德新品榜发现，目标站验证

US新品榜用于发现早期产品信号，DE新品榜用于发现当地新出现的需求。采集相关细分类目，保存榜单类型、类目、排名、ASIN、价格、时间、可售/预售状态。榜单与卖家精灵“上架近60天”分别记录，不互相代替。

US候选按功能和用途映射本地搜索词，验证目标欧洲站需求、规格/使用习惯和现货适配；美元售价不直接换算为建议欧元售价。DE候选可以先本地验证，再扩到FR/IT/ES，不要求四站或双榜同时出现。

榜单排名只在同站同类目比较；不将名次换成精确销量。只有对应榜页覆盖完整，才判断本次入榜/退出；采集失败不记跌榜。同榜多个变体、同商品跨榜与跨入口均去重。

本次未取得实时新品榜商品清单。入口、细类目和分页需联调确认；不编造榜单商品。

### 3.6 策略F：现货组合与单品比较

候选通过基础验证后，先建立现货单品方案；对具有明确搭配理由的产品，检索少量现成组件并比较组合方案。默认两个产品组套。

| 搭配依据 | 示意，非实测商机 |
|---|---|
| 同一任务的前后步骤 | 清洁工具＋匹配收纳件 |
| 主用品需要辅助用品 | 手工定位工具＋适配夹持附件 |
| 同一对象的互补用途 | 植物固定夹＋适配绑带 |

两个产品各自有需求，只能支持组合研究；还要证明同一顾客有一起购买的理由。优先看目标站可比套装、明确共同使用的评论和规格兼容性。推荐位与店铺同时上架仅为线索。组合销量独立估计，不能将两个单品的销量相加。

按`Σ(组件单价×数量)+包装材料+标签+组套包装人工≤¥20`筛选，费用已包含的分项不重复计算。A¥7+B¥6+包装人工¥2为¥15；A¥12+B¥8+包装¥2为¥22，后者不通过。

实测整套包装尺寸与重量，再单独核算物流、FBA和退货成本。比较A单卖、B单卖与A+B在€5–20范围内的售价、贡献与资金；单品可以直接胜出。核对目标站适用组合要求、品牌和商品身份，验样通过后形成小批量计划。

共享组件按统一库存池预留；已包装/入仓商品的拆套残值须有处理地点和费用依据。

### 3.7 策略H：9月回看去年11—12月，提前选季节产品

这是一条正式发现路径。以2026年9月发起任务为例，分别读取2025年11月和12月的商品月度数据，找历史旺季需求；有权限和历史覆盖时，再读2024年同季增强重复性证据。历史只有一季仍可进入候选池，不增加中国卖家数量门槛。

2026-09-18核对的公开选品页列出了2025年11月、12月和更早月份，并展示月销量与月销量环比增长率筛选；这是公开控件能力，登录后历史覆盖和筛选结果需要实测。界面叫“飙升榜”、增长预设或自定义筛选都可以映射，必须区分销量增长、BSR变化和关键词增长。[卖家精灵公开选品页](https://www.sellersprite.com/v3/)

**第一步：旺季增长与旺季热销同时取候选。**

11月、12月各跑两组条件，合并去重：一组按销量增长找快速起量商品，另一组按当月销量找持续旺销商品。12月环比下降但仍有大量需求的产品不能因不在飙升队列被漏掉。

试跑建议：历史旺季月估算销量≥100件；增长队列再优先看环比≥50%且比前月增加≥50件。它们只是可调的排序/采样起点，不是全类目成功标准，也不决定采购量。历史参考价可先看€5–20，但报价及利润最终按今年计划销售单位计算；没有历史价格时不把当前价格当成去年价格。H不叠加“近60天”“必须FBM”“少评论”的过滤条件。

**第二步：补足全年走势和同比，判断为什么上涨。**

对前列候选补去年全年及今年截至目前可得历史。至少看旺季前、旺季中、旺季后；有更多年份时，对比相同月份或相同节日窗口。关键词历史可作为独立需求证据，官方教程介绍了历史趋势与分年查看能力，实际覆盖以账号为准。[卖家精灵关键词选品说明](https://cn.sellersprite.com/cn/help/market-selection-guide)

| 证据 | 能帮助回答什么 |
|---|---|
| 月销量、绝对增量、按月份天数换算的日均 | 增长是否有真实规模，是否只是从1件到10件 |
| 去年全年曲线和旺季后回落 | 是季节性，还是新品起量后持续增长 |
| 前年同季、同用途可比商品、关键词同季趋势 | 是否有重复需求；缺失时保留不确定性 |
| 同期价格、促销、缺货/恢复、父子体关系 | 上涨是否由折扣、供货恢复或统计变更造成 |
| 今年同阶段可得需求、当前竞品价格和供给 | 去年机会是否仍适合今年进入 |

同类多商品是增强季节证据的样本，不是中国卖家准入数量要求。同比必须用同周期：2026年9月尚未结束时，不能拿9月半月与2025年完整9月比较；优先用两年最近相同的完整月份，或来源确实支持的同截止日数据。

区分三类：节日型（窗口固定且结束快）、天气/季节型（受当地气候影响）、促销事件型（需求可能依赖折扣）。同一商品可以有混合原因；证据不足标“季节假设”。从去年11—12月榜单发现的是产品方向，不自动沿用当年的品牌款式或年份图案。

**第三步：按需求开始日期倒排，判断9月是否还来得及。**

不能一律按12月旺季峰值安排到仓。先估计今年需求起量窗口，再计算：

`最晚启动日 = 目标可售日 - 拿样/验货 - 采购/备货 - 运输 - 入仓处理 - 上架准备 - 缓冲`

默认按保守串行时长估算；已确认可以并行的步骤按关键路径计算，不重复相加。各项交期来自供应商、货代与实际履约计划；缺失时给出需要补齐的时长，不凭空宣布来得及。

纯演示：目标2026年11月1日前可售，总准备和物流时间45天，缓冲10天，则最晚启动日约为9月7日。到9月18日才启动，按该计划已经晚11天，应比较能被确认的更快方案、其他销售窗口或暂缓；不能因为旺季在11—12月就认为9月一定来得及。月度历史只能给月份级窗口，不能据此伪造精确起量日。

**第四步：用今年的成本和保守需求安排小批量。**

初期建议以常年可售的现货作为基础，季节品先做小批量验证；同等条件下优先销售窗口较长、没有固定年号、旺季后仍有用途的产品。具体资金占比等预算和真实试销结果明确后再设定。

淡季当前销量低不自动否定季节品；需要判断历史季节证据、今年同阶段需求、当前竞争与能否按期可售。去年竞品月销不是今年自己的销量。试销量取决于独立的保守销售假设、剩余窗口、预算、MOQ和亏损承受额；缺少预算时给出资金需求，不自动决定采购件数。

季节品按整批核算库存风险：正常售出利润、折价销售、剩余库存处理、仓储及资金占用。补货以“预计补货到仓后还能卖几天”判断；预计到仓晚于有效销售窗口时停止补货建议。少量未售的年号/节庆专用款与全年可用款分开处理残值，组合按整套≤¥20及实际包装计算。

输出季节机会卡：历史来源月份、起量/峰值/回落窗口及精度、季节原因、历史重复证据、今年需求与竞争、目标可售日、最晚采购/发运日期、交期缺口、单品/组合、今年成本利润、试销资金需求、补货截止与尾货处理。

### 3.8 所有策略共用一条验证流程

```text
任务目标 + 可选策略池
        ↓
按策略采集与生成候选 → 去重、保留全部命中理由
        ↓
一个中国卖家证据 + 目标站需求/竞争 + 现货匹配
        ↓

        ↓

```

用户看一个候选列表，通过策略标签、常规/季节属性和待办筛选。底层复用采集与经济模型；同一需求证据不因多策略命中重复加分。所有策略保留独立调用能力，任务计划按种子、时间窗口和预算决定先后顺序。

## 5. 从广泛发现到少量深研的漏斗

### 阶段 0：账户与能力探测

检查卖家精灵当前登录状态、可用页面、可选站点、历史范围、分页和导出能力。建立能力矩阵。先确认确实能够读取，再扩大候选扫描。

### 阶段 1：策略池汇入统一候选池

按任务启用同类现货、近期需求、关键词、评论、店铺相邻产品、美德新品榜、历史旺季、近60天FBM与组合策略；采集月份和预算随策略记录。销售站点保持DE/FR/IT/ES，来源站点与销售站点分别存储。候选去重后分成现货单品池、可组套组件池和待验证池。

不将榜单前100名称为全市场；记录采集类目、榜单、页码、时间、排序与未覆盖范围。不同入口命中同一商品只增加证据，不重复生成多个待采购SKU。

### 阶段 2：快速清洗与粗排

按站点-ASIN 去重、父商品组聚合、分清币种单位和销量层级，检查价格异常、历史缺失、相关性、明显不可行条件。将几百个商品线索聚为几十个需求机会。

### 阶段 3：重点核实

先用一个有效中国卖家证据、少量相关竞品、核心关键词和评论做快速判断；只对排名靠前、报价可得或接近决策边界的候选补采。更多竞品是分析资料，不恢复为中国卖家数量门槛。

精铺无需每款都写长篇研究。优先排除身份不符、无对应现货、超成本、目标价无利润和无法解决的使用问题。

### 阶段 4：经济模型与产品方案

每个机会输出单品或A/B/组合可比较方案，按€5–20售价和整套采购包装≤¥20核算。真实报价缺失时输出允许的采购包装上限并进入“待询价”；不猜测国内进价。

### 阶段 5：样品与小批量验证

采购现货样品，核对规格、质量、组合适配、完整包装和入仓成本，然后做小批量验证。这里的样品是验货样，不是定制打样。系统给出建议，人确认供应商和采购动作。

上述数量是处理规模示例，不是必须凑满的数量。没有足够证据时输出较少候选及缺口。

## 6. 评分：进入约束、机会分、证据质量分别展示

### 6.1 进入约束先于评分

每一项为 `pass / fail / unknown / not_applicable`：同类中国卖家存在、现货可得、采购包装≤¥20、售价€5–20、账号/类目资格、适用产品/组合规则、MOQ/预算、包装物流可行性、经济模型下限。

明确 fail 的不可开候选进入淘汰池并保存原因；unknown 根据阶段进入待验证池。高需求不能覆盖强制合规缺口，单纯缺失数据也不等于已证实不能做。

### 6.2 精铺机会评分，满分100

| 评分块 | 权重 | 子项建议 |
|---|---:|---|
| 需求质量D | 30 | 当前可得需求45%、目标站购买意图35%、趋势可确认度20% |
| 竞争可进入性E | 15 | 价格压力35%、头部控制30%、近期进入者35% |
| 现货方案匹配R | 15 | 使用场景适配40%、规格/组件兼容30%、购买价值30% |
| 单位经济U | 30 | 绝对贡献40%、压力情景30%、获客余量20%、成本余量10% |
| 精铺执行F | 10 | 现货补货35%、MOQ与资金35%、验货和组套复杂度30% |

`S=0.30D+0.15E+0.15R+0.30U+0.10F`，各块0—100。

中国卖家存在为独立准入规则：至少1个即pass，不再按卖家数量分档打分。普通单品按自身用途适配评分；组合按组合用途、兼容与价值评分，不设“必须组合”或“必须创新”加分。

同站点、相近类目和价格段建立归一化参照。价格段采用€5–9.99、€10–14.99、€15–20。单件贡献和资金效率均展示，避免只因高利润率而忽略过低的绝对利润。

缺失项不重分权重，显示S_low/S_high与证据质量。新上架缺历史保留未知并安排观察，不因不满90天直接淘汰。

### 6.3 数据质量 Q，满分 100

`Q = 40%关键字段覆盖 + 25%时效 + 20%身份/口径确定性 + 15%可核验程度`。

Q 是内部证据质量分，不是成功概率。卖家精灵与 Amazon 可能共享底层信息，重复出现不能当两份独立销量真值。对核心事实的冲突单列，不靠平均掩盖。

按阶段组织候选：发现阶段依据商品身份、同类中国卖家证据与需求线索进入队列；询价阶段检验现货规格、报价和目标售价；试销评审检验完整成本、适用要求与预算。分数区间和Q用于阶段内排序、指出应补证据。

历史数据少、报价尚未取得的候选可进入补证据/询价队列。完整机会总分不再作为所有阶段共用的准入门槛。明确成本超限或实物不匹配等结果进入淘汰或替代现货流程。

## 7. 几个必须正确实现的指标

### 市场样本规模与集中度

同站点、同时间窗、同需求范围内按商品组去重。父体销量仅计一次；完整且口径一致的子体数据才允许汇总。父体和子体不能相加。父子映射不确定时输出无法去重的占比和规模区间。

`CR5_sample = 样本前 5 个独立商品组估算销量 / 有效样本估算销量总和`。

同时输出品牌集中度、可见卖家集中度和样本数。商品组销量可用于品牌维度；Buy Box 卖家可能变化，不能将商品全月销量直接认定为该卖家实际成交量。卖家维度只能标“当前卖家关联商品的估算需求占比”。

### 新品进入表现

可见新品中满足持续需求条件的比例、其中位销量、价格变动和评论积累。没有完整同期新品追踪时不输出无偏成功率。对已有老父体的新子体单独分类。

### 需求可获得性

大市场不意味着新品能拿到固定 1% 份额。优先从可比新进入产品的实际观察分布构造销量情景，再用流量模型交叉检查：

`广告订单 = 广告点击数 × 广告转化率`

`自然订单 = 去重口径下的自然曝光 × 点击率 × 转化率`

`情景订单 = 广告订单 + 自然订单`，并受供给能力与可比进入者表现约束。

CTR/CVR/可得曝光是我们的假设或后续实测，不是从竞品页面抓到的真值。关键词搜索量存在重叠，不能逐词直接相加当独立顾客数。冷启动期对自然流量使用低假设。

### 现货适配与组合价值

评论用于判断现货规格和组件是否合适。组合价值分别呈现场景互补、独立需求、组合购买依据、兼容性与增量成本。两单品销量相加、取较小值或相乘都不能冒充组合销量；组合销量使用独立情景并待试销校准。

### 广告竞争

搜索页广告占位仅是特定时间地点下的展示情况；PPC 字段是来源方估计时保留 estimated，不能当我们真实 CPC。盈利应测试多种 CPC/CVR 组合。

## 8. 欧洲站利润与现金流模型

### 8.1 每个方案按站点和履约路径单独计算

输入至少包括：€5–20范围内的实际含税成交价、税率分类、采购人民币金额与汇率、组件数量、包装材料/标签/组套人工、头程、关税、FBA/配送、佣金、仓储、退货净损失、其他责任费用和广告参数。采购包装合计≤¥20是硬上限，实际可接受成本还可能更低。

将费用分成单件、按成交额、按广告点击、按时间库存、一次性固定投入五类。可抵扣税额与不可抵扣税额分别处理，避免把同一项税重复当成本。进口 VAT 即使可抵扣，也可能占用现金。真实适用税率按商品和经营路径核实；欧盟各国税率并非统一。[欧盟 VAT 规则与税率](https://europa.eu/youreurope/business/finance-and-tax/vat/vat-rules-rates/index_en.htm)

统一函数：

```text
P = 已计入卖家承担折扣后的含税成交收入
R = P / (1 + VAT税率)
CM_before_ads = R - 佣金 - 配送 - 采购 - 包装 - 头程/关税
                - 仓储 - 退货净损失预留 - 单件责任费用 - 其他变动费用
每广告订单成本 = CPC / CVR
每总订单广告成本 = 广告订单占比 × CPC / CVR
CM_after_ads = CM_before_ads - 每总订单广告成本
贡献率 = CM_after_ads / R
```

佣金基数、最低佣金与费用税额按实际类目规则计算，不能默认都按不含税售价收费。已经计入成交价的 Coupon 折扣不能再减一次；Coupon 的独立使用费另列。

退货预留应覆盖退款导致的收入冲减、不可回收费用、处理费、损耗，扣除可退费用与可回收库存价值，并避免和其他行重复。只知道退货率、却不知道损失构成时，用明确的场景假设。

### 8.2 广告盈亏线

在相同订单及收入口径下：

`广告订单盈亏 CPC = CM_before_ads × 广告 CVR`。

`单广告订单盈亏 ACoS = CM_before_ads / 广告销售额每单口径`。

广告销售额分母必须与报表一致。含税与不含税 ACoS 不能混用；自然订单可以改善总盘利润，但不能据此把亏损的广告订单误标为盈利。

### 8.3 按三个价格段分别计算

| 价格段 | 核心核算 |
|---|---|
| €5–9.99 | 配送、税费和广告占比较高，倒算实际能承受的采购包装金额 |
| €10–14.99 | 比较单卖与数量装，检查单件贡献和入仓费用 |
| €15–20 | 比较单品与互补组合，关注增加部件后的费用和退货成本 |

不要求每个商品花满¥20。实际成本上限为：

`min(¥20, [不含税收入－其他全部单件成本－目标单件贡献]×人民币/欧元汇率)`。

若费用或目标贡献未确定，只能显示情景区间，不能判定可采购；经济上限≤0时该售价情景不可行。

**纯演示，不是报价或费率承诺：** 假设售价€15、VAT19%、采购包装¥16、演示汇率¥8/€，则不含税收入约€12.605，采购包装为€2。再假设佣金€2.25、配送€2.70、头程关税€0.60、仓储退货等€0.60，广告前贡献约€4.455。若CPC€0.30、CVR10%、全部订单来自广告，广告后单件贡献约€1.455。

即使采购包装低于¥20，也不能跳过其他费用。实际费用需由站点、类目、包装和履约方式确定，冷启动用独立广告情景。

### 8.4 三情景与压力测试

每个机会都输出保守、基准、乐观情景。独立展示售价、CPC、CVR、自然/广告占比、销量、汇率、采购和配送费用的假设。

压力组合初始可设：售价下降 10%、CPC 增加 25%、CVR 下降 25%、采购和头程增加 10%、退货预留加倍；这些是风险测试幅度，不是预测概率。费用随价格/尺寸变化重新计算，不能全部固定。

缺报价时倒算：

`允许采购包装上限CNY = min(20, (R - 除采购包装外全部单件成本 - 目标单件贡献) × CNY/EUR汇率)`

输出整套采购包装允许金额，并将剩余部件预算分配给询价。已经由报价包含的包装项不重复扣除；头程等费用独立核算。

Amazon 当前费用页包含按时间变更的费用和附加费，因此费用规则必须有 `effective_from / effective_to / source`；使用官方计算器已含附加费时不要重复加收。[Amazon 费用说明](https://sell.amazon.de/preisgestaltung)

### 8.5 现金流和首批数量

现金峰值按时间展开：定金、尾款、运输、进口税费、入仓、广告投入、平台回款、退货退款及下一批定金。贡献利润为正不等于资金链安全。

`首批需求建议 = 保守日销 × 测试覆盖天数 + 明确的安全库存`，再与 MOQ、可用预算和季节窗口比较。若 MOQ 高于可承受数量，标记不匹配，不能自动把采购量加到 MOQ。

`补货点 = 交期内需求 + 安全库存`，安全库存按需求和交期波动估算。旺季品加入季末清货价值与禁止补货日期。最终首批订单由用户确认。

## 9. 多站点规则与合规设计

销售站点、库存国、进口国、买家所在地分别存储，覆盖DE/FR/IT/ES。新品发现使用US/DE来源，销售与履约评估使用上述四站。组合装单独检查目标站适用规则及品牌/商品身份，不因为参考竞品存在就自动认定可销售。

建立适用性规则：目标用途、年龄对象、是否通电/含电池、食品接触、材料化学风险、无线功能、承重保护用途等，触发待验证事项。不是所有商品都需要 CE；不能根据竞品图片有标志就认定自己的商品已合规。

对 GPSR 适用产品，规则涉及追溯、责任主体和线上展示等信息，须匹配具体角色与产品。使用官方文本和指南维护规则，不把 AI 摘要当最终判定。[欧盟产品安全适用指南](https://eur-lex.europa.eu/eli/C/2025/6233/oj/eng/pdf)

包装及 EPR 规则按国家、主体角色和生效日期维护。德国主管机构资料已包含 2026 年包装规则变化，因此禁止把“一个登记号+一个固定费用”写成永久通用规则。[德国 LUCID 登记说明](https://www.verpackungsregister.org/en/registration/find-out-about-registrations)

系统可以发现商标、外观或专利疑点并建立核查任务；没有检索结果不等于没有权利风险，最终生产销售前需要完成对应评审。

## 10. 机会卡与开发交付

每个机会卡固定包含：

1. 机会名称、站点、需求簇和目标用户。
2. 命中的发现策略及其证据。
3. 市场样本范围、可比商品组、去重规则和时间窗。
4. 中国卖家可进入证据、新品表现和反面证据。
5. 本地核心词、购买意图、搜索结果匹配情况。
6. 评论证据、现货避坑点和可用现成配件。
7. 单品或组合方案、组件清单、数量、采购与包装分项、整套尺寸重量。
8. US/DE新品来源、欧洲四站验证状态和建议试销站点。
9. €5–20售价情景、整套采购包装≤¥20验证、单件贡献与资金峰值。
10. 强制项状态、机会分区间、数据质量和关键缺口。
11. 下一步最值得做的 3 个动作及停止条件。
12. 来源链接、快照、计算规则版本和更新时间。

建议决策状态：`发现 → 初筛 → 补证据 → 待询价 → 待现货拿样 → 待小批验证 → 用户批准推进 / 淘汰 / 观察`。数据质量和业务状态分开，partial 数据仍能产出有限结论。

Excel 交付建议保留现有三张核心表的语义：参考产品信息调研、产品确认、自有产品变体详情；另附机会总览、四站经济模型、风险与待办。待确认字段显式标记，不能用竞品规格直接填成自有产品事实。

## 12. 建议开发优先级与精铺复盘

首个闭环：**任务选择策略（同类现货、美德新品、近60天FBM、历史旺季等）→ 现货单品与组合候选 → 采购包装≤¥20 → €5–20利润测算 → 现货验样与小批试销资料**。

| 阶段 | 交付重点 | 完成标准 |
|---|---|---|
| P0 | 登录、历史月份、筛选与榜单探测 | 近60天/FBM与历史月份生效；榜单类型和字段可核验 |
| P1 | 数据、单卖家准入与去重 | 1个CN即可通过，来源站与销售站分开 |
| P2 | 现货单品与旺季验证 | 当前竞争、历史季节证据、交期、报价和利润可核验 |
| P3 | 两产品组合 | BOM、互补证据、整套成本与包装、单卖对照 |
| P4 | 四站扩展与复盘 | 本地需求、费用、试销结果与补货/退出建议 |

每批候选先粗筛，仅对前列候选深研；首批数量由单款测试资金、预估销量、MOQ和可承受亏损共同决定，当前未提供总预算，不自动确定采购数量。

精铺看板保留：单SKU实际贡献、广告消耗、退款损失、库存周转、缺件率、供应商交期、同类SKU重叠、每款人工处理时间。组合增加组件共享库存与组套效率。放量、继续观察、停止补货、清货各自具有明确触发条件；建议阈值待用户预算与真实样本校准。

评价插件关注候选有效率、单位研究成本、验样通过率、试销后贡献和周转，而不只统计推荐或上架数量。

历史验证必须只用当时已经可得的数据，保留淘汰及下架样本；先做时间切分和影子运行，再调整评分权重。不输出未经回测校准的“爆款概率”。

## 13. 精铺执行补充：从候选到值得继续投入的SKU

### 13.1 现货匹配与询价应成为正式环节

Amazon和卖家精灵负责提供需求及竞品证据；采购成本需要匹配的供应商报价。现货候选与标杆按核心用途、规格、材质声明、件数、配件和包装内容逐项对照，形成“匹配/不同/未知”的清单。图片相似只用于检索。

每份报价保存供应商款号、选中规格、计划采购量、该数量对应单价、报价日期/有效期、现货数量、包装内容、税费及国内运费口径。先用人工填写、文件导入或用户提供的商品资料完成这一环，后续再扩展供应商来源适配器。

数量阶梯报价必须使用本次计划采购量对应的一档。页面“起价”、不同规格的最低价和大起订量价格只作为线索。用于采购的报价与实物样品必须指向同一规格。

至少区分：货品采购、包装材料、标签、组套包装人工、国内运输、质检、国际头程及其他费用。供应商已打包包含的项目保留包含关系，避免重复计费；独立发生的国内运费、质检费进入完整经济模型。采购加包装的用户上限仍为¥20/销售单位。

### 13.2 增加绝对利润底线和SKU经营账

筛选同时看广告后单件贡献金额、贡献率与现金占用。只看采购包装低于¥20，会保留一批低价却没有费用空间的候选。

以下是建议的初始模拟档，用于比较候选，参数可调整；属于研究假设，尚未作为用户确认的执行规则：

| 含税售价 | 建议广告后单件贡献下限 | 建议贡献率下限 |
|---|---:|---:|
| €5–9.99 | €1.00 | 不含税收入的15% |
| €10–14.99 | €1.50 | 不含税收入的15% |
| €15–20 | €2.00 | 不含税收入的15% |

金额和比例同时满足，目标单件贡献取二者较大值。另展示压力情景是否亏损；所有假设均附来源或scenario标记。实际费用按类目、站点、包装和当期规则取得。[Amazon费用说明](https://sell.amazon.de/preisgestaltung)

单件贡献扣除了订单层面的变动支出。SKU经营账再扣上架素材、拿样、首次研究和合理分摊的固定开支，计算回收这些投入需要卖多少件。已在单件成本里计算的组套人工不再次分摊。

`回收准备投入所需销量=ceil(本SKU准备投入/单件广告后贡献)`，仅在贡献为正且口径一致时使用。多个站点复用素材、库存和研究时，共享成本分摊一次。

### 13.3 将两种“同类”关系分别记录

中国卖家准入需要的是市场上的同类销售证据；采购匹配需要的是供应商现货能够兑现准备销售的规格。二者分别记录，可避免把“有中国卖家销售类似功能”误当成“这份便宜报价就是可直接采购的对应款”。

一个有效中国卖家仍然足够。卖家数量不成为额外门槛。若其是某知名品牌的经销报价，记录业务角色，并将品牌需求与通用需求分开分析，避免把品牌搜索流量全部归给普通现货。

### 13.4 新品观察增加短促与身份变化标记

榜单候选记录入榜前后可得价格、优惠、可售状态、评论数和父子关系。观察短促、老父体新子体、变体合并、重新上架或资料变化的迹象；字段不足时写unknown。

这些标记用于解释需求信号和安排复查。历史短的真正新品仍可进入询价。榜单同名但规格不同的产品保留独立实体，同一需求重复出现则在需求层聚合。

### 13.5 组合需要一条明确的共同购买理由

为每个组合增加证据等级：

| 等级 | 依据 | 下一步 |
|---|---|---|
| A | 目标站已有同用途组合，且有可核验的需求证据 | 验证自己的规格、成本和价值 |
| B | 用户评论/问题明确提到需同时使用A与B，且规格相容 | 小样验证使用流程和目标售价 |
| C | A、B各自有需求，共同购买理由来自使用逻辑推断 | 作为组合假设，小范围验证 |

等级反映证据强度，不是成功概率。A、B均有需求是筛选入口，组合仍需与单卖方案比较。

将组合问题写成一句话：“谁在做什么时，同时需要A和B，因此这一套能减少什么麻烦？”无法清楚回答时暂缓组套。

组合比较除单件利润外，还看固定试销资金下的可备货数量、预估周转、组套时间、缺件处理和滞销时组件回收价值。已封装或已入仓的套装，只有确认拆套地点、处理成本和回收路径后，才计入可拆分残值。

### 13.6 给每个SKU建立试销卡

试销卡包含：计划售价、站点、采购数量、完整投入、广告测试预算、最大可承受损失、最低有效观察量、预计归因等待时间、复查日期和库存退出方式。总预算未提供时输出预算需求，采购数量保持待确定。

先检查可售状态、库存、价格和流量质量，再判断销量表现。记录从有货且正常可售起的有效观察天数。流量不足的“没单”进入曝光诊断；有足够相关流量但转化弱时检查商品/页面/价格；费用超预算或贡献持续为负时给出暂停投入与复核建议。

只有在实际贡献、需求持续性、供货和现金条件都满足时，才建议补货。广告归因和退货尚未成熟的近期数据附滞后标记，不用几天的表面利润直接放量。当前插件提供建议与记录，具体经营动作由对应流程执行。

### 13.7 将精铺管理单位提升到“试销批次”

一批候选里，识别同需求、同款换供应商、不同颜色及单品/组合的关系。展示每个需求簇、供应商和共享组件占用的资金，优先选择具有不同需求依据的SKU。

可按每个需求簇安排有限的试销名额，名额和资金上限均为可配置参数。使用同一库存覆盖多站时统一核算库存和资金，各站保留自己的售价、费用与销量，避免把同一批库存算四遍。

### 13.8 首版优先验证最短可用流程

开发顺序：榜单/卖家商品采集与证据 → 快速候选卡 → 匹配现货报价与样品 → 单品/两件组合费用表 → 可执行试销卡。

第一轮使用有限类目和少量真实样本，验证能否产出一个单品案例、一个组合案例和一个有依据的淘汰案例。复杂自动探索、长历史批量回补和全库组合扩展，在首轮流程验证后逐步开放。

完整架构保留扩展位置，首版验收关注字段正确、证据可复查、成本真实和下一步动作清楚。
