# 开发文档格式契约

本格式来自公司现有的单产品开发表。固定原则是一个产品一个工作簿、三张工作表；同一产品的多个变体在第三张表中分块展示。

## 1. 参考产品信息调研

固定为第一张表，默认列顺序：

| 列 | 字段 | 规则 |
| --- | --- | --- |
| A | 站点 | 使用 US、DE 等站点代码 |
| B | 上架日期 | 使用真实日期值 |
| C | Review数量 | 数值；未知留空 |
| D | 售价（当地币种） | 数值；币种由站点确定 |
| E | 大品类排名 | 保留原始排名口径 |
| F | 所在品类 | 保留站点原文或可靠中文说明 |
| G | 预估日销量 | 允许记录来源口径，如月销量快照 |
| H | 产品优点&特征 | 只写有证据的观察 |
| I | 缺点 | 只写产品不足或评论痛点，不写数据缺失 |
| J | 生命周期 | 全年或明确月份 |
| K | ASIN | 真实商品 ASIN |
| L | 亚马逊产品链接 | 完整 URL，可点击并换行 |
| M | 图片 | 嵌入当前参考商品图片 |
| N | 备注 | 来源、限制或补充说明 |

同一产品可有多条竞品记录。主要同款或主参考放在第 2 行，其他链接向下追加。用户提供 Amazon 链接时，按站点和 ASIN 优先从卖家精灵“查竞品”补齐研究字段，再用 Amazon 或用户资料补充缺项；备注记录来源、采集日期和销量换算口径。每条链接都要有对应研究行，不能只有链接而缺少其他可核实数据。访问受限时明确标记待补及原因，不将空白研究表视为完成。表头默认浅绿色 `#C6E0B4`、微软雅黑 11 号加粗、细黑边框；数据区域居中换行。图片行和长链接行按内容加高，不用极窄字体缩放。

## 2. 产品确认

固定为第二张表，只允许一个产品记录。默认列顺序：

`图片、名称、备注说明、SKU、起订量、交期（天）、成本（元）、重量（g）、亚马逊链接、亚马逊链接2、ASIN、图片/视频建议、采购链接1、供应商、首单进货数量、变体情况`

- 第一列嵌入产品图，不放图片路径。
- “备注说明”用于卡航、包装或其他内部交接备注，不自动进入买家文案。
- “首单进货数量”是采购数量，不等于每套商品件数。
- “变体情况”按 `变体1：名称*数量` 分行列出；多个变体仍只占一个产品记录。
- 用户的历史表使用“取样款式、预想售卖情况”时，可按明确需求替换最后两列，但不要同时保留两套重复列。

表头白底、微软雅黑 12 号加粗、细黑边框。产品行居中换行并设置足够行高显示图片和长文本。

## 3. 产品详情表

固定为第三张表，表名是产品简称。默认六列：

`价格/克重、变体、供应商产品名称/图片、产品属性、产品主图/实拍图、备注`

可根据产品证据把“供应商产品名称/图片”拆成文字和图片区域，但必须保留以下语义：

- 每个变体的价格和克重；包装尺寸与产品尺寸分开写。
- 清楚的变体名称和数量/图案/尺寸差异。
- 供应商成品名称、供应商图或实拍图。
- 材质、尺寸、结构、使用方式等已确认产品属性。
- 自有产品主图或实拍图；竞品图不能冒充自有产品图。
- 侵权词、包装、配件、拍摄等必要注意事项。

每个变体使用独立的高行区块。图片保持原比例置于对应单元格范围内，不能跨到其他变体。产品属性中的关键材料或规格可用红色加粗强调，但未知项只写“待确认”。不设置“内容清单”或 `listing` 列。

## 视觉与结构

- 字体：微软雅黑；正文 10–11 号，表头 11–12 号加粗。
- 对齐：表头和结构化字段水平、垂直居中；长文本自动换行。
- 边框：业务区域使用细黑边框；不要改成无边框展示页。
- 网格线：保持可见，与历史开发表一致。
- 图片：直接嵌入，保留比例；确认表和详情表的图片行通常高于普通文字行。
- 空白：允许保留少量空白行供人工补充，不创建额外说明页、审核页或汇总页。
- 链接：保留完整 Amazon/采购 URL；不得将竞品 ASIN误写成自有 ASIN。
