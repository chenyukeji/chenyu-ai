# 晨玙 Amazon 开发

根据用户本次目标自动选择下方专业 Skill，由当前助手读取并执行。用户指定专业入口时遵从其选择；目标明确时直接开始，无需让用户再选功能。专业 Skill 仍可单独使用。

## 自动选择

| 用户目标或输入 | 读取并执行 |
| --- | --- |
| 找品、筛选新品、比较候选、分析新品榜历史、筛查近期 FBM 热销商品或生成开品结果 | [chenyu-xuanpin](../chenyu-xuanpin/SKILL.md)；找品策略、站点、类目和评分规则由该 Skill 决定 |
| 1688链接和目标属性，要求供应商名称、规格、图片、报价或库存 | [chenyu-gongyingshang](../chenyu-gongyingshang/SKILL.md)；通过已授权领星只读解析，歧义规格待确认 |
| 从1688链接和属性继续生成开发Excel | 先采集供应商资料，确认匹配规格后，将事实包和对应本地图交给开发文档Skill |
| 已确认产品，要求整理竞品、供应商报价、规格、变体和图片，生成或修改产品开发 Excel | [chenyu-kaifawendang](../chenyu-kaifawendang/SKILL.md)；每个产品独立一个三表工作簿，同一产品的变体留在同一文件 |
| 同时要求找品和开发文档 | 先执行选品分析，按用户已明确的产品范围或选择条件确定要写入开发文档的产品，再执行开发文档 Skill |
| 已有选品结果或已确认产品，继续生成开发文档 | 直接复用相关资料，执行开发文档 Skill；只有用户要求重新选品或更新数据时才重新调研 |

“开发一批产品”且未指定具体产品或资料整理目标时，按选品需求处理。只有“帮我开发”这类无法判断目标且会影响执行的请求才集中询问目标；附件类型用于理解输入，不能替代用户明确的任务要求。

## 连续任务

同时执行两种交付时，保留一次任务的原始需求、候选身份、站点、ASIN、来源链接、图片和确认状态。选品得分代表调研优先级；不能将排名靠前自动当作用户已确认开发。用户已明确“前五款生成开发文档”等选择条件时可直接按条件继续；没有选择范围时先交付选品成果，再请用户确定要开发的产品。

竞品证据和自有产品事实分别保留。用户为开发文档提供新的 Amazon 链接时，按开发文档 Skill 查询卖家精灵并补齐第一张参考商品表，不触发重新选品或评分。供应商、成本、MOQ、交期、规格或变体缺失时，按开发文档 Skill 写 `/`；不从竞品推定自有事实，不编造采购资料。选品流程返回待补数或部分完成状态时，保留并说明该状态；不能把未完成的候选称为完整选品成果。

## 交付

会生成文件时，先读取 [输出目录规范](../../references/output-paths.md)，连续交付复用同一个日期任务名，分别写入各自交付目录。仅交付本次要求的真实成果：选品结果、供应商事实包或每产品一个开发工作簿，不互相替代。

供应商采集可独立交付，也可作为开发文档前置步骤；不保存领星配对、不新增供应商或下单。供应商比较、采购决策、Listing、作图要求、实际作图和广告不因使用开发总入口自动扩展执行。
