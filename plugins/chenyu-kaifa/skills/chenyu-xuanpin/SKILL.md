# 晨玙 Amazon 选品分析

本 Skill 只完成一件事：**根据用户要求找产品，分析候选并生成开品表格。**

开始执行会生成文件的任务前，先读取并遵循 [输出目录规范](../../references/output-paths.md)。

## 默认行为

1. 读取用户自然语言并识别开品策略。用户明确指定的策略优先。
2. 用户明确说近60天 FBM 时优先使用 J；否则说“新品”“新品榜”或没有说明方式时使用 E：美德新品榜。
3. 用户没有指定来源站点时，默认同时采集 US 和 DE。
4. E 策略下 Amazon 作为 ASIN、站点、新品榜名次和商品主图兜底来源；其他分析字段由卖家精灵按 ASIN 补充。卖家精灵返回真实商品图时优先使用，返回站内占位图时保留 Amazon 主图。
5. E 的 ASIN 不论来自实时榜单、历史 JSON 或续跑任务，只要上架日期、Review、售价、BSR、品类、预估月销量或图片为空，都进入卖家精灵补数阶段。先验证页面账号身份，输入框可用不代表已登录。每次单条或批量查询前，确认“展示所有变体”未勾选；控件缺失或无法关闭时停止补数，不得假定默认状态。查询必须收到与本次 ASIN 对应的成功响应；加载动画消失不代表查询成功。登录或接口异常时停止并返回 `AWAITING_ENRICHMENT`，不得用空结果冒充已完成。只有已登录、接口成功且明确返回零条记录才记为未收录，并最多缓存 24 小时；单个 ASIN 连续返回无关商品时保留 `query_result_mismatch` 证据，将该 ASIN 标记待补并继续查询其他 ASIN。有足够数据的其他候选时可交付标记 `PARTIAL` 的结果；不能把不匹配数据写给该 ASIN，也不能称其为未收录。超时和解析失败在续跑时重新查询。会话失效最多重新登录一次；验证码、权限不足或重试仍失败时如实报告。
6. 按站点和 ASIN 合并，不能仅凭标题相似跨站合并。
7. 按 [输出契约](references/output-contract.md) 计算透明得分，降序生成 `开品结果.xlsx`，并把商品图直接嵌入文件。同一图片地址每次生成只读取一次；续跑或重建同一工作簿时，按站点和 ASIN 复用其中已有图片，只补取新增或缺失图片。
8. 用户要求比较今天、昨天、过去若干天、首次出现、连续出现、产品类型扎堆或排名趋势时，读取 [new_releases.db 只读契约](references/new-releases-db.md)。数据库由采集器独占写入，本 Skill 只能以 SQLite 只读模式查询，不迁移或反写数据库。
9. 数据库不建立产品类型、分组标签或相似度字段。产品扎堆由本 Skill 在运行时同时比较同站点同类目商品的标题和主图；两项证据都达标才组成无名称的相似商品组，只返回组内 ASIN 与成对相似度证据，不给组命名，也不写回数据库。

E 的类目由用户定义，`category-presets.json` 只是快捷映射，不是允许类目清单。运行 E 的实时选品前读取 [自定义类目与榜单入口](references/custom-categories.md)：识别单类目或多类目，优先采用用户提供的入口；未命中预设时，用可用的网页搜索或浏览器查找并核实各站点对应的 Amazon 新品榜入口，写入本次任务的 `task.categories` 后执行。不要因未命中预设立即让用户提供 URL，也不要为一次自定义请求修改插件源码。

例如“针对厨房庭院给出开品结果”，按厨房用品、庭院园艺两个方向分别核实 US/DE 入口；若语义明显指“户外厨房”这一细分类目，则保留该范围，不扩大成两个大类。真正存在影响选品的歧义才询问用户。搜索仍无法核实入口或页面受限时，说明具体类目、站点和已尝试的方法；不能凭节点编号猜链接，也不能将搜索结果中的商品当成已采集 ASIN。

## J：近60天 FBM 机会

当用户明确要求近期 FBM 商品时，单独选择 J：从卖家精灵“选产品”按站点、上架近60天、FBM、最低预估月销量筛选。J 不使用 Amazon 新品榜，也不要求商品出现在新品榜。默认最低预估月销量100，可通过 `discovery.j_min_monthly_sales` 调整；可通过 `discovery.j_keyword` 输入卖家精灵支持的产品关键词。没有关键词时是站点范围筛查，不把自然语言类目误当作已应用的筛选器。

对返回记录再次核对上架日期、FBM 和月销量，缺项或不符合者写入资格审核 JSON，不进入 Excel。J 使用独立调研优先级，不按新品榜名次打分；输出增加原文标题、FBM资格证据和“近期火爆原因”。原因逐项检查同站同类目相对售价、季节主题、站外流量、功能创新和变体数。只把有来源的观测写成证据；季节主题属于待用历史趋势核实的假设；没有站外流量或功能对比资料时明确写“未核实”。指标与销量同时出现不证明因果关系。卖家精灵仅提供游客可见结果或分页被截断时标记 `PARTIAL` 并说明覆盖范围。

## 运行

```json
{
  "skill_action": "run_discovery_flow",
  "request": "针对玩具类目的派对用品找新品"
}
```

未说明策略时也可直接运行，程序默认采用 E，来源站点为 US 和 DE。已有 JSON 数据可通过 `discovery_paths` 输入，用于续跑或离线复算。

历史分析不需要 MCP。传入 `db_path`，或设置 `CHENYU_NEW_RELEASES_DB`。用户明确问“今天”或“昨天”时，把当前本地日期作为 `as_of_date` 传入，缺少当天快照就如实返回空；用户只问“最近”或“过去若干天”且未指定截止日时，可省略 `as_of_date`，以数据库最新快照日为分析日，并明确报告与系统日期的差距。完整参数和计算口径见 [new_releases.db 只读契约](references/new-releases-db.md)。

## 交付

每次运行保留原始请求、策略识别、Amazon ASIN、卖家精灵补数、候选池、评分明细和最终 Excel。Excel 按内部得分从高到低排列，最终只展示带颜色标识的“结论”和合并后的“理由”。E 的“产品优点&特征”全部使用中文；J 的原文标题单独列出，不冒充已验证的中文卖点。图片字节只在内存中处理并写入工作簿，不生成单独图片文件；重复生成时直接复制旧工作簿已嵌入的图片。“缺点”只描述产品不足；“生命周期”表示全年或具体可售月份。

从历史数据库进入完整开品流程时，先按 `NEW`、`REPEAT`、`RISING` 合并候选，历史信号进入“市场信号”理由，但不直接修改现有 100 分权重；卖家精灵继续补充评分所需的上架日期、BSR和预估月销量。只做历史问答时返回结构化 JSON，不强制生成 Excel。

得分只用于排列调研优先级。理由固定按“市场信号、竞争门槛、新品与价格、销售周期、主要风险、数据与评分、下一步”七段生成。结论还受缺失字段、Review 壁垒、低销量和低榜单名次的公开上限约束。缺失数据必须写入理由，不得当成零销量或自动淘汰。

## 边界

不处理供应商报价、成本利润、采购、验样、试销、Listing、广告或店铺操作。不绕过登录、验证码或网站访问限制。

关键评分字段缺失时结论为“🟡 待补数据”，内部得分仅供排查，不代表负面选品结论。部分资料不足的工作簿标记 `PARTIAL`；不要把它描述为完整补数成功。若流程返回 `AWAITING_ENRICHMENT`，不要自行跳过登录检查或用已有空表交付，先报告具体阻塞原因。
