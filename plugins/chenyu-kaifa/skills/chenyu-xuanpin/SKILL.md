# 晨玙 Amazon 选品分析

本 Skill 只完成一件事：**根据用户要求找产品，分析候选并生成开品表格。**

开始执行会生成文件的任务前，先读取并遵循 [输出目录规范](../../references/output-paths.md)。

卖家精灵共用一个浏览器：选品和运营任务在同一默认上下文中各开自己的窗口，Cookie 和登录状态共享；任务结束关闭自己的窗口，最后一个使用者结束后自动关闭浏览器并清理临时页面，保留登录状态和成果。有其他任务或未知页面时不强行关闭。所有卖家精灵操作使用现有采集入口，定制采集须复用 `scripts/sellersprite_session.py` 的 `launch_context` 和 `ensure_login`，不得另起临时浏览器或独立上下文登录。`CHENYU_BROWSER_DATA_DIR` 指向共享目录，未配置时使用用户级固定目录。`scripts/sellersprite_session.py status` 只检查状态，`login` 初始化登录；锁定、密码错误或安全验证会跨任务阻止重登，只有确认解锁、修正凭据或完成验证后才用 `recover` 单次恢复。网络或不明失败冷却 5 分钟，不通过换目录或删状态绕开。

## 统一入口与综合调查

类目、主题、商品链接和店铺链接的综合选品读取 [统一选品流程](references/unified-selection.md)，使用 `plan_selection` / `resolve_selection_input` / `run_selection` / `resume_selection`。模型先确定站点、目录和本地语言关键词，再统筹亚马逊新品榜、卖家精灵研发新品榜、当前销量飙升、关键词趋势和只读新品数据库。只有用户明确要求去年同期或历史销量对比时才查询历史销量飙升，不将其作为综合选品默认步骤。类目、商品链接和店铺链接默认交付50个通过筛选的不同父体产品；用户明确指定数量时按指定值执行，明确要求全部时分批审阅全部已采集父体。淘汰不相关或重复商品后继续补选，证据不足时如实说明实际数量，不凑数；卖家精灵采集先关闭“展示所有变体”，同次查询跨页只保留一个父体代表，跨月份和关键词再按站点与父ASIN去重。父体未知时先补数，不计入50款、不进入最终Excel；原始变体记录保留在过程证据中。商品事实与关键词需求分别保存，按证据关联；用户只查榜单入口时直接交付已核实链接。用户明确指定独立策略时使用下面的旧流程，不额外扩大查询。

数量以用户明确指定值优先，否则为50个不同父体；将明确数量写入 `scope.shortlist_limit`，保留原始 `request`，不得把模型新增条件伪装成用户要求。未达到目标时核对 `counts.target/shortfall` 并继续补选，不能仅因已生成文件结束。月份或季节用途不等于上架日期；只有用户明确要求该期间新上架时才按上架日期筛选。历史数据缺失与不相关分开记录，具体处理见统一流程。

## 竞品 ASIN 反查长尾词

用户给竞品 ASIN、商品链接或明确要从搜索词找铺品方向时，选择独立的 [ASIN 反查长尾词暴涨选品](references/asin-keyword-breakout.md) 方法。重点是具体产品形态长尾词的月度需求是否近期抬升；宽泛词、同义词和变体不能凑出虚高市场规模。PPC 是竞争辅助信号，不能单独证明没有存量商品。该方法用 `scripts/asin_keyword_breakout.py` 采集真实逐月数据，默认仅交付一份 `开品结果.xlsx`、一张“开品结果”工作表；关键词判断归入对应产品的理由，商品图片嵌入结果表。趋势曲线、逐月原始点、筛选说明、补充指标和搜索核实留在内部任务 JSON，不生成独立 PNG 长图或辅助子表。竞品标题和关键词的材质、规格不一致时标明冲突，不把搜索词当成产品事实。现有综合流程的 `keyword_trends` 只查询已给关键词的历史趋势，**不会自动反查 ASIN**；需要综合选品时先取得反查证据，再把核实的词投入综合流程。

## 已核实信息与留空原则

只填写有来源支持且匹配当前站点、ASIN和变体的信息。不确定、来源冲突且未核实的材质、尺寸、颜色、性能、类目或销售原因省略或留空；不写“可能”“待验证”等推测性占位句。已确认的结构与使用限制放在特征中，不自动当作产品缺点。类目先读卖家精灵实际类目路径，再用 Amazon 商品页导航、BSR类目或实际包含该ASIN的榜单核对；只查到大类就只填大类，不以搜索主题或标题推断补齐。

“缺点”仅填写有确切证据的产品不足；未取得证据、评论无法读取，或已读样本没有明确问题时留空。不用露指设计、仅手洗、套装数量、缺少资料、低销量或通用风险凑缺点，也不把表头改成“结构/规格限制”来填满。留空不代表商品没有缺点。仍需主动核查可用来源，采集失败、冲突与样本范围保留在任务证据中；用户明确不用评论报告时不生成报告，继续用可获取的数据完成表格。

## 生命周期与评论缺点（交付前必读）

入选商品先调用 `collect_product_evidence` 在共享浏览器打开卖家精灵网页“销量趋势”和“子体销量趋势”表读取实际月度点；返回 `product_evidence_requests` 时按请求补查，已有数据保存在同一任务的 `product-history-*.json`。读取到不足12个月时，继续按父体/子体及页面时间范围补查，不将“有限观察”填成生命周期；未补齐的记录保留待补。随后按 [历史销量与评论证据](references/product-evidence.md) 核查可用的历史月销与评论原文；只填写证据明确支持的可售窗口/旺淡季与产品不足。默认不查历史飙升榜只约束发现候选，不代表省略入选商品的历史曲线分析。当前近30天销量和评论数量不能替代这两项；必须主动读取证据，不能用留空代替调查。没有取得依据时，对应单元格留空，不填错误码、链接或失败说明；实际原因保留在任务 JSON，状态保留 `PARTIAL`。综合流程用 `lifecycle_analysis` / `review_analysis` 提交可追溯结论，历史记录及评论样本留在任务 JSON。

## 独立策略流程

1. 读取用户自然语言并识别开品策略。用户明确指定的策略优先。
2. 本节适用于独立 `run_discovery_flow`；综合任务按统一入口执行。明确指定策略优先。近期 FBM 用 J，新品榜用 E，历史季节性用 H，店铺跟踪用 I，搜索热词用 C，排名跃升用 K；没有说明方式时默认 E。H/I/C/K 执行前读取 [六种策略与输入契约](references/six-strategies.md)，不要将历史季节性任务改为新品榜数据库分析。
3. 用户没有指定来源站点时，默认同时采集 US 和 DE。
4. E 策略下 Amazon 作为 ASIN、站点、新品榜名次和商品主图兜底来源；其他分析字段由卖家精灵按 ASIN 补充。卖家精灵返回真实商品图时优先使用，返回站内占位图时保留 Amazon 主图。
5. E 的 ASIN 不论来自实时榜单、历史 JSON 或续跑任务，只要上架日期、Review、售价、BSR、品类、预估月销量或图片为空，都进入卖家精灵补数阶段。先验证页面账号身份，输入框可用不代表已登录。每次单条或批量查询前，确认“展示所有变体”未勾选；控件缺失或无法关闭时停止补数，不得假定默认状态。查询必须收到与本次 ASIN 对应的成功响应；加载动画消失不代表查询成功。登录或接口异常时停止并返回 `AWAITING_ENRICHMENT`，不得用空结果冒充已完成。只有已登录、接口成功且明确返回零条记录才记为未收录，并最多缓存 24 小时；单个 ASIN 连续返回无关商品时保留 `query_result_mismatch` 证据，将该 ASIN 标记待补并继续查询其他 ASIN。有足够数据的其他候选时可交付标记 `PARTIAL` 的结果；不能把不匹配数据写给该 ASIN，也不能称其为未收录。单个 ASIN 解析失败重试后仍失败时保留 `query_parse_error` 证据，从本次评分和 Excel 跳过该 ASIN，让其余候选继续；有足够有效候选时交付标记 `PARTIAL` 的结果。超时和解析失败在续跑时重新查询。会话失效交给统一会话入口检查；验证码、锁定、密码错误或权限不足时停止并如实报告，不另建浏览器反复登录。
6. 按站点和 ASIN 合并，不能仅凭标题相似跨站合并。
7. 按 [输出契约](references/output-contract.md) 计算透明得分，降序生成 `开品结果.xlsx`，并把商品图直接嵌入文件。同一图片地址每次生成只读取一次；续跑或重建同一工作簿时，按站点和 ASIN 复用其中已有图片，只补取新增或缺失图片。
8. 用户要求比较今天、昨天、过去若干天、首次出现、连续出现、产品类型扎堆或排名趋势时，读取 [new_releases.db 只读契约](references/new-releases-db.md)。数据库由采集器独占写入，本 Skill 只能以 SQLite 只读模式查询，不迁移或反写数据库。
9. 数据库不建立产品类型、分组标签或相似度字段。产品扎堆由本 Skill 在运行时同时比较同站点同类目商品的标题和主图；两项证据都达标才组成无名称的相似商品组，只返回组内 ASIN 与成对相似度证据，不给组命名，也不写回数据库。

E 的类目由用户定义，`category-presets.json` 只是快捷映射，不是允许类目清单。运行 E 的实时选品前读取 [自定义类目与榜单入口](references/custom-categories.md)：识别单类目或多类目，优先采用用户提供的入口；未命中预设时，用可用的网页搜索或浏览器查找并核实各站点对应的 Amazon 新品榜入口，写入本次任务的 `task.categories` 后执行。不要因未命中预设立即让用户提供 URL，也不要为一次自定义请求修改插件源码。

例如“针对厨房庭院给出开品结果”，按厨房用品、庭院园艺两个方向分别核实 US/DE 入口；若语义明显指“户外厨房”这一细分类目，则保留该范围，不扩大成两个大类。真正存在影响选品的歧义才询问用户。搜索仍无法核实入口或页面受限时，说明具体类目、站点和已尝试的方法；不能凭节点编号猜链接，也不能将搜索结果中的商品当成已采集 ASIN。

## J：近60天 FBM 机会

当用户明确要求近期 FBM 商品时，单独选择 J：从卖家精灵“选产品”按站点、上架近60天、FBM、最低预估月销量筛选。J 不使用 Amazon 新品榜，也不要求商品出现在新品榜。默认最低预估月销量100，可通过 `discovery.j_min_monthly_sales` 调整；可通过 `discovery.j_keyword` 输入卖家精灵支持的产品关键词。没有关键词时是站点范围筛查，不把自然语言类目误当作已应用的筛选器。

对返回记录再次核对上架日期、FBM 和月销量，缺项或不符合者写入资格审核 JSON，不进入 Excel。J 使用独立调研优先级，不按新品榜名次打分。品类遵循已核实信息规则，卖家精灵未显示时继续核对 Amazon；仍未取得真实类目就留空，不根据标题推断。J 先检查页面账号身份；当前会话是游客且环境变量提供账号密码时，在同一浏览器会话中自动登录并核验。登录失败或身份无法核验时保留阻塞原因；续跑须重新采集此前缓存的部分结果。没有配置凭据而仅有游客结果，或分页被截断时标记 `PARTIAL` 并说明覆盖范围。

J 对 shortlist 尝试采集 Amazon 商品详情页要点并保留来源链接；详情受限时使用已有标题和指标。可用 `discovery.j_enrich_details=false` 关闭详情采集。首次 `run_discovery_flow` 返回 `AWAITING_AI_ANALYSIS` 和 `analysis_requests` 时，当前模型逐个写一段简短中文“AI分析”，用同一 `run_dir` 和 `j_ai_analyses` 调用 `resume_discovery_flow`。数组每项包含 `marketplace`、`asin`、`analysis`，品类缺失不要求模型猜测；补查到真实类目时同时提交 `category_name` 与 `category_source_ref`。覆盖全部 shortlist 的分析才生成 Excel。

J 的“AI分析”一段合并商品特点、能证实的不足和近期机会判断，优先写 60–120 字，上限 180 字。只使用标题、详情、评论痛点或指标支持的内容；没有不足证据就省略不足，不编造评论或功能。不要写“待验证”、固定占位句、逐项缺失清单或冗长的下一步计划。价格优势只在同站同币种同类目至少 3 款可比时确认；季节主题或变体数不直接证明销量原因。J Excel 不再单列“产品优点&特征”“缺点”“理由”或“近期火爆原因”；E 保持原有列与理由规则。

## 独立策略运行

```json
{
  "skill_action": "run_discovery_flow",
  "request": "针对玩具类目的派对用品找新品"
}
```

未说明策略时也可直接运行，程序默认采用 E，来源站点为 US 和 DE。已有 JSON、CSV、XLSX 数据可通过 `discovery_paths` 输入，用于续跑或离线复算。

历史分析不需要 MCP。传入 `db_path`，或设置 `CHENYU_NEW_RELEASES_DB`。用户明确问“今天”或“昨天”时，把当前本地日期作为 `as_of_date` 传入，缺少当天快照就如实返回空；用户只问“最近”或“过去若干天”且未指定截止日时，可省略 `as_of_date`，以数据库最新快照日为分析日，并明确报告与系统日期的差距。完整参数和计算口径见 [new_releases.db 只读契约](references/new-releases-db.md)。

## 交付

所有选品入口（包括 ASIN 反查长尾词）默认只交付一份 `开品结果.xlsx`，其中仅一张“开品结果”工作表，沿用该策略的既有结果列与商品嵌图。不另交付趋势长图、图表预览 PNG、分析报告或“逐月搜索量原始点”“范围与筛选说明”“补充指标与判读”“搜索结果核实”等子表，也不将这些表隐藏后保留。分析步骤照常执行，原始数据与溯源记录保存在内部任务目录，不列入用户交付附件。必要结论精简写入结果行的“理由”或“AI分析”。用户明确另要过程资料或图表时才按指定范围追加。

综合入口按[统一流程](references/unified-selection.md)只交付一张原版 15 列“开品结果”工作表；关键词、季节性和来源证据保留在任务 JSON 中，不另设工作表。综合入口仍以审阅优先级排序，不套用独立 E 的分数和“强开”结论。以下评分规则适用于旧的独立 E/J 等流程。

每次运行保留原始请求、策略识别、Amazon ASIN、卖家精灵补数、候选池、评分明细和最终 Excel。Excel 按内部得分从高到低排列，结论带颜色标识。E 保留独立的中文优点、缺点和理由列；J 只使用一列简短“AI分析”，原文标题单独列出。图片字节只在内存中处理并写入工作簿，不生成单独图片文件；重复生成时直接复制旧工作簿已嵌入的图片。“缺点”只描述有确切依据的产品不足，没有依据就留空；“生命周期”表示全年或具体可售月份。

从历史数据库进入完整开品流程时，先按 `NEW`、`REPEAT`、`RISING` 合并候选，历史信号进入“市场信号”理由，但不直接修改现有 100 分权重；卖家精灵继续补充评分所需的上架日期、BSR和预估月销量。只做历史问答时返回结构化 JSON，不强制生成 Excel。

得分只用于排列调研优先级。E 的理由按“市场信号、竞争门槛、新品与价格、销售周期、主要风险、数据与评分、下一步”排列；销售周期和产品风险没有依据时省略对应段落，不为凑齐七段填推测。结论还受缺失字段、Review 壁垒、低销量和低榜单名次的公开上限约束。缺失数据必须写入理由，不得当成零销量或自动淘汰。

## 边界

不处理供应商报价、成本利润、采购、验样、试销、Listing、广告或店铺操作。不绕过登录、验证码或网站访问限制。

关键评分字段缺失时结论为“🟡 待补数据”，内部得分仅供排查，不代表负面选品结论。部分资料不足的工作簿标记 `PARTIAL`；不要把它描述为完整补数成功。若流程返回 `AWAITING_ENRICHMENT`，不要自行跳过登录检查或用已有空表交付，先报告具体阻塞原因。
