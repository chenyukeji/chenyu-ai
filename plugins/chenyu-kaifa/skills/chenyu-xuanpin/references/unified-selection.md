# 单一选品入口

用户给类目、细分主题、商品链接或店铺链接，默认由同一个 `chenyu-xuanpin` 理解需求、制定任务并交付。使用 `run.py` 的 `plan_selection`、`resolve_selection_input`、`run_selection`、`resume_selection`；旧的 `run_discovery_flow` 保留给明确指定的独立 E/J/H 等任务。

## 先确定范围

模型负责把自然语言变成 `scope`，不要求用户填写技术参数。修正明显错字；保留明确的站点、排除项、价格、配送和时间要求。商品/店铺链接优先确定站点；无链接且未指定站点时默认 US/DE。当前实时采集只支持美德，不偷偷替换其他站点。

商品链接：先运行 `resolve_selection_input`，读取 ASIN、商品目录、排名目录、实际新品榜链接和卖家链接。目录可能不唯一，以用户产品用途确认；再打开新品榜核对目录、站点与页面标题。仅从节点编号构造的地址不得直接当作已验证入口。

店铺链接：该动作读取卖家目录的可见商品样本，或品牌旗舰店展示商品。品牌店不自动等同于单一卖家；店铺目录仅按实际读取范围声明。默认关注店内商品和主营方向，扩大到同类榜单的商品要标为类目延伸发现。首次快照不称新上架；部分快照的差集不称全店新品。模型从已取得的商品事实整理主营类目，再填写 `scope.categories`。

类目/主题：先核实各站目录；无独立目录时，保留关键词范围并记录新品榜入口未核实，不把主题词当作目录节点。模型用网站搜索或浏览器查找入口，按 `custom-categories.md` 核实。关键词使用目标站点实际用语，通过结果商品核对意图；翻译只用于查询起点。同义词搜索量不相加。

用户只查榜单入口时，交付已核实的目录和链接即可，不运行完整选品。

## 综合任务参数

```json
{
  "skill_action": "run_selection",
  "request": "分析美国站圣诞树装饰，结合新品、销量增长、关键词和季节性",
  "as_of_date": "2026-10-11",
  "run_dir": "<按输出目录规范生成的绝对路径>",
  "scope": {
    "marketplaces": ["US"],
    "categories": [{
      "name": "圣诞树装饰",
      "keywords": {"US": ["christmas tree ornaments"]},
      "amazon_new_releases": {"US": "<已打开核实的新品榜URL>"},
      "db_categories": {"US": ["<数据库实际存在的对应类目标识>"]}
    }],
    "following_months": 2,
    "shortlist_limit": 20,
    "filters": {"price_min": 10, "price_max": 30}
  },
  "browser": {"headless": true, "max_pages": 1}
}
```

示意占位符不能直接执行。目录未找到时省略该映射，覆盖表会记录不可查询，其他来源继续。`db_path` 或环境变量 `CHENYU_NEW_RELEASES_DB` 指向已有数据库；不得为调研修改数据库。

`scope.sources` 可指定：`amazon_new_releases`、`sellersprite_new`、`sellersprite_surge`、`sellersprite_history`、`keyword_trends`、`new_releases_db`；综合任务默认全部检查。`scope.input_urls` 是商品/店铺链接数组。价格、评论上限、销量下限和配送方式使用 `filters.price_min/price_max/review_max/sales_min/fulfillment`；其他排除条件放在 `exclusions`，由模型逐项核对。价格币种属于各站当地币种。

卖家精灵“研发新品榜”和“销量飙升榜”按网页真实预设运行，记录实际筛选字段；不把它们当成不同的独立数据商。产品页面使用词组匹配，并核对请求中的站点、关键词、匹配模式、月份和榜单预设。关键词筛选不冒充精确目录筛选。研发新品标签不保证近60天上架，必须核对实际上架日期。历史窗口为去年同月加随后 2 或 3 个月，跨年继续；历史销量不会覆盖当前销量。关键词返回独立需求方向，不要求预先绑定 ASIN。

## 执行、分析与续跑

每次调用保存计划、分来源证据和状态。`max_queries` 限制一次实际查询数量（默认20）；返回 `RUNNING` 时以相同 `run_dir` 继续。成功结果复用，阻塞结果重试；`refresh=true` 才重采成功来源。不要无限重试验证码、账号权限或查询拒绝。

`AWAITING_SCOPE`：模型根据入口事实补全 `scope` 后续跑，不把技术参数问题转嫁给用户。

`AWAITING_ANALYSIS`：读取 `selection-evidence.json` 和 `analysis_requests`，对 shortlist 每个商品填写 `reviews`：`marketplace`、`asin`、`relevant`（布尔值）、`priority`（优先研究/继续观察/低优先级）、`reason`。不相关商品用 `relevant=false` 并写原因。初次审阅后相关商品未达到用户要求且候选池仍有可用记录时，扩大 shortlist_limit（不超过100）并复用原采集证据继续审阅；仍不足时如实说明实际数量。理由说明用户范围匹配、可核验的需求/销量/竞争证据、季节窗口及关键缺项。缺关键当前数据时不能强推，程序会保留待补数据。

审阅同时核对：品牌需求与通用品需求、当前搜索走势和历史季节回升、父子体销量口径、近期上架商品实际表现、同类相关性。商品不足必须有产品/评论证据，不能凭低销量编造缺点。搜索排名变化不是搜索量变化；缺少月份不填零；只有样本时不计算全市场垄断率；新品榜数据库与实时同一榜单不重复计作独立证据。

`associations` 可补充有来源的关键词与商品对应关系：`marketplace/asin/keyword/relation/source_ref`。只有商品确实相关时才用于解释；同一个关键词在多个商品中不能重复算作市场规模。

以 `resume_selection`、相同 `run_dir` 和完整 `reviews` 生成工作簿。已变更证据不复用旧审阅。`PARTIAL` 保留可用结果和具体缺失来源；`BLOCKED`、`NO_CANDIDATES` 不称完整成功。来源部分分页覆盖属于样本，应说明采集范围。

## 交付

`开品结果.xlsx` 包含选品结果、关键词趋势、关键词月度明细、季节性明细、来源与覆盖。商品图片嵌入文件并在续跑时复用；不另存图片。机会优先级与证据缺项分开，不输出未经校准的成功概率、利润或采购结论。

真实登录状态必须检查。Amazon 公开页面可读不代表账号已登录；卖家精灵必须验证账号身份和本次匹配响应。凭据只从进程环境读取，不写入请求、产物或日志。实际账号可访问的站点/历史月份以查询结果为准。某站点未显示指定榜单预设时，该来源返回 unavailable 并继续其他来源；不能自动替换成其他榜单并沿用原标题。

## 提问格式

无需填写程序参数，可以直接复制后替换内容：

- **大类**：`用选品分析美国站派对用品，先拆分实际子类目，综合新品榜、销量飙升、关键词和数据库，选出10个值得研究的产品，说明具体依据。`
- **细类**：`分析美国站圣诞树装饰，结合当前新品榜、销量飙升、关键词趋势，以及去年同月和随后3个月的飙升情况，输出开品Excel。`
- **商品链接**：`分析这个商品：<Amazon商品链接>。先找并核实所在目录的新品榜，再调查同类新品与关键词趋势，推荐值得研究的方向。`
- **店铺链接**：`分析这个店铺：<Amazon店铺链接>。先看店内可见商品和主营方向，再结合对应新品榜、销量与关键词趋势找机会，区分店内商品与类目延伸发现。`
- **附加条件**：`只看美国站，售价10～30美元，评论不超过100，不要带电和食品，优先研究10款。缺数据请标注，不要猜。`
- **只查目录**：`帮我找到并核实这个商品所在目录的Amazon新品榜：<商品链接>。`

用户要求“全店”“全部榜单”或指定页数时，按实际分页能力和结果覆盖执行；不能将默认一页样本称为完整扫描。大类先分解成实际子类和当地关键词，不能把“派对用品”的单次查询说成整个类目已覆盖。涉及季节准备时，若未给出采购、生产和运输周期，只判断需求窗口，不虚构备货截止日期。
