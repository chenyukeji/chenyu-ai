# 生命周期与评论缺点

入选商品交付前必须主动补取这两类证据。当前售价、Review数量、近30天销量补齐，不等于完成历史销量与评论分析。`sellersprite_history` 是历史飙升榜发现候选的策略；默认不查该榜不影响对入选商品读取历史月销曲线。不要为了填生命周期扩大选品来源或重新搜历史榜。

## 读取与分析

- 生命周期指可售时间窗口，不是新品期/成长期标签。优先读取卖家精灵该站点、该 ASIN 的24个月历史月销量，至少争取12个完整连续月；结合销量曲线、同比、BSR及价格/断货记录，归纳全年可售还是季节性、起量月份、旺季和回落月份。排名只作辅助，关键词热度不等于该商品销量，榜单命中月份不等于销售窗口。父体与子体口径不能混合或求和，缺月不能补零，当前未完成月不能与完整月直接比较。仅一年数据只能描述已观察年度，不称连续多年季节性；不足一年先补查历史覆盖，不将“有限观察”或“只能确认起量”写进生命周期列。不按固定类目模板直接指定月份。
- 缺点必须阅读真实买家评论。优先近期评论，兼顾1–3星与其他星级，尽量读取30–50条去重评论；实际可读更少时明确样本范围。不把星级、Review数量或自动摘要当成已读取原文。归纳耐用、尺寸适配、气味、操作等实际产品问题，分清物流/卖家服务、误用、旧版本和不匹配变体；不把物流慢写成产品性能差。不重复计算同一评论，单条只能说有一条反馈。记录每个问题出现的评论数/实际所读样本数，不能外推到全部评论。
- 所有卖家精灵页面读取遵循共享会话 `launch_context` / `ensure_login`，复用同一已授权浏览器。在卖家精灵网页商品行打开“销量趋势”和“子体销量趋势”读取月度表；无需安装或调用浏览器扩展。父体和子体单独保存，不能相加或混为同一曲线。`100,000+`、`100K+` 等保留原始显示值并标记为销量下限，不能改成精确销量。评论原文从卖家精灵网页实际可用的评论入口或对应Amazon买家评论读取，AI摘要不算原文。登录、验证码、权限、无记录或数据不足分别保留实际原因，不能用猜测补齐。
- 先保留实际读到的月度点/评论正文、来源与采样范围，再由模型总结，最后提交以下结构。不为通过校验虚构点位、评论或来源。原文是否支持总结、混合变体是否适用，必须语义审核；结构校验不保证结论正确。

## 浏览器采集动作

```json
{"skill_action":"collect_product_evidence","marketplace":"US","asins":["实际ASIN"],"run_dir":"本次选品目录","as_of_date":"2026-10-13"}
```

动作复用 `launch_context` / `ensure_login` 的同一浏览器默认上下文；ASIN查询匹配成功后，通过商品行历史趋势按钮读取父体“销量趋势”，点击“子体销量”列读取“子体销量趋势”；每次等待对应商品身份与表格加载完毕。`sales_scope` 默认 `both`，也可指定 `parent` 或 `child`；两条曲线保存在 `series` 中，`history` 优先取请求口径，默认优先有数据的父体曲线，其次子体曲线。单次最多50个ASIN；原始表、月份、父ASIN、来源保存在 `product-history-<站点>-<ASIN>.json`。未完成月份不进入history，空格和破折号不补零。读取到不足12个月不能视为完成：检查时间范围和分年展示、父体入口及已核实同族子体，独立保留各曲线，不拼接为虚假的完整年份。仍不足时保留 `insufficient` 及实际尝试，不将局部起量总结输出到生命周期列。返回的是原始事实，不是生命周期结论，须读完再提交下述结构。

历史采集成功不能冒充评论采集成功。采集只保留已完成月份；新商品即使不足12个月也保留实际历史，不将其视为没有数据。分析子体销量下限时明确下限口径，不以阈值差异推算精确增长率。

## 短历史补查

先复核当前商品站点、父ASIN和上架日期，检查页面是否有全部时间、24个月或分年展示控件；等待切换后的月份表加载完毕。父体记录较短时继续查询已核实父体入口及同族子体，分别保存来源与口径，不能拼接、相加或借其他商品历史冒充该商品。小于号销量（如 `<5`）保留为严格上限，不丢弃该月份，也不能按5件或0件精确计算。

已读取的两个月不等于卖家精灵只存在两个月数据；完成上述核查才能记录实际覆盖不足。确实上架较晚、父体变更、权限或访问受限时，把查询范围、尝试和原因保留在任务证据；生命周期继续待补，不输出“有限观察”式结论。历史选品必须核对用户目标月份，目标期间没有可核实销量的候选不能当作该期间热销商品；按原条件继续寻找其他候选。不得为了补全年而编造历史。

## 提交契约

`resume_selection.reviews` 每个 `relevant=true` 的商品增加 `lifecycle_analysis` 与 `review_analysis`。仍保留原来的站点、ASIN、relevant、priority、reason。完整原始证据保存在任务 JSON，不新增工作表。

```json
{
  "lifecycle_analysis": {
    "status": "analyzed",
    "summary": "根据实际曲线填写可售窗口、旺淡季及观察年份",
    "history": [
      {"marketplace":"US","asin":"B012345678","month":"2025-10","estimated_sales":500,
       "sales_scope":"parent","period_complete":true,"source_ref":"实际读取的卖家精灵历史来源"}
    ]
  },
  "review_analysis": {
    "status":"analyzed",
    "sampling_scope":"实际采样日期范围、星级筛选、排序方式及变体范围",
    "samples":[
      {"marketplace":"US","asin":"B012345678","review_id":"实际评论ID",
       "date":"2026-09-10","rating":2,"text":"实际评论原文","source_ref":"实际评论来源"}
    ],
    "findings":[{"summary":"有原文支持的具体产品不足","review_ids":["实际评论ID"]}]
  }
}
```

上面只展示单条结构，不是完整数据样本；确认销售窗口需要至少12个完整连续月，所有点必须同 ASIN、同父/子体口径。该门槛用于防止用当前单月销售猜全年，不能代替对季节性、断货或新品影响的判断。

取不到时使用 `{"status":"unavailable","reason":"实际尝试及阻塞原因"}`；历史不足使用 `{"status":"insufficient","reason":"实际覆盖范围与缺口","history":[...],"summary":"可选：仅保留在内部证据中的局部趋势"}`。不要提交空理由或声称没有尝试过的失败。`review_analysis.findings=[]` 只用于已经读取样本、但未归纳出明确产品不足；不是未读取评论的替代。样本较少不能声称全面覆盖。

## 输出与续跑

Excel 保留原15列，“生命周期”只写经完整历史支持的可售窗口总结，“缺点”写问题与所读样本频次；理由保留历史区间、来源、评论采样范围及限制。不再固定写空缺点或“需结合历史趋势复核”。没有提交分析或证据不可得时，对应“缺点”或“生命周期”单元格留空；已读评论但无明确产品不足时“缺点”也留空，采样说明保留在依据中。失败原因、错误码和失败入口链接只保留在任务证据及 `analysis_gaps`，不填入这两栏。结果仍标 `PARTIAL`；旧任务可读取但不能因为普通补数完成就标为完整分析。补取证据后以相同任务提交更新的 reviews，再生成完整结果。不能因缺点未知就声称产品没有缺点。
