# 生命周期与评论缺点

入选商品交付前必须主动补取这两类证据。当前售价、Review数量、近30天销量补齐，不等于完成历史销量与评论分析。`sellersprite_history` 是历史飙升榜发现候选的策略；默认不查该榜不影响对入选商品读取历史月销曲线。不要为了填生命周期扩大选品来源或重新搜历史榜。

## 读取与分析

- 生命周期指可售时间窗口，不是新品期/成长期标签。优先读取卖家精灵该站点、该 ASIN 的24个月历史月销量，至少争取12个完整连续月；结合销量曲线、同比、BSR及价格/断货记录，归纳全年可售还是季节性、起量月份、旺季和回落月份。排名只作辅助，关键词热度不等于该商品销量，榜单命中月份不等于销售窗口。父体与子体口径不能混合或求和，缺月不能补零，当前未完成月不能与完整月直接比较。仅一年数据只能描述已观察年度，不称连续多年季节性；不足一年仍可总结已观测区间，但标为有限观察，不确认全年窗口。不按固定类目模板直接指定月份。
- 缺点必须阅读真实买家评论。优先近期评论，兼顾1–3星与其他星级，尽量读取30–50条去重评论；实际可读更少时明确样本范围。不把星级、Review数量或自动摘要当成已读取原文。归纳耐用、尺寸适配、气味、操作等实际产品问题，分清物流/卖家服务、误用、旧版本和不匹配变体；不把物流慢写成产品性能差。不重复计算同一评论，单条只能说有一条反馈。记录每个问题出现的评论数/实际所读样本数，不能外推到全部评论。
- 所有卖家精灵页面读取遵循共享会话 `launch_context` / `ensure_login`，复用当前已授权浏览器。在商品详情历史趋势或评论分析入口读取；没有专用采集动作时可在同一共享会话中定制只读采集，不新建登录上下文、不猜接口数据。若当前可控制的已授权浏览器已安装卖家精灵扩展，可在对应 Amazon 商品页读取扩展的销量历史，并使用评论下载/分析入口；先确认扩展已加载、账号权限与站点/ASIN匹配。保存实际历史点和评论原文，不能把扩展 AI 摘要当作已读评论原文。没有连接扩展时如实记录，不能声称已调用。评论入口不可用时可从对应 Amazon 买家评论读取。登录、验证码、权限、无记录或数据不足分别保留实际原因，不能用猜测补齐。
- 先保留实际读到的月度点/评论正文、来源与采样范围，再由模型总结，最后提交以下结构。不为通过校验虚构点位、评论或来源。原文是否支持总结、混合变体是否适用，必须语义审核；结构校验不保证结论正确。

## 提交契约

`resume_selection.reviews` 每个 `relevant=true` 的商品增加 `lifecycle_analysis` 与 `review_analysis`。仍保留原来的站点、ASIN、relevant、priority、reason。完整原始证据保存在任务 JSON，不新增工作表。

```json
{
  "lifecycle_analysis": {
    "status": "analyzed",
    "summary": "根据实际曲线填写可售窗口、旺淡季及观察年份",
    "history": [
      {"marketplace":"US","asin":"B012345678","month":"2025-10","estimated_sales":500,
       "sales_scope":"parent","period_complete":true,"source_ref":"实际读取的卖家精灵历史来源"}
    ]
  },
  "review_analysis": {
    "status":"analyzed",
    "sampling_scope":"实际采样日期范围、星级筛选、排序方式及变体范围",
    "samples":[
      {"marketplace":"US","asin":"B012345678","review_id":"实际评论ID",
       "date":"2026-09-10","rating":2,"text":"实际评论原文","source_ref":"实际评论来源"}
    ],
    "findings":[{"summary":"有原文支持的具体产品不足","review_ids":["实际评论ID"]}]
  }
}
```

上面只展示单条结构，不是完整数据样本；确认销售窗口需要至少12个完整连续月，所有点必须同 ASIN、同父/子体口径。该门槛用于防止用当前单月销售猜全年，不能代替对季节性、断货或新品影响的判断。

取不到时使用 `{"status":"unavailable","reason":"实际尝试及阻塞原因"}`；历史不足使用 `{"status":"insufficient","reason":"实际覆盖范围与缺口","history":[...],"summary":"可选：仅已观察区间内有依据的趋势"}`。不要提交空理由或声称没有尝试过的失败。`review_analysis.findings=[]` 只用于已经读取样本、但未归纳出明确产品不足；不是未读取评论的替代。样本较少不能声称全面覆盖。

## 输出与续跑

Excel 保留原15列，“生命周期”写上述总结，“缺点”写问题与所读样本频次；理由保留历史区间、来源、评论采样范围及限制。不再固定写空缺点或“需结合历史趋势复核”。没有提交分析或证据不可得时，对应“缺点”或“生命周期”单元格留空；已读评论但无明确产品不足时“缺点”也留空，采样说明保留在依据中。失败原因、错误码和失败入口链接只保留在任务证据及 `analysis_gaps`，不填入这两栏。结果仍标 `PARTIAL`；旧任务可读取但不能因为普通补数完成就标为完整分析。补取证据后以相同任务提交更新的 reviews，再生成完整结果。不能因缺点未知就声称产品没有缺点。
